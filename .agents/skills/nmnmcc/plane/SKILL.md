# Plane

Use this view for a result that must remain coherent across technical domains. Hold the user promise, decide the boundaries, and integrate domain work into one tested outcome.

1. State the visible result, acceptance evidence, risks, and domains involved.
2. Pass each domain question to `line` with a clear boundary and return path.
3. Resolve cross-domain contracts and integrate the domain results.
4. Verify the complete result, including the user-visible path and remaining limits.

Read [the detailed guide](references/guide.md) for a full cross-boundary workflow or use `cluster` when the domains can progress independently.
