# v3 → v4 names that trip people up

Most Effect material online — blog posts, Stack Overflow, model memory — is
v3. These names changed. Verified against `effect@4.1.2`; grep
`node_modules/effect/src/<Module>.ts` if in doubt. The full upstream guide is
`migration/v3-to-v4.md` in the
[tagged repository](https://github.com/Effect-TS/effect/blob/effect%404.1.2/migration/v3-to-v4.md).

## Errors

| v3 | v4 |
| --- | --- |
| `Effect.catchAll` | `Effect.catch` |
| `Effect.catchAllCause` | `Effect.catchCause` |
| `Effect.catchAllDefect` | `Effect.catchDefect` |
| `Effect.catchSome` | `Effect.catchFilter` |
| `Effect.catchSomeCause` | `Effect.catchCauseFilter` |
| `Effect.catchSomeDefect` | removed |
| `Either` | `Result` (`Result.succeed`, `Effect.result`) |
| `Effect.either` | `Effect.result` |
| `Data.TaggedError` / `Schema.TaggedError` | same names; `catchTag` accepts one tag or an array |
| — | new: `Effect.catchReason`, `catchReasons`, `unwrapReason` for errors with a tagged `reason` field |

`Effect.catchTag(["A", "B"], handler)` handles several tags in one call.

## Services and layers

| v3 | v4 |
| --- | --- |
| `Context.Tag("X")<X, Shape>()`, `Effect.Tag`, `Effect.Service`, `Context.GenericTag` | `class X extends Context.Service<X, Shape>()("id") {}` |
| `X.Default` (generated by `Effect.Service`) | write `static readonly layer = Layer.effect(X, ...)` yourself |
| `Effect.Tag` accessors (`X.method(...)`) | `const x = yield* X; x.method(...)` |
| `Context.Reference` for defaults / `FiberRef` | `Context.Reference` (also replaces `FiberRef`) |
| `Layer.scoped(Tag, eff)` | `Layer.effect(Tag, eff)` — it removes `Scope` from the requirement itself |
| `Layer.scopedDiscard` | `Layer.effectDiscard` |
| `Runtime<R>` | removed; use `Effect.run*`, `ManagedRuntime`, or a `Context` |

## Fibers

| v3 | v4 |
| --- | --- |
| `Effect.fork` | `Effect.forkChild` |
| `Effect.forkDaemon` | `Effect.forkDetach` |
| `Effect.forkIn(scope)` | `Effect.forkIn(scope)` (unchanged) |
| `Effect.forkScoped` | `Effect.forkScoped` (unchanged) |
| `FiberRef.*` | `Context.Reference` + `Effect.provideService` / `Effect.updateService` |

## Schema

Schema v4 is a rewrite. Reach for the [schema guide](schema/guide.md) rather than
translating by hand. Highlights: `Schema.decodeUnknownEffect` (was
`decodeUnknown`), `Schema.String.check(Schema.isPattern(...))` (was `pipe(Schema.pattern(...))`
filters), `validate*` removed, `Schema.optionalKey` vs `Schema.optional`,
`*FromSelf` names simplified.

## Imports

Everything that was `@effect/platform`, `@effect/rpc`, `@effect/cluster`,
`@effect/cli`, `@effect/ai`, `@effect/sql`, `@effect/workflow` and
`@effect/experimental` is now a subpath of `effect`:
`effect/http`, `effect/http-api`, `effect/rpc`, `effect/cluster`, `effect/cli`,
`effect/ai`, `effect/sql`, `effect/workflow`, `effect/persistence`,
`effect/eventlog`, `effect/encoding`, `effect/testing`, `effect/observability`.
`effect/unstable/*` does not exist. Platform adapters (`@effect/platform-node`),
SQL drivers (`@effect/sql-pg`…), AI providers (`@effect/ai-openai`…),
`@effect/vitest` and `@effect/opentelemetry` remain separate packages and must
be pinned to the same exact version.

## Tests

`@effect/vitest` v4 requires Vitest 5. Property tests take a `Schema` or an
`Arbitrary`, not raw fast-check values; options are `arbitrary: { runs }`, not
`fastCheck: { numRuns }`.
