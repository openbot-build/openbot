OpenBot is a pnpm workspace. Each package has one job. `openbot` puts the parts together into the server. You can use the other libraries on their own.

All packages are named `@openbot-build/<name>`, have version `0.1.0`, and use `effect@4.0.5`. They are not on npm yet. Use them from the workspace with `"workspace:*"`.

---

## Overview

| Package         | What it is for                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------- |
| `openbot`       | The server, its plugins, and its model providers. See [Run from code](/docs/server).           |
| `api`           | The typed HTTP contract. The server, the client, and the API reference use it.                 |
| `client`        | The TypeScript client. See [Client](/docs/client).                                             |
| `core`          | The Bot core: Bots, Sessions, Turns, Timelines, storage, plugins, and skills.                  |
| `protocol`      | The OpenBot App Protocol: publish, find, connect, and index Apps.                              |
| `protocol-test` | A public test service for the App Protocol. See [Protocol test](/docs/protocol-test).          |
| `cli`           | The `openbot` command. It runs `openbot-<name>` for `openbot <name>`.                          |
| `computer`      | The `openbot computer` command, which pairs and connects your own [Computer](/docs/computers). |
| `docs`          | This docs site.                                                                                |

The examples below leave out the model. To run them, provide a `LanguageModel` Layer, for example from a [model provider](#model-providers) in `openbot`.

## core

`@openbot-build/core` runs Bots. It has these main parts:

| Module                                       | What it does                                                                                         |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `Bot`                                        | A Bot definition: tools, plugins, providers, and compaction. One definition can serve many Sessions. |
| `SessionRuntime`                             | Runs Turns: `execute`, `stream`, `start`, `steer`, `approve`, `interrupt`, and more.                 |
| `SessionStore`, `Store`                      | Saves Sessions and their Timelines.                                                                  |
| `SessionStoreMemory`                         | A store that keeps everything in memory, for tests and scripts.                                      |
| `Timeline`, `Item`, `Turn`, `Session`        | The data types.                                                                                      |
| `Plugin`, `PluginComposition`, `PluginState` | Make and combine plugins, and give them saved state.                                                 |
| `Skill`, `SkillMap`                          | Describe skills and keep a list of them.                                                             |

A **Session** is one line of work. Each input starts a **Turn**. A Turn can have many model steps and tool calls.
The **Timeline** is the saved history of a Session. Every change makes a new Timeline version, so you can read or fork from an earlier point.

```ts
import { SessionRuntime, SessionStoreMemory, Store } from "@openbot-build/core"
import { Effect } from "effect"
import { Toolkit } from "effect/ai"

const program = Effect.scoped(
	Effect.gen(function* () {
		const definition = yield* Store.define({
			stores: {},
			schemaVersion: "timeline/1",
		})
		const store = yield* SessionStoreMemory.make(definition)
		const runtime = yield* SessionRuntime.make({
			store,
			bot: { toolkit: Toolkit.empty },
		})
		const view = yield* store.create({ metadata: { title: "Closures" } })
		return yield* runtime.execute({
			base: { session: view.session.id, revision: view.session.revision },
			input: "Explain closures",
		})
	}),
)
```

`execute` waits for the Turn to end and returns the saved Session. `stream` gives events while the Turn runs.
Each change needs the current `revision`. This stops two writers from changing the same Session at once.

The store also forks, renames, exports, and imports Sessions without a model:

```ts
const fork =
	yield *
	store.fork({
		source: view.session.id,
		metadata: { title: "Another try" },
	})
const record = yield * store.export(fork.session.id)
```

### Plugins

A plugin wraps the model loop. `Plugin.make` makes one. Its constructor runs once. The middleware it returns wraps the event stream of each Turn:

```ts
import { Plugin } from "@openbot-build/core"
import { Effect, Stream } from "effect"

const logging = Plugin.make({ id: Plugin.Id.make("logging") })(() =>
	Effect.succeed((next, options) =>
		next(options).pipe(
			Stream.tap((event) =>
				event._tag === "ModelStepStarted"
					? Effect.log("A model step started")
					: Effect.void,
			),
		),
	),
)
```

`PluginComposition.merge(a, b)` combines two plugins. `a` runs outside `b`.
A plugin can also save its own data in the Session or in the Timeline. Pass `plugin.stores` to `Store.define`, then use `PluginState.make`.

### Skills

`Skill.Descriptor` describes a skill. `SkillMap.Catalog` is a list of skills. When two lists have the same skill ID, the later one wins.
Your program finds, loads, and runs the skills.

## Plugins in openbot

`@openbot-build/openbot` has all plugins of OpenBot. The server uses the Bot, App, work, and memory plugins in every Turn. The work plugin gives the Bot its todo list. You can also use the memory and Turn limit plugins with your own `SessionRuntime`.

### Memory

The memory plugin keeps learned memory: short facts that the Bot learns in a Session and uses in later Turns.
The server uses it for the memory API. See [Memory](/docs/memory). The schemas of the memory API are in `api`, as `Memory` and `BotMemory`.

```ts
import { SessionStoreMemory, Store } from "@openbot-build/core"
import {
	LanguageModelMemory,
	Memory,
	MemoryOperations,
	MemoryRules,
} from "@openbot-build/openbot"
import { Effect } from "effect"

const program = Effect.scoped(
	Effect.gen(function* () {
		const definition = yield* Store.define({
			stores: Memory.stores,
			schemaVersion: "timeline/1",
		})
		const store = yield* SessionStoreMemory.make(definition)
		const memory = MemoryOperations.make({
			store,
			policy: MemoryRules.policy,
			model: LanguageModelMemory.model,
		})
		return yield* memory.read(sessionId)
	}),
)
```

`read` returns the learned entries. `update` runs a `Remember` or `Forget` edit. `consolidate` asks the model to learn new entries from new history.
`MemoryRules` and `LanguageModelMemory` are the default rules and model. You can replace them.
`MemoryRules.policy` limits the memory text to 8000 characters. Use `MemoryRules.make({ maxLength })` for another limit.

`MemoryPlugin.make` gives the plugin that uses memory in each Turn. It adds the active entries to the instructions. After a completed Turn, it learns new entries. You give it two Effects that run in each Turn:

- `settings` returns `{ use, generate }`. `use` turns on the instructions. `generate` turns on learning.
- `languageModel` returns the model that learns the entries.

The host decides where these values come from. Pass `plugin.stores` to `Store.define`, and provide `plugin.store` with `PluginState.make`.

Here `learner` is a `LanguageModel` service that you built before:

```ts
const plugin = MemoryPlugin.make({
	settings: Effect.succeed({ use: true, generate: true }),
	languageModel: Effect.succeed(learner),
})
```

### Turn limits

Three plugins put a limit on each Turn. You can use one of them, or merge them with `PluginComposition.merge`. Each one counts only its own Turn.

#### Model steps

`TurnLimiter` stops a Turn after a set number of model steps. The first model request counts as one step.

```ts
import { TurnLimiter } from "@openbot-build/openbot"

const runtime =
	yield *
	SessionRuntime.make({
		store,
		bot: { plugin: TurnLimiter.make({ maxSteps: 4 }) },
	})
```

It fails with one of two errors:

| Error                    | When                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `InvalidMaxSteps`        | `maxSteps` is not a positive whole number.                                          |
| `ModelStepLimitExceeded` | The Turn needs another model step after the limit. It has `maxSteps` and `history`. |

#### Tokens

`TokenLimiter` stops a Turn after it uses a set number of tokens. A token is a small piece of text that the model reads or writes. The plugin adds the input and output tokens of each model step. A model step that has started can finish. The next model step fails when the total reaches `maxTokens`.

```ts
import { TokenLimiter } from "@openbot-build/openbot"

const plugin = TokenLimiter.make({ maxTokens: 100_000 })
```

| Error                | When                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `InvalidMaxTokens`   | `maxTokens` is not a positive whole number.                                                         |
| `TokenLimitExceeded` | The Turn needs another model step after the limit. It has `maxTokens`, `usedTokens`, and `history`. |

#### Time

`TimeLimiter` stops a Turn after a set time. `maxDuration` takes a number of milliseconds or a text such as `"5 minutes"`. When the time is up, the plugin stops the Turn at once. It also stops a model step or a tool call in the middle.

```ts
import { TimeLimiter } from "@openbot-build/openbot"

const plugin = TimeLimiter.make({ maxDuration: "5 minutes" })
```

| Error                | When                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `InvalidMaxDuration` | `maxDuration` is not a positive, finite time.                            |
| `TimeLimitExceeded`  | The Turn runs longer than the limit. It has `maxDuration` and `history`. |

## Model providers

`@openbot-build/openbot` has three model providers. Each one turns a model selection into a `LanguageModel` Layer. You give the API key. See [Models](/docs/models) for how OpenBot uses them.

### OpenAiCompatProvider

```ts
import { Config, Model, Provider } from "@openbot-build/core"
import { OpenAiCompatProvider } from "@openbot-build/openbot"
import { Effect, Layer, Redacted } from "effect"
import { LanguageModel } from "effect/ai"
import { FetchHttpClient } from "effect/http"

const selection = Config.Selection.make({
	provider: Provider.Id.make("openai-compat"),
	model: Model.Id.make("gpt-4.1"),
})
const model = Layer.unwrap(
	OpenAiCompatProvider.make({ max_output_tokens: 1024 }).model(selection),
).pipe(
	Layer.provide(
		OpenAiCompatProvider.layerClient({
			apiKey: Redacted.make(process.env.OPENAI_API_KEY ?? ""),
			apiUrl: "https://api.openai.com/v1",
		}),
	),
	Layer.provide(FetchHttpClient.layer),
)

const program = LanguageModel.generateText({ prompt: "Hello" }).pipe(
	Effect.provide(model),
)
```

Leave out `apiUrl` to use `https://api.openai.com/v1`. A selection's `reasoningEffort` and `serviceTier` replace `reasoning_effort` and `service_tier` in the defaults.

### OpenAiProvider

The same pattern, with `OpenAiProvider` and the provider ID `openai`. It uses the Responses API.
It also has `ResponsesCompaction.layer()`, which makes long histories shorter with the native compaction of the Responses API.

```ts
import { OpenAiProvider, ResponsesCompaction } from "@openbot-build/openbot"

const services = Layer.merge(
	Layer.unwrap(OpenAiProvider.make().model(selection)),
	ResponsesCompaction.layer(),
).pipe(
	Layer.provide(OpenAiProvider.layerClient({ apiKey })),
	Layer.provide(FetchHttpClient.layer),
)
```

### AnthropicProvider

The same pattern, with `AnthropicProvider` and the provider ID `anthropic`. It uses the Messages API.

```ts
import { AnthropicProvider } from "@openbot-build/openbot"

const provider = AnthropicProvider.make({ max_tokens: 1024 })
```

`reasoningEffort` can be `low`, `medium`, or `high`. `serviceTier` can be `auto` or `standard_only`. Other values fail before any request.

## protocol

`@openbot-build/protocol` implements the OpenBot App Protocol. Publishers use it to put an App on the web. Hosts use it to find, connect to, and call Apps.

```ts
import { Document, McpPublisher } from "@openbot-build/protocol"
import { Effect, Schema } from "effect"
import { McpServer, Tool, Toolkit } from "effect/ai"

const tools = Toolkit.make(
	Tool.make("Hello", {
		parameters: Schema.Struct({ name: Schema.String }),
		success: Schema.Struct({ greeting: Schema.String }),
	}),
)
const handlers = tools.toLayer({
	Hello: ({ name }) => Effect.succeed({ greeting: `Hello, ${name}` }),
})
const origin = "https://apps.example.com"

const publisher = McpPublisher.layer({
	publication: {
		card: {
			$schema: Document.cardSchemaUrl,
			name: "com.example/hello",
			version: "1.0.0",
			description: "Say hello",
			remotes: [
				{
					type: "streamable-http",
					url: origin + "/mcp",
					supportedProtocolVersions: [Document.protocolVersion],
				},
			],
		},
		cardUrl: origin + "/mcp/server-card",
		catalogUrl: origin + "/.well-known/ai-catalog.json",
		mcpUrl: origin + "/mcp",
		allowedOrigins: ["https://host.example.com"],
	},
	register: McpServer.registerToolkit(tools).pipe(Effect.provide(handlers)),
})
```

Serve `publisher` with `HttpRouter.serve` and an HTTP server Layer. See [Protocol](/docs/protocol) for the full guide.
