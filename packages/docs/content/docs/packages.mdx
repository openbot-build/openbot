OpenBot is a pnpm workspace. Each package has one job. `openbot` puts the parts
together into the server. You can use the other libraries on their own.

All packages are named `@openbot-build/<name>`, have version `0.1.0`, and use
`effect@4.0.5`. They are not on npm yet. Use them from the workspace with
`"workspace:*"`.

---

## Overview

| Package         | What it is for                                                                                                                                |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `openbot`       | The server, its plugins, and its model providers. See [Run from code](/docs/server).                                                          |
| `api`           | The typed HTTP contract. The server, the client, and the API reference use it.                                                                |
| `client`        | The TypeScript client. See [Client](/docs/client).                                                                                            |
| `core`          | The Bot core: Bots, Chats, Turns, storage, plugins, and skills.                                                                               |
| `protocol`      | The OpenBot App Protocol: publish, find, connect, and index Apps.                                                                             |
| `protocol-test` | A public test service for the App Protocol. See [Protocol test](/docs/protocol-test).                                                         |
| `cli`           | The `openbot` command. It runs `openbot-<name>` for `openbot <name>`.                                                                         |
| `computer`      | The `openbot computer` command, which pairs and connects your own [Computer](/docs/computers).                                                |
| `docs`          | This docs site.                                                                                                                               |
| `ability`       | Typed authorization policies for Effect. A git subtree of [ability](https://github.com/nmnmcc/ability). See [Permissions](/docs/permissions). |

The examples below leave out the model. To run them, provide a `LanguageModel`
Layer, for example from a [model provider](#model-providers) in `openbot`.

## core

`@openbot-build/core` runs Bots. It has these main parts:

| Module                                       | What it does                                                                                                 |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------ |
| `Bot`                                        | A Bot definition: tools, plugins, providers, compaction, and approvals. One definition can serve many Chats. |
| `ChatRuntime`                                | Runs Turns: `deliver`, `execute`, `stream`, `interrupt`, `drain`, `wait`, and more.                          |
| `ChatStore`, `ChatStoreRepository`, `Store`  | Save Chats: a small record for each Chat, and a log of Items that only grows.                                |
| `ChatStoreMemory`                            | A store that keeps everything in memory, for tests and scripts.                                              |
| `Chat`, `Item`, `Turn`, `ChatState`          | The data types. `Chat` also has the `Approvals` service.                                                     |
| `ContextCompaction`, `SummaryCompaction`     | Make a long history shorter, so that it fits the model.                                                      |
| `Plugin`, `PluginComposition`, `PluginState` | Make and combine plugins, and give them saved state.                                                         |
| `Skill`, `SkillMap`                          | Describe skills and keep a list of them.                                                                     |

A **Chat** is one conversation with no end. Each input goes to its **inbox**. It
starts a **Turn**, or it steers the running Turn. A Turn can have many model
steps and tool calls. A Turn never waits: it runs, and then it ends. The store
keeps the Items of a Chat in a log that only grows, so a long Chat stays cheap
to save.

```ts
import { ChatRuntime, ChatStoreMemory, Store } from "@openbot-build/core"
import { Effect } from "effect"
import { Toolkit } from "effect/ai"

const program = Effect.scoped(
	Effect.gen(function* () {
		const definition = yield* Store.define({
			stores: {},
			schemaVersion: "chat/1",
		})
		const store = yield* ChatStoreMemory.make(definition)
		const runtime = yield* ChatRuntime.make({
			store,
			bot: { toolkit: Toolkit.empty },
		})
		const view = yield* store.create({})
		return yield* runtime.execute({
			chat: view.chat.id,
			input: "Explain closures",
		})
	}),
)
```

`execute` starts a Turn, waits for it to end, and returns the Chat. `stream`
gives events while the Turn runs. Both fail when a Turn already runs in the
Chat.

`deliver` gives input to a Chat in one step, by the rules of the
[inbox](/docs/chats#the-inbox). It starts a Turn when the Chat is idle, steers
the running Turn when the input has the same `author`, and waits in the inbox
otherwise. It returns `started`, `steered` or `queued`. After each Turn, the
next input in the inbox starts the next Turn.

### Approvals

A tool with `needsApproval` asks before each call. The runtime then asks the
`Approvals` service. Give it as `approvals` in the Bot definition, or provide
`Chat.Approvals`. It answers each call with one of three decisions:

- `Chat.Decision.Allow()` runs the call now.
- `Chat.Decision.Deny({ reason })` does not run the call. The model sees the
  reason.
- `Chat.Decision.Pending({ result })` does not run the call now. The model gets
  `result` at once, and the Turn goes on.

Without the service, every such call is pending. So a Turn never waits.

When a decider allows a pending call later, give the call back with `deliver`
and `approved`. The ID of the call must be new. The Turn that reads the input
runs the call, and it does not ask again. Mark input from your program with
`notice`, so that the model knows that it does not come from a person:

```ts
import { Chat } from "@openbot-build/core"

const runtime =
	yield *
	ChatRuntime.make({
		store,
		bot: {
			toolkit,
			approvals: {
				decide: (request) =>
					Effect.succeed(
						Chat.Decision.Pending({ result: { pending: request.approvalId } }),
					),
			},
		},
	})

yield *
	runtime.deliver({
		chat: view.chat.id,
		input: "[Host] A person allowed the email.",
		notice: { kind: "request", ref: "req-1" },
		approved: {
			id: "approved-1",
			name: "SendEmail",
			params: { to: "team@example.com" },
		},
	})
```

### Plugins

A plugin wraps the model loop. `Plugin.make` makes one. Its constructor runs
once. The middleware it returns wraps the event stream of each Turn:

```ts
import { Plugin } from "@openbot-build/core"
import { Effect, Stream } from "effect"

const logging = Plugin.make({ id: Plugin.Id.make("logging") })(() =>
	Effect.succeed((next, options) =>
		next(options).pipe(
			Stream.tap((event) =>
				event._tag === "ModelStepStarted"
					? Effect.log("A model step started")
					: Effect.void,
			),
		),
	),
)
```

`PluginComposition.merge(a, b)` combines two plugins. `a` runs outside `b`. A
plugin can also save its own data in the record of the Chat or in its state.
Pass `plugin.stores` to `Store.define`, then use `PluginState.make`.

### Skills

`Skill.Descriptor` describes a skill. `SkillMap.Catalog` is a list of skills.
When two lists have the same skill ID, the later one wins. Your program finds,
loads, and runs the skills.

## Plugins in openbot

`@openbot-build/openbot` has all plugins of OpenBot. The server uses its
plugins, such as the Bot, App, and work plugins, in every Turn. The work plugin
gives the Bot its todo list, its reminders and plan mode. You can also use the
Turn limit plugins with your own `ChatRuntime`.

### Memory

`BotMemory` has the types and helpers of [Bot memory](/docs/memory). The server
uses them for the memory Bot and the memory API. The schemas of the memory API
are in `api`, as `BotMemory`.

### Turn limits

Three plugins put a limit on each Turn. You can use one of them, or merge them
with `PluginComposition.merge`. Each one counts only its own Turn.

#### Model steps

`TurnLimiter` stops a Turn after a set number of model steps. The first model
request counts as one step.

```ts
import { TurnLimiter } from "@openbot-build/openbot"

const runtime =
	yield *
	ChatRuntime.make({
		store,
		bot: { plugin: TurnLimiter.make({ maxSteps: 4 }) },
	})
```

It fails with one of two errors:

| Error                    | When                                                                                |
| ------------------------ | ----------------------------------------------------------------------------------- |
| `InvalidMaxSteps`        | `maxSteps` is not a positive whole number.                                          |
| `ModelStepLimitExceeded` | The Turn needs another model step after the limit. It has `maxSteps` and `history`. |

#### Tokens

`TokenLimiter` stops a Turn after it uses a set number of tokens. A token is a
small piece of text that the model reads or writes. The plugin adds the input
and output tokens of each model step. A model step that has started can finish.
The next model step fails when the total reaches `maxTokens`.

```ts
import { TokenLimiter } from "@openbot-build/openbot"

const plugin = TokenLimiter.make({ maxTokens: 100_000 })
```

| Error                | When                                                                                                |
| -------------------- | --------------------------------------------------------------------------------------------------- |
| `InvalidMaxTokens`   | `maxTokens` is not a positive whole number.                                                         |
| `TokenLimitExceeded` | The Turn needs another model step after the limit. It has `maxTokens`, `usedTokens`, and `history`. |

#### Time

`TimeLimiter` stops a Turn after a set time. `maxDuration` takes a number of
milliseconds or a text such as `"5 minutes"`. When the time is up, the plugin
stops the Turn at once. It also stops a model step or a tool call in the middle.

```ts
import { TimeLimiter } from "@openbot-build/openbot"

const plugin = TimeLimiter.make({ maxDuration: "5 minutes" })
```

| Error                | When                                                                     |
| -------------------- | ------------------------------------------------------------------------ |
| `InvalidMaxDuration` | `maxDuration` is not a positive, finite time.                            |
| `TimeLimitExceeded`  | The Turn runs longer than the limit. It has `maxDuration` and `history`. |

## Model providers

`@openbot-build/openbot` has three model providers. Each one turns a model
selection into a `LanguageModel` Layer. You give the API key. See
[Models](/docs/models) for how OpenBot uses them.

### OpenAiCompatProvider

```ts
import { Config, Model, Provider } from "@openbot-build/core"
import { OpenAiCompatProvider } from "@openbot-build/openbot"
import { Effect, Layer, Redacted } from "effect"
import { LanguageModel } from "effect/ai"
import { FetchHttpClient } from "effect/http"

const selection = Config.Selection.make({
	provider: Provider.Id.make("openai-compat"),
	model: Model.Id.make("gpt-4.1"),
})
const model = Layer.unwrap(
	OpenAiCompatProvider.make({ max_output_tokens: 1024 }).model(selection),
).pipe(
	Layer.provide(
		OpenAiCompatProvider.layerClient({
			apiKey: Redacted.make(process.env.OPENAI_API_KEY ?? ""),
			apiUrl: "https://api.openai.com/v1",
		}),
	),
	Layer.provide(FetchHttpClient.layer),
)

const program = LanguageModel.generateText({ prompt: "Hello" }).pipe(
	Effect.provide(model),
)
```

Leave out `apiUrl` to use `https://api.openai.com/v1`. A selection's
`reasoningEffort` and `serviceTier` replace `reasoning_effort` and
`service_tier` in the defaults.

### OpenAiProvider

The same pattern, with `OpenAiProvider` and the provider ID `openai`. It uses
the Responses API. It also has `ResponsesCompaction.layer()`, which makes long
histories shorter with the native compaction of the Responses API.

```ts
import { OpenAiProvider, ResponsesCompaction } from "@openbot-build/openbot"

const services = Layer.merge(
	Layer.unwrap(OpenAiProvider.make().model(selection)),
	ResponsesCompaction.layer(),
).pipe(
	Layer.provide(OpenAiProvider.layerClient({ apiKey })),
	Layer.provide(FetchHttpClient.layer),
)
```

### AnthropicProvider

The same pattern, with `AnthropicProvider` and the provider ID `anthropic`. It
uses the Messages API.

```ts
import { AnthropicProvider } from "@openbot-build/openbot"

const provider = AnthropicProvider.make({ max_tokens: 1024 })
```

`reasoningEffort` can be `low`, `medium`, or `high`. `serviceTier` can be `auto`
or `standard_only`. Other values fail before any request.

## protocol

`@openbot-build/protocol` implements the OpenBot App Protocol. Publishers use it
to put an App on the web. Hosts use it to find, connect to, and call Apps.

```ts
import { Document, McpPublisher } from "@openbot-build/protocol"
import { Effect, Schema } from "effect"
import { McpServer, Tool, Toolkit } from "effect/ai"

const tools = Toolkit.make(
	Tool.make("Hello", {
		parameters: Schema.Struct({ name: Schema.String }),
		success: Schema.Struct({ greeting: Schema.String }),
	}),
)
const handlers = tools.toLayer({
	Hello: ({ name }) => Effect.succeed({ greeting: `Hello, ${name}` }),
})
const origin = "https://apps.example.com"

const publisher = McpPublisher.layer({
	publication: {
		card: {
			$schema: Document.cardSchemaUrl,
			name: "com.example/hello",
			version: "1.0.0",
			description: "Say hello",
			remotes: [
				{
					type: "streamable-http",
					url: origin + "/mcp",
					supportedProtocolVersions: [Document.protocolVersion],
				},
			],
		},
		cardUrl: origin + "/mcp/server-card",
		catalogUrl: origin + "/.well-known/ai-catalog.json",
		mcpUrl: origin + "/mcp",
		allowedOrigins: ["https://host.example.com"],
	},
	register: McpServer.registerToolkit(tools).pipe(Effect.provide(handlers)),
})
```

Serve `publisher` with `HttpRouter.serve` and an HTTP server Layer. See
[Protocol](/docs/protocol) for the full guide.
