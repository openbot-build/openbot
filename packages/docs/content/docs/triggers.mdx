---
title: "Run work at a set time"
description: "Run work at a set time"
---

A trigger starts Bot work from a schedule or an outside event. Set it up with
the trigger controls your client provides.

## Set the task

Choose the Bot and write the message it should receive. If you leave the Bot
unset, the trigger uses your default Bot. Make sure that Bot is available and
has a model.

Choose a one-time or repeated schedule and check its time zone. For an outside
event, a webhook is the address another service calls to start the task. Give
its address and secret only to the service that should start it.

A restart keeps the schedule. If a run is overdue, OpenBot starts one task when
it is back. After an upgrade, your client may ask you to confirm the trigger
again. Review and save its settings with your current access before it can run.
Old work does not start again under the new access.

## Check a run

Read the trigger history and the task result in your client. Work from a trigger
still uses your access. It can need a [decision](/docs/requests), and it can
fail when a model, connection, or default Bot is no longer available.

## Change or stop the trigger

Turn off a trigger when it should not start more work. Check already started
work separately. Update the task or schedule when the need changes. Ask your
administrator about access or model failures; use your integration provider for
webhook setup.
