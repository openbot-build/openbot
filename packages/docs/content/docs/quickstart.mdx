This page starts OpenBot on your computer with a test account and test models.
You do not need an identity provider or a model key.

---

## Prerequisites

You need:

1. [devenv](https://devenv.sh) 2.0 or newer. It gives you the right Node.js, pnpm, PostgreSQL, and mkcert. devenv also runs the development database, so you do not need Docker.
2. A copy of the code:

```sh
git clone https://github.com/openbot-build/openbot.git
cd openbot
```

Run every command from the top folder of the code, inside `devenv shell --`.

---

## Start OpenBot

<Steps>

<Step>

### Make the local settings

```sh
devenv shell -- pnpm dev:setup
devenv shell -- mkcert -install
```

The first command makes `.env.development` with a new secret key, and a certificate for `localhost`.
If you have an `.env.development` from an older version, delete it first.
The second command makes your computer trust that certificate. It can ask for your password.

</Step>

<Step>

### Start the server

```sh
devenv shell -- pnpm dev
```

This starts PostgreSQL, builds OpenBot, updates the database, and starts OpenBot at `https://localhost:8443`.
The development server sets up the platform by itself, so you do not run the setup program.
The first start can take a few minutes. Press **Ctrl+C** to stop. Your data stays in the database.

</Step>

<Step>

### Sign in

```sh
curl -c cookies.txt -X POST https://localhost:8443/auth/development/sign-in \
  -H "Origin: https://localhost:8443" \
  -H "Content-Type: application/json" \
  -d '{}'
```

In development, this signs you in to the local test account `developer@localhost.test` at once. The sign-in cookie goes to `cookies.txt`.
This account is a platform admin. It also gets its own organization named "Personal".

</Step>

<Step>

### Make a user token

```sh
curl -b cookies.txt \
  -H 'Origin: https://localhost:8443' \
  -H 'Content-Type: application/json' \
  -d '{"name":"local"}' \
  https://localhost:8443/v1/user/tokens
```

You are the Super Administrator of your "Personal" organization, and the token belongs to it. The answer has a `secret` that starts with `obut_`. You see it only once, so keep it:

```sh
export OPENBOT_TOKEN=obut_...
```

</Step>

<Step>

### Make an Agent

Every Session belongs to an [Agent](/docs/agents). A new account has no Agents, so make one:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"name":"Assistant","role":"Helps me","instructions":"Answer in short sentences."}' \
  https://localhost:8443/v1/agents
```

Take `id` from the answer. To use this Agent when you name no Agent, make it your [default Agent](/docs/agents#your-default-agent).

</Step>

<Step>

### Start a Session and a Turn

Make a Session for your Agent:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"agent":"<agentId>","title":"My first Session"}' \
  https://localhost:8443/v1/sessions
```

Take `session.id` and `session.revision` from the answer. Then give the Session some work:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H 'Content-Type: application/json' \
  -d '{"expected":0,"input":"Hello"}' \
  https://localhost:8443/v1/sessions/<sessionId>/turns
```

The Turn runs in the background and you get `202` at once. Add `"stream": true` to get the answer as a live stream.

</Step>

</Steps>

The test model `mock-text` answers with `Development response:` and your input.
See [Models](/docs/models) for the other test models.
