---
title: Reminders
description: Read and cancel the reminders that a Bot saved for you.
---

`openbot_remind` saves a note for later in the same Chat. It uses the existing
execution engine, so it survives a server restart. A reminder is separate from a
recurring trigger.

`GET /v1/reminders` lists your reminders in the current organization. Optional
query fields are `chatId`, `status`, `after` and `limit` (1–100, default 50).
The response is `{ items, next }`. Each item has `id`, `chatId`, `turnId`,
`executionId`, `note`, `dueAt` and `status`. Pass `next` as `after` to continue;
keep going even if a page has no visible items but has a cursor. Current Chat
rights filter each page. Other members' notes are never returned.

The statuses are `waiting`, `done` and `cancelled`. `done` means the note has
been delivered to the Chat. The work caused by that note may still be running.
Read the saved execution for that work to see its result.

`GET /v1/reminders/:reminderId` reads one reminder. To cancel, send
`POST /v1/reminders/:reminderId/cancel` with `{ "commandKey": "cancel-1" }`. The
response is the existing execution receipt. Keep its key when the HTTP reply is
lost, and read that execution to confirm cancellation. This route uses normal
execution cancellation and current permissions; it does not create another
scheduler. Imported reminders without an execution ID remain readable, but
cancellation returns a conflict.

The SDK exposes `Reminders.list`, `get` and `cancel`. The cancel helper prepares
one command whose key remains stable when its send effect is retried.
