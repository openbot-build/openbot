---
title: Models
description: Connect OpenBot to language models with models and model providers.
---

An Agent needs a language model to do work. OpenBot does not include a model. You connect one.
OpenBot keeps two kinds of records for this:

- A **model** describes one model, such as `gpt-5`: its type, its name, its options and its limits. A model does not belong to a provider.
- A **model provider** is a model service and its API key. A provider **links** the models that it offers. A link can change some values of the model for this provider only.

You add both through the API. OpenBot stores them in the database, so every instance uses the same ones.

The platform or an organization owns each model and each provider:

| Owner        | Who adds it                               | Who can use it                                                                                  |
| ------------ | ----------------------------------------- | ----------------------------------------------------------------------------------------------- |
| Organization | An organization, with its own key         | Only that organization. This is "bring your own key".                                           |
| Platform     | A platform admin, with the platform's key | The organizations in its `availability`. See [Platform](/docs/platform#shared-model-providers). |

An organization can use a model of a provider only when it may use both the provider and the model.

Each model has one of two types:

- A `language` model writes text and calls tools. It runs Sessions, judges Rules and learns Agent memory.
- A `decision` model only picks an answer from a fixed list. It does not write text. Jev from TypeSafe is an example. See [Decision model](#decision-model).

When you run OpenBot from code, you can also give built-in models. See [Built-in models](#built-in-models).

## Add a model

`POST /v1/organization/models` adds a model to your organization. It needs `model_providers.write`.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "id": "qwen3-32b", "name": "Qwen3 32B", "reasoningEfforts": [], "serviceTiers": [], "contextWindow": 131072 }' \
  https://api.example.com/v1/organization/models
```

| Field              | Rules                                                                                                                                                        |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `id`               | Required. 1 to 200 characters. It is unique for its owner, and you cannot change it. A provider sends it as the model name, unless the link sets `upstream`. |
| `type`             | Optional. `language` or `decision`. The default is `language`. You cannot change it later.                                                                   |
| `name`             | Required. A name for people.                                                                                                                                 |
| `reasoningEfforts` | Required. The `reasoningEffort` values that the model accepts. Can be empty.                                                                                 |
| `serviceTiers`     | Required. The `serviceTier` values that the model accepts. Can be empty.                                                                                     |
| `contextWindow`    | Optional. The size of the context window, in tokens.                                                                                                         |
| `maxOutputTokens`  | Optional. The most tokens that the model can write in one answer.                                                                                            |

If your organization already has a model with this `id`, OpenBot returns `409` with `ModelConflict`.

| Route                                     | What it does                                                                             |
| ----------------------------------------- | ---------------------------------------------------------------------------------------- |
| `GET /v1/organization/models`             | Lists the models of your organization. Shared models are not in this list.               |
| `GET /v1/organization/models/:modelId`    | Reads one model.                                                                         |
| `PATCH /v1/organization/models/:modelId`  | Changes a model. The body needs `expectedVersion`. Send `null` for a limit to remove it. |
| `DELETE /v1/organization/models/:modelId` | Removes a model.                                                                         |

Reading needs `model_providers.read`. Changes need `model_providers.write`.
You cannot remove a model while one of your providers links it. OpenBot returns `409` with `ModelInUse`. Remove the link first.

## Add a provider

`POST /v1/organization/model_providers` adds a provider to your organization. It needs `model_providers.write`.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "openai-compat",
    "name": "Local vLLM",
    "endpoint": "https://llm.example.com/v1",
    "apiKey": "sk-...",
    "models": [
      { "model": "qwen3-32b", "modelOwner": "organization", "upstream": "Qwen/Qwen3-32B" }
    ]
  }' \
  https://api.example.com/v1/organization/model_providers
```

| Field      | Rules                                                                                                                                                                   |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `kind`     | Required. The API that the service speaks: `openai`, `anthropic`, `openai-compat` or `typesafe`. See the table below.                                                   |
| `name`     | Required. 1 to 120 characters.                                                                                                                                          |
| `endpoint` | Required for `openai-compat` and `typesafe`. Optional for the others. An `http` or `https` base URL, often ending in `/v1`. No user name, password, query, or `#` part. |
| `apiKey`   | Required. OpenBot stores it encrypted and sends it to the endpoint only.                                                                                                |
| `models`   | Required. 0 to 200 links. The order is the order of the model list.                                                                                                     |

| `kind`          | API                                                     | Model types it can link   |
| --------------- | ------------------------------------------------------- | ------------------------- |
| `openai`        | OpenAI Responses API.                                   | `language`                |
| `anthropic`     | Anthropic Messages API.                                 | `language`                |
| `openai-compat` | OpenAI Chat Completions API, and services that copy it. | `language` and `decision` |
| `typesafe`      | The decision API of TypeSafe.                           | `decision`                |

An `openai-compat` provider can link both types, so a gateway (a service that passes calls on to other services), such as OpenRouter or LiteLLM, can offer both.
OpenBot connects only to public addresses. For a model server in your own network or on your machine, the operator must list its host in `OPENBOT_OUTBOUND_ALLOW`. Until then, calls to it fail. See [Outbound connections](/docs/configuration#outbound-connections).
A `typesafe` provider has no default address yet, because TypeSafe has not published one official address. Give the address that your account uses.
If a provider links a model of a type that it cannot serve, OpenBot returns `400` with `ModelProviderInvalid`.

Each link has these fields:

| Field              | Rules                                                                                        |
| ------------------ | -------------------------------------------------------------------------------------------- |
| `model`            | Required. The `id` of the model. A provider links each model ID only once.                   |
| `modelOwner`       | Required. `organization` for a model of your organization, or `platform` for a shared model. |
| `upstream`         | Optional. The model name that the service gets, when it is not the model `id`.               |
| `reasoningEfforts` | Optional. Replaces the `reasoningEfforts` of the model for this provider.                    |
| `serviceTiers`     | Optional. Replaces the `serviceTiers` of the model for this provider.                        |
| `contextWindow`    | Optional. Replaces the `contextWindow` of the model for this provider.                       |
| `maxOutputTokens`  | Optional. Replaces the `maxOutputTokens` of the model for this provider.                     |

A provider of your organization can link your own models, and the shared models that the platform makes available to you. For any other model, OpenBot returns `404` with `ModelNotFound`.

OpenBot answers with the provider. Its `id` starts with `prov_`. A provider ID is unique in the whole platform. A model selection names it as `provider`.
The API key never comes back. The answer shows `apiKey: { set, hint }` instead. See [Platform](/docs/platform#secrets-never-come-back).

### Change or remove a provider

| Route                                                 | What it does         |
| ----------------------------------------------------- | -------------------- |
| `GET /v1/organization/model_providers`                | Lists the providers. |
| `GET /v1/organization/model_providers/:providerId`    | Reads one provider.  |
| `PATCH /v1/organization/model_providers/:providerId`  | Changes a provider.  |
| `DELETE /v1/organization/model_providers/:providerId` | Removes a provider.  |

Reading needs `model_providers.read`. Changes need `model_providers.write`.

The body of `PATCH` needs `expectedVersion`, the `version` that you read. If someone changed the provider after you read it, OpenBot returns `409` with `ModelProviderConflict`. Leave out `apiKey` to keep the current key. Send `models` to replace all links of the provider.

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expectedVersion":0,"apiKey":"sk-new..."}' \
  https://api.example.com/v1/organization/model_providers/prov_4c1e...
```

The next model call after a change uses the new key, endpoint or links. OpenBot builds each model once, and builds it again when its provider changes.

You cannot remove a provider while `rulesModel`, `agentMemoryModel` or `decisionModel` in the [organization settings](/docs/organization#settings) names it. OpenBot returns `409` with `ModelProviderInUse`. Change the setting first.

## Choose a model

`GET /v1/organization/model_catalog` lists the models that your organization can use now. It needs `models.use`.
Each item is one model of one provider, with the values of the link already applied. A model that two providers link shows two times.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  https://api.example.com/v1/organization/model_catalog
```

```json
{
	"providers": [
		{
			"id": "prov_4c1e...",
			"owner": "organization",
			"kind": "openai-compat",
			"name": "Local vLLM"
		}
	],
	"models": [
		{
			"provider": "prov_4c1e...",
			"id": "qwen3-32b",
			"owner": "organization",
			"type": "language",
			"name": "Qwen3 32B",
			"reasoningEfforts": [],
			"serviceTiers": [],
			"contextWindow": 131072,
			"price": {
				"model": "qwen3-32b",
				"timeZone": "UTC",
				"tiers": [
					{
						"upToInputTokens": null,
						"inputUncached": 400000,
						"inputCacheRead": 100000,
						"inputCacheWrite": 0,
						"output": 1200000,
						"outputReasoning": null
					}
				],
				"periods": [],
				"effectiveFrom": "2026-10-20T08:00:00.000Z"
			}
		}
	],
	"decisionModel": null
}
```

`price` is the current price of the model at this provider. It is missing when nobody set a price. See [Prices](/docs/usage#prices).

A model selection names both the provider and the model ID:

```json
{ "_tag": "Config.Selection", "provider": "prov_4c1e...", "model": "qwen3-32b" }
```

OpenBot never picks a model for you. There is no default model. Each use names its own model:

- **A new Session** uses `settings.model` from the request. Without it, the Session uses the `model` of its [Agent](/docs/agents). When neither gives a model, OpenBot returns `400` with `SessionModelInvalid` and the reason `missing`. A new Agent has no model unless you give it one, so set its `model` when you make it, or later with `PATCH /v1/agents/:id`.
- **The judge of [Rules](/docs/rules)** uses `rulesModel` in the [organization settings](/docs/organization#settings). When it is `null`, the judge gives no answer, so a person or an Agent decides.
- **[Agent memory](/docs/memory#agent-memory)** uses `agentMemoryModel` in the same settings. When it is `null`, Agents learn nothing.

`rulesModel` and `agentMemoryModel` must be `language` models. The catalog gives the `type` of each model, and a Session can choose only `language` models.

Older versions of OpenBot had `defaultModel` and `helperModel`. When you upgrade, OpenBot gives the old `defaultModel` to each Agent that has no model. `rulesModel` and `agentMemoryModel` get the old helper model: `helperModel`, or else `defaultModel`. When both were `null`, the new values stay empty, and you must set them.

For example, to give an Agent a model, send its current `revision` as `expected`:

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" -H 'Content-Type: application/json' \
  -d '{"expected":0,"model":{"_tag":"Config.Selection","provider":"prov_4c1e...","model":"qwen3-32b"}}' \
  https://api.example.com/v1/agents/$AGENT_ID
```

A Session can save its own choice. Send the current Session revision as `expected`:

```sh
curl -X PUT -H "Authorization: Bearer $OPENBOT_TOKEN" -H 'Content-Type: application/json' \
  -d '{"expected":3,"selection":{"_tag":"Config.Selection","provider":"prov_4c1e...","model":"qwen3-32b"}}' \
  https://api.example.com/v1/sessions/$SESSION_ID/model
```

`GET /v1/sessions/:id/models` shows the same models for one Session. See the [Sessions API reference](/docs/api/operations/tags/sessions/) for all fields.

To limit which providers a member may choose, use `models.use` on `openbot.org.<org>.model.<providerId>`. See [Permissions](/docs/permissions#limit-models).

## Decision model

`decisionModel` in the [organization settings](/docs/organization#settings) names the decision model of your organization. It must be a `decision` model that one of your providers offers. Otherwise OpenBot returns `400` with `SettingsInvalid`. `null` means that your organization has no decision model.

For example, to use Jev through TypeSafe, add the model, then a provider that links it, then the setting:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" -H "Content-Type: application/json" \
  -d '{ "id": "jev-latest", "type": "decision", "name": "Jev", "reasoningEfforts": [], "serviceTiers": [] }' \
  https://api.example.com/v1/organization/models

curl -H "Authorization: Bearer $OPENBOT_TOKEN" -H "Content-Type: application/json" \
  -d '{
    "kind": "typesafe",
    "name": "TypeSafe",
    "endpoint": "https://typesafe.example.com/v1",
    "apiKey": "...",
    "models": [{ "model": "jev-latest", "modelOwner": "organization" }]
  }' \
  https://api.example.com/v1/organization/model_providers

curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" -H "Content-Type: application/json" \
  -d '{"expectedVersion":3,"decisionModel":{"_tag":"Config.Selection","provider":"prov_9a2b...","model":"jev-latest"}}' \
  https://api.example.com/v1/organization/settings
```

`GET /v1/organization/model_catalog` shows the setting as `decisionModel`.

OpenBot calls a `typesafe` provider with the TypeSafe client of Effect (`@effect/ai-typesafe`). It sends each request to `<endpoint>/systemone` with the API key as a bearer token, and sends `upstream` as the model name. OpenBot builds the client once for each provider and model, and builds it again when the provider changes.
OpenBot cannot ask a decision model through an `openai-compat` provider yet. You can link one there, but use a `typesafe` provider to ask it.

No part of OpenBot asks the decision model yet.

## Run without a model

An organization without any provider can still read, rename, fork, and delete the Sessions that it has. It cannot make a new Session, because a new Session needs a model. See [Choose a model](#choose-a-model).

Work that needs a model fails with status `503` and the error `SessionExecutionUnavailable`. This includes:

- starting a Turn with `POST /v1/sessions/:id/turns`,
- choosing a model with `PUT /v1/sessions/:id/model`,
- continuing a Turn after a decision or after delegated work.

```json
{ "_tag": "SessionExecutionUnavailable", "session": "..." }
```

## Built-in models

When you run OpenBot from your own program, you can give models in code with the `builtinModels` option. See [Run from code](/docs/server).

- Every organization can use them.
- The API cannot change them.
- They show in the model list next to the stored providers.

`builtinModels` has three fields:

| Field       | What it is                                                                     |
| ----------- | ------------------------------------------------------------------------------ |
| `providers` | The providers to show, such as `{ id, name }`.                                 |
| `models`    | The models to show, as `Config.Model` values.                                  |
| `resolve`   | A function that gets a selection and returns an Effect with a `LanguageModel`. |

This example gives one Anthropic model with a key from the environment of your program:

```ts
import { NodeRuntime } from "@effect/platform-node"
import { Config, Model, Provider } from "@openbot-build/core"
import {
	AnthropicProvider,
	EnvironmentConfiguration,
	Server,
} from "@openbot-build/openbot"
import { Context, Effect, Layer, Redacted } from "effect"
import { LanguageModel } from "effect/ai"
import { FetchHttpClient } from "effect/http"

const selection = Config.Selection.make({
	provider: Provider.Id.make("house"),
	model: Model.Id.make("claude-sonnet-4-5"),
})

NodeRuntime.runMain(
	Effect.scoped(
		Effect.gen(function* () {
			const settings = yield* EnvironmentConfiguration.load
			// Build the model once. It lives as long as the program.
			const layer = Layer.unwrap(
				AnthropicProvider.make({ max_tokens: 4096 }).model(selection),
			).pipe(
				Layer.provide(
					AnthropicProvider.layerClient({
						apiKey: Redacted.make(process.env.ANTHROPIC_API_KEY ?? ""),
					}),
				),
				Layer.provide(FetchHttpClient.layer),
			)
			const claude = Context.get(
				yield* Layer.build(layer),
				LanguageModel.LanguageModel,
			)
			const builtinModels = {
				providers: [{ id: selection.provider, name: "House models" }],
				models: [
					Config.Model.make({
						provider: selection.provider,
						id: selection.model,
						name: "Claude Sonnet 4.5",
						reasoningEfforts: [],
						serviceTiers: [],
					}),
				],
				resolve: (requested: Config.Selection) =>
					requested.model === selection.model
						? Effect.succeed(claude)
						: Effect.fail(
								new Config.ModelConfigurationError({
									reason: "model-not-found",
									message: "This model is not available",
								}),
							),
			}
			return yield* Layer.launch(
				Server.layer({ ...settings, builtinModels }).pipe(
					Layer.provide(FetchHttpClient.layer),
				),
			)
		}),
	),
)
```

When `resolve` fails, starting a Turn returns `503`.
The development entry point uses `builtinModels` for its test models. See `packages/openbot/src/app/DevelopmentModel.ts` for a full example.

### Provider modules

A provider module turns a model name into a `LanguageModel` for one kind of API. `@openbot-build/openbot` exports three of them. Each one has the same parts:

| Part                        | What it does                                                            |
| --------------------------- | ----------------------------------------------------------------------- |
| `make(defaults?)`           | Makes a provider. `defaults` are request options for every call.        |
| `provider.model(selection)` | Returns the model Layer for one selection. It sends no requests.        |
| `layerClient(options)`      | Makes the HTTP client. Pass `apiKey`, and `apiUrl` for another address. |
| `layer(tag, defaults?)`     | Puts the provider in a service that you name.                           |

| Module                 | Provider ID     | API                                                                         |
| ---------------------- | --------------- | --------------------------------------------------------------------------- |
| `OpenAiProvider`       | `openai`        | OpenAI Responses API. `ResponsesCompaction` adds native context compaction. |
| `OpenAiCompatProvider` | `openai-compat` | OpenAI Chat Completions API, and services that copy it.                     |
| `AnthropicProvider`    | `anthropic`     | Anthropic Messages API.                                                     |

OpenBot uses these modules for the stored providers too.
Context compaction makes a long history shorter so that it fits in the model's context window.
See [Packages](/docs/packages) for a short example of each provider.

## Development models

The development server (`devenv shell -- pnpm dev`) does not call a real model. It uses test models instead. They give the same answer every time, so you can test clients without cost.

The provider ID is `development`. The model IDs are:

| Model          | What it does                                                                 |
| -------------- | ---------------------------------------------------------------------------- |
| `mock-text`    | The default. Returns fixed text at once.                                     |
| `mock-slow`    | Returns text slowly over ten seconds. Use it to test streams and interrupts. |
| `mock-tool`    | Calls a harmless test tool that waits for a [request](/docs/requests).       |
| `mock-app`     | Calls a tool of the test App and returns its real content.                   |
| `mock-failure` | Sends some text, then fails on purpose with a model error.                   |

The token counts in their answers are not real. To pick one, save it on a Session:

```sh
curl -X PUT -H "Authorization: Bearer $OPENBOT_TOKEN" -H 'Content-Type: application/json' \
  -d '{"expected":1,"selection":{"_tag":"Config.Selection","provider":"development","model":"mock-slow"}}' \
  https://localhost:8443/v1/sessions/$SESSION_ID/model
```

The development entry point gives these models with `builtinModels`, so every organization of the development platform can use them. The production program never uses them.
