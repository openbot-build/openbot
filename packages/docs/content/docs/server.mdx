For developers. Start with the [developer manual](/developers) to choose API
work, App publishing, or project changes.

The `openbot` program covers most needs. When you need more, you can start
OpenBot from your own program. Then you can add your own models, tools, routes,
and App Index sources.

OpenBot is built with [Effect](https://effect.website). You build it from
Layers. A Layer is an Effect recipe that builds services. Making a Layer does
not open the network or the database. That happens when you launch it.

---

## The smallest program

This program does the same as `openbot`:

```ts
import { Host, Launch } from "@openbot-build/openbot"

Launch.main(Host.layer)
```

`Launch.main` first reads the command line. With `--help` it shows the help and
stops, and it needs no settings for that. Then it reads the variables in
[Configuration](/configuration), from the environment or from secret files. It
blocks outbound connections to private addresses, and logs a failed start. Then
it runs the Layer that you give it until the process stops. It gives that Layer
the Node.js services and the fetch HTTP client. `Launch.server` is the same
program as an Effect, for when you run it yourself. Give it `NodeServices.layer`
and `NodeCrypto.layer`.

`Launch.settings` reads the same settings: `host`, `port`, `databaseUrl`,
`secretKeys`, `clusterSecret`, `clusterHost`, `outboundAllow`, and
`pluginsFile`. You can also write these values in code.

The program still needs a platform. Run the setup program once before people use
it. See [Platform](/platform#setup).

## What the package exports

The package exports four namespaces and the programs (`openbot-server`,
`openbot-migrate`, `openbot-setup`, and `openbot-inspect`). It exports nothing
else.

| Export                                                       | What it is                                                                                                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `Host.layer(options)`                                        | OpenBot with its own Node.js HTTP server. `openbot-server` runs it.                                                                        |
| `Host.layerApp(options)`                                     | The OpenBot routes and services, for an HTTP server that you already have.                                                                 |
| `Host.Options`, `Host.AppOptions`                            | The options of `Host.layer` and of `Host.layerApp`. See [Options](#options).                                                               |
| `Host.routes(work)`, `Host.startup(work)`                    | Your own routes and your own startup work, with the services of plugins that they need. See [Your own routes](#your-own-routes).           |
| `Host.Outside`, `Host.RouteServices`, `Host.StartupServices` | The services from outside, and the services of the host that your routes and your startup work can use.                                    |
| `Launch.main(make)`, `Launch.server(make)`                   | Runs the Layer from `make` as `openbot-server` does.                                                                                       |
| `Launch.settings`, `Launch.Settings`                         | Reads the settings of a server from environment variables and secret files, and their type.                                                |
| `Launch.StartFailed`                                         | The error of a start that failed. See [The plugin host](#the-plugin-host).                                                                 |
| `Preset`                                                     | The table of the plugins of OpenBot (`plugins`), its entries for the loader (`entries`), and the plugins that must be active (`required`). |
| `Wallets`                                                    | The service of credit operations (`Wallets.Wallets`). Your routes can use it.                                                              |

The development server (`@openbot-build/server-development`) and the test
helpers (`@openbot-build/server-testing`) are built on these exports only. See
[Run the development server](#run-the-development-server) and
[Test servers in code](/developers/testing#test-servers-in-code).

## Options

`Host.layer` takes instance options, sign-in options, and app options.
`Host.layerApp` takes the instance options and the app options, but not `host`
and `port`, because it has no HTTP server of its own. It also takes no sign-in
options.

### Instance options

| Option          | Type               | What it is                                                                                               |
| --------------- | ------------------ | -------------------------------------------------------------------------------------------------------- |
| `host`          | `string`           | Required. The address to listen on, such as `127.0.0.1`.                                                 |
| `port`          | `number`           | Required. The port to listen on, such as `3000`.                                                         |
| `databaseUrl`   | `Redacted<string>` | Required. The PostgreSQL URL.                                                                            |
| `secretKeys`    | `Redacted<string>` | Required. The secret key list. See [Secret keys](/configuration#secret-keys).                            |
| `clusterSecret` | `Redacted<string>` | Required. At least 32 characters. All nodes use the same secret for private RPC.                         |
| `clusterHost`   | `string`           | Optional. The address other nodes can reach. It defaults to the bound HTTP address.                      |
| `pluginsFile`   | `string`           | Optional. The path of the plugins file. See [Plugins](/plugins) and [The plugin host](#the-plugin-host). |

### Sign-in

Without the `auth` option, the server reads the public origin, the platform
provider, and the sign-in secret from the
[platform settings](/platform#platform-settings).

- Before setup, every route except `/health` answers `503` with `SetupRequired`.
- OpenBot reads these settings each time it uses them. When one of them changes,
  the next request uses the new value. The server is built only once, so
  requests and Turns that are running go on.

The `auth` option of `Host.layer` gives one sign-in configuration. When the
server starts, it writes the public origin, the sign-in secret, and the provider
of `auth` to the platform settings. Then it works as it does without `auth`, so
a later change of the platform settings also works at once. When `auth` is in
development mode, the server uses the local test account, and it keeps its App
Index apart from the public one. Tests and the development server use this
option. Two more options go with `auth`: `platformAdmins` gives the platform
admins of a new platform, and `fileStorage` gives the object storage for files.

### App options

| Option      | What it does                                                                                                                                                                                                         |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entries`   | The entries of the plugin loader. The default is `Preset.entries`. A test can add its own plugins here.                                                                                                              |
| `plugins`   | More plugins that the entries can name, by module name. The plugins of the preset win over them.                                                                                                                     |
| `hostTools` | The tools that your program gives to every Chat. See [Add a tool](#add-a-tool).                                                                                                                                      |
| `outside`   | A Layer with services from outside that take the place of the real ones. Its errors and the services it needs go into the type of the server Layer. See [Services that OpenBot needs](#services-that-openbot-needs). |
| `work`      | Your own routes and startup work. Make each one with `Host.routes` or `Host.startup`. See [Your own routes](#your-own-routes).                                                                                       |

Values that every instance shares are settings in the database, not options. The
timing of the App Index worker is the config of the `apps` plugin in the plugins
file: `{ intervalMs, retryMs }`. See [Plugins](/plugins).

## Services that OpenBot needs

`Host.layer` and `Host.layerApp` build the services that OpenBot needs, but not
the platform services. Two options let your program give its own services in
place of the default ones. So a test can give fakes, and your program can give
its own.

| Services                               | What they are                                                                                                                                                                                                                                | Default                                                                                                                                   |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| Shared services                        | The database pool, the secret keys, and the shared settings.                                                                                                                                                                                 | Made from `databaseUrl` and `secretKeys`.                                                                                                 |
| Services from outside (`Host.Outside`) | The drivers of the Computer providers, the Live backends, the readers of password managers, the network and the check of Apps, the DNS check of domains, the public network of the App Index, the discovery of Apps, and the mail transport. | The real services, on the network of the process, with the address rule of the outbound guard. Mail goes out with SMTP. Option `outside`. |
| Built-in models (`BuiltinModels`)      | Models that every organization can use, given in code. See [Models](/models#built-in-models). It is an outside service too.                                                                                                                  | None. Give `Layer.succeed(BuiltinModels, models)` in the `outside` Layer.                                                                 |
| Tools of the host (`HostTools`)        | The tools that your program gives to every Chat.                                                                                                                                                                                             | `HostTools.none`. Option `hostTools`.                                                                                                     |
| Platform services                      | Files, paths, random numbers, digests, and the HTTP client.                                                                                                                                                                                  | None. Give `NodeServices.layer`, `NodeCrypto.layer`, and `FetchHttpClient.layer`.                                                         |

The `outside` Layer can give only some of the services from outside. The host
keeps the real service for each one that it does not give. The `outside` Layer
can use the shared services, such as the settings and the database pool.

`Launch.main` gives the platform services. This program does the same as
`Launch.main(Host.layer)`, with the tools of the host in view:

```ts
import { Host, Launch } from "@openbot-build/openbot"
import * as HostTools from "@openbot-build/tools-contract/HostTools"

Launch.main((settings) =>
	Host.layer({ ...settings, hostTools: HostTools.none }),
)
```

## Chats

Models come from the model providers in the database and from the
`BuiltinModels` service. See [Models](/models). [Bot memory](/developers/memory)
follows `botMemory` in the [organization settings](/organization#settings).

The server keeps application services and active executions. Each Turn builds
its model and tools in its own scope. A saved execution identity carries the
member, original token, Bot, and delegation limits. Requests do not keep a
member runtime open. One Chat admits one advancing Turn at a time. Its commands,
checkpoints, events, and results stay in PostgreSQL across nodes and restarts.
Closing an HTTP stream closes observation; cancellation is a separate command.

### Add a tool

A tool is a function that the model can call. Make it with Effect AI. Then give
the toolkit and its handlers to OpenBot with `HostTools.layer`. Every Turn of
every Chat can call the tool. `handlers` gets the ID of the Chat and gives the
handlers for its Turns. Each Turn builds them when it starts, and closes them
when it ends.

```ts
import { Host, Launch } from "@openbot-build/openbot"
import * as HostTools from "@openbot-build/tools-contract/HostTools"
import { DateTime, Effect, Schema } from "effect"
import { Tool, Toolkit } from "effect/ai"

const CurrentTime = Tool.make("CurrentTime", {
	description: "Returns the current time on the server.",
	parameters: Schema.Struct({}),
	success: Schema.String,
})
const toolkit = Toolkit.make(CurrentTime)
const handlers = toolkit.toLayer({
	CurrentTime: () => Effect.map(DateTime.now, DateTime.formatIso),
})

Launch.main((settings) =>
	Host.layer({
		...settings,
		hostTools: HostTools.layer({ toolkit, handlers: () => handlers }),
	}),
)
```

Add `needsApproval: true` to `Tool.make` when each call needs a decision.
OpenBot then checks the capability `tools.call` for it. When the call needs a
decider, the Bot gets a pending result, and the call runs later when it is
allowed. See [Requests](/developers/requests).

## Your own routes

`Host.routes` adds HTTP routes to the same server. It takes a name, the keys of
the services of plugins that the routes need (`inject`), and a Layer with the
routes. The Layer can use the services of `inject` and the services of the host
in `Host.RouteServices`: the router, the database pool, the settings, and the
rate limits. For example, inject `Auth` to check the sign-in cookie, and
`Wallets.Wallets` for credit operations.

```ts
import { Host, Launch, Wallets } from "@openbot-build/openbot"
import { Effect, Layer } from "effect"
import { HttpRouter, HttpServerResponse } from "effect/http"

const origin = Host.routes({
	name: "origin",
	inject: [Wallets.Wallets],
	layer: Layer.unwrap(
		Effect.map(Wallets.Wallets, (wallets) =>
			HttpRouter.add(
				"GET",
				"/origin",
				Effect.map(wallets.publicOrigin, (text) =>
					HttpServerResponse.text(text),
				).pipe(Effect.orDie),
			),
		),
	),
})

Launch.main((settings) => Host.layer({ ...settings, work: [origin] }))
```

The routes are a fork of the host. A fork is a part of the plugin host that
starts and stops on its own. It mounts the routes when every key of `inject` is
there. When a plugin that gives one of these keys starts again, the fork takes
the routes away, and mounts them again with the new services. So the routes
always use the services that run now. When a key is never there, for example
because the plugins file turns its plugin off, the server does not start.

`Host.startup` adds work that runs when the server starts, such as indexing an
App. It takes the same three values. Its Layer can use the services of `inject`
and the services in `Host.StartupServices`. It lives as long as the routes do,
and it runs again when a plugin that gives one of its keys starts again.

Do not use paths under `/auth/` or `/v1/`. OpenBot owns them.

OpenBot serves these routes with a router of their own. Router middleware in
this Layer, also global middleware, works only on these routes. When a route of
OpenBot and one of your routes match the same request, the route of OpenBot
wins. This is also true for a wildcard route, such as `/*`. It gets only the
requests that no route of OpenBot takes, also for `HEAD`.

## Use your own HTTP server

`Host.layerApp(options)` gives the OpenBot routes and services, for an HTTP
server that you already have. Serve it with
`HttpRouter.serve(Host.layerApp(options))`. It needs the platform services and
your HTTP server.

`Host.layer` starts its own Node.js server, and puts a check of the platform
settings around the router. While the platform has no settings, the check
answers every route except `/health` with `503` and `SetupRequired`.
`Host.layerApp` has no such check. Add the same check to your server as router
middleware. Read `packages/openbot/src/Serving.ts` for how `Host.layer` does it.
Keep the sign-in secret in the platform settings, not in your own environment
variable. Every instance must use the same one.

## The plugin host

`Host.layer` and `Host.layerApp` run OpenBot on the plugin host. Each feature is
a plugin. See the plugin host in [Execution design](/architecture).

The Layer is ready when every plugin and every fork of `work` is active. A
failed start fails the Layer with `Launch.StartFailed`. Its `reason` is
`RequiredPluginMissing`, `PluginsInactive`, `PluginsFileInvalid`, or
`PluginsFileUnreadable`. Its `message` names the plugins or the problems, and
its `cause` holds the full error. The full cause of a plugin failure is in the
error records. `Launch.main` logs the failure and stops the process.

The Layers give the services of the host, such as the database pool and the
settings, and no service of a plugin. Work that needs a service of a plugin is a
fork of `work`, and it names the keys that it needs. So the plugins file can
turn any plugin off that is not required, also in `Host.layer`. Turn off the
plugins that need it too: for example, without `bots`, also turn off `chats` and
every other plugin that injects a service of `bots`. A plugin that waits for a
service that no plugin gives stops the start. See [Plugins](/plugins).

## Migrate the database

The `openbot-migrate` program applies every migration of `server-database` and
then checks the schema. It needs only `OPENBOT_DATABASE_URL`. Stop all instances
before you run it. `Host.layer` and `Host.layerApp` check the schema before they
start services. This version needs a new database: a migration stops with an
error when the database holds data of an older version. See
[Deploy](/deploy#prepare-the-database).

```sh
pnpm --filter @openbot-build/openbot migrate
```

## Run the development server

`pnpm dev` runs the development server. It has a local test account, simulated
models, and a simulated App. A project that builds on OpenBot can run the same
server from its own program:

```ts
import { NodeRuntime } from "@effect/platform-node"
import * as Development from "@openbot-build/server-development/Development"

NodeRuntime.runMain(Development.launch)
```

`Development.launch` reads the same settings as `Launch.main`, and
`OPENBOT_DEV_PUBLIC_ORIGIN`. When the `OPENBOT_DEV_S3_*` variables are set, it
uses that local object storage for files, and makes its bucket.
`Development.layer` is the server without these steps. It is `Host.layer` with
simulated services from outside, simulated models, and the routes and startup
work of the simulated App. It needs the platform services, such as
`NodeServices.layer`, `NodeCrypto.layer`, and `FetchHttpClient.layer`, and
`Development.launch` gives them. It writes the platform settings itself, so it
needs no setup program. `Development.developmentSecret` makes the sign-in secret
from the first secret key, so it stays the same after a restart. `pnpm dev` runs
it from the package `server-development`. Never use the development server in
production. Everyone who can reach it can sign in.

## Send error logs to your own service

OpenBot writes failures as error logs. Add your own Effect logger to send them
to another service. See [Error logs](/error-logs) for what each log contains and
a full example.
