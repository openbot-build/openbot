**OpenBot** 是一个开源的 Bot（机器人）平台。它没有自己的用户界面。你通过 HTTP
API 使用它。Bot 是一种程序。它接收用自然语言写的目标，规划步骤，使用工具，然后给出结果。

OpenBot 在服务器上运行 Bot 的工作，并保存历史记录。Bot 要使用新能力之前，OpenBot 会先询问人。客户端由你自己提供：可以是脚本、后端服务、聊天机器人，或者你自己的网页或移动应用。

---

## 你可以做什么

- 在一个 **Chat**（聊天）中和一个 **Bot**
  说话。它总是马上回答。你可以一次读取完整回答，也可以读取实时流。
- 让 Bot 把长的工作交给其他 Bots，或者交给它自己。这些工作并行运行，每个结果都会回到你的 Chat。
- 让 Bot 使用 **Apps**：这是人们连接到自己账户的外部服务。
- 维护一个长期存在的 **Bots**
  团队，例如一个程序员和一个写作者。每个 Bot 有自己的 Chats 和记忆，它们之间可以互相分派工作。
- 让 Bot 在**计划模式**中先做计划，维护**待办列表**，并请求**提醒**。用**触发器**按计划时间或通过 webhook 启动它的工作。
- Bots 没有预设的限制。当 Bot 尝试新的事情时，它上面的决策者会回答一个
  **request**（请求），这个回答会被保存下来。
- 在公开的 **App
  Index**（App 索引）中查找 Apps，并以发布者身份检查你自己的 App。

## 工作原理

| 部分         | 作用                                                                          |
| ------------ | ----------------------------------------------------------------------------- |
| OpenBot      | 服务器。它运行 Chats，把数据存到 PostgreSQL，并提供 HTTP API。                |
| Platform     | 一个部署，包含多个组织。平台管理员通过 API 管理它。                           |
| 登录         | 一个人在浏览器中登录一次，使用平台或其所在组织的 OpenID Connect 提供方。      |
| 用户令牌     | 程序在每次调用时，都在 `Authorization: Bearer <token>` 请求头中发送一个令牌。 |
| 权限         | 角色和策略决定每个成员和每个令牌可以做什么。                                  |
| API 契约     | 一份有类型的契约，生成服务器、TypeScript 客户端和 [API 参考](/docs/api/)。    |
| App Protocol | 一种开放的方式，用来在网上发布 Apps，让 Bots 能找到并使用它们。               |

每个 OpenBot 都会告诉你下一步去哪里。发送 `GET /` 来读取它的服务文档：

```sh
curl https://api.example.com/
```

```json
{
	"name": "OpenBot API",
	"documentation": "/docs",
	"openapi": "/openapi.json",
	"auth": "/auth",
	"tokens": "/v1/user/tokens"
}
```
