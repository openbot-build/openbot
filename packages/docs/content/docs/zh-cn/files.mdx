任务需要文档或图片时，把文件交给 Bot。平台需要配置文件存储，客户端也需要支持上传。

## 把文件交给 Bot

通过客户端上传文件。等待上传就绪后，将文件附在消息中，并说明要如何处理。仅上传文件不会把它发送给 Bot。所选模型必须支持这种输入。

## 保留或删除文件

你可以读取和删除自己的文件。引用文件的 Chat 会保留它。删除 Chat 后，不再使用的文件可能被清理。未使用文件通常在 24 小时后到期，平台可以设置其他时间。需要长期保留的文件，请另存副本。

删除文件后，早先消息中也无法再读取它。Bot 会看到一条简短提示，代替原有内容。

OpenBot 在同一数据库事务中隐藏文件并保存删除任务。共同工作流先删除存储中的内容，再删除文件记录。存储调用失败时会保存错误 ID，并在逐渐增加的等待时间后重试。重启会保留任务和已保存的结果。一个持久保留期任务查找过期且未使用的文件，各实例不再分别运行删除循环。

数据迁移会把旧的未完成删除保留为已中断工作。重新发送删除请求，即可按你当前的权限继续处理。重复请求共用正在执行的任务。外部结果未知的任务会保持停止，直到相关决定得到处理。

## 处理上传问题

检查文件类型、大小和存储额度。仍在上传的文件不能用于消息。如果存储不可用或客户端无法上传，请把错误信息交给管理员或客户端提供者。

## 读取生成的成果

Bot 发布为[成果](/zh-cn/artifacts)的文件保留固定的成果 ID 和各个版本。有权读取所属 Chat 的人可以下载它们。这不会改变普通上传文件的私有权限。
