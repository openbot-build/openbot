面向开发者。从[开发者手册](/zh-cn/docs/developers)选择 API 接入、App 发布或项目贡献。

这些工具面向发布 App 的人。你可以检查你的 App、证明你控制它、与团队共享访问权限、运行私密测试、请求收录，以及在出现问题时收到通知。

只有检查调用是公开的。其他所有调用都需要用户令牌或 session cookie，以及 `App`
上的 `publish`。参见[身份验证](/zh-cn/docs/developers/authentication)。

声明、证明、成员、报告和收录请求的 ID 必须是 UUID 文本。报告翻页游标 `before`
和比较 ID `other` 也遵循此规则。旧 UUID v4 和新 UUID
v7 都可使用。API 会在访问存储前拒绝其他格式。邀请的 bearer
token 和通知 ID 保留各自的格式。

## 检查 App

任何人都可以检查 App。你不需要登录。检查只读取公开的文档。它不保存任何东西，也不连接 App。

```sh
curl -X POST https://api.example.com/v1/developer/inspect \
  -H "Content-Type: application/json" \
  -d '{ "input": "apps.example.com" }'
```

`input` 可以是一个域名或一个 HTTPS 链接，最多 8192 个字符。报告包含：

| 字段     | 说明                                                                                                                                                                                 |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `apps`   | 找到的每个 App。对于公开的 Index，`eligibility` 为 `Eligible`、`Excluded` 或 `Unconfirmed`。`stored` 显示最近一次保存的索引检查（如果有）。                                          |
| `issues` | 需要修复的问题。每个问题都有一个 `code`、一个 `stage`、一个 `severity`（`blocking` 或 `suggestion`）、一个 `message` 和一个 `repair` 提示。                                          |
| `stages` | 每个检查步骤：`Input`、`Discovery`、`CardRead`、`CardSchema`、`Compatibility`、`PublisherAssociation` 和 `Eligibility`。每个都是 `Passed`、`Failed`、`Unconfirmed` 或 `NotChecked`。 |

`Eligible` 结果并不表示 App 已经在 Index 中。参见
[App Index](/zh-cn/docs/developers/app-index#app-如何被收录)。

## 证明你控制 App

大多数工具需要证明你控制这个 App。你可以用两种方式证明：

| 范围                | 覆盖什么                                                             | 令牌放在哪里      |
| ------------------- | -------------------------------------------------------------------- | ----------------- |
| `PublisherHostname` | Card 位于这个主机名上、并且被同一主机名上的 Catalog 列出的所有 App。 | 一条 DNS TXT 记录 |
| `AppCard`           | 一个 App，按它确切的 Card URL。                                      | Server Card       |

<Steps>
<Step>

### 发起声明

```sh
curl -X POST https://api.example.com/v1/developer/claims \
  -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "_tag": "PublisherHostname", "hostname": "apps.example.com" }'
```

对于单个 App，发送
`{ "_tag": "AppCard", "cardUrl": "https://apps.example.com/mcp/server-card" }`。主机名必须是一个确切的公开名称，不能带端口、路径或通配符。

响应中有一个 `id` 和一个形如 `openbot-verification=...` 的
`token`。声明保留 24 小时。

</Step>
<Step>

### 发布令牌

对于主机名，在 `_openbot-verification.<hostname>` 添加一条 DNS
TXT 记录。用完整的令牌作为值：

```txt
_openbot-verification.apps.example.com.  TXT  "openbot-verification=abc123..."
```

对于单个 Card，把令牌加到 Card 中：

```json
{
	"_meta": {
		"openbot/developer-verification": {
			"version": 1,
			"tokens": ["openbot-verification=abc123..."]
		}
	}
}
```

OpenBot 在 Card 确切的 URL 读取它，不跟随重定向。你的 `robots.txt` 必须允许
`OpenBot` 用户代理。

</Step>
<Step>

### 验证

```sh
curl -X POST https://api.example.com/v1/developer/claims/<claim id>/verify \
  -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"commandKey":"proof-check-1"}'
```

API 返回 202 和 `executionId`。如果响应丢失，使用同一个 `commandKey` 重试。读取
`/v1/executions/:executionId` 或订阅执行事件。完成后，用
`GET /v1/developer/proofs/<claim id>` 读取**证明**。你会成为该范围的
`administrator`。失败结果只包含安全的错误分类和
`errorId`，完整原因保存在加密错误记录中。令牌缺失或声明过期会产生 `conflict`
结果；网络读取失败会产生 `external`
结果。关闭事件流不会停止检查，停止检查需要调用执行取消端点。

SDK 提供 `Proofs.verifyClaim(id)` 和
`Proofs.verifyProof(id)`。它们返回带有稳定键和 `send`
Effect 的命令，重试时复用该命令。

</Step>
</Steps>

请保留令牌。证明的有效期是 7 天，OpenBot 每天都会重新检查它：

- 如果令牌不见了，证明会立刻变成 `Suspended`。
- 如果检查无法运行，证明会变成
  `Unconfirmed`。在到期之前它仍然有效。OpenBot 会在大约一分钟后重试。
- `Suspended` 的证明不提供任何访问权限。

要立刻检查，请向 `POST /v1/developer/proofs/:id/verify` 提交新的
`commandKey`。它也会返回执行回执。要放弃一份证明，请调用
`POST /v1/developer/proofs/:id/relinquish`。要取消一个声明，请调用
`POST /v1/developer/claims/:id/revoke`。

`GET /v1/developer` 返回你的 App、你的证明，以及你的访问授权 `grants`。

## 成员和角色

管理员可以邀请其他账号。

| 角色            | 能做什么                                   |
| --------------- | ------------------------------------------ |
| `administrator` | 做出证明的账号。可以做所有事，并管理成员。 |
| `maintainer`    | 保存报告、运行测试和请求收录。             |
| `viewer`        | 读取 App、报告和收录请求。不能修改。       |

1. 邀请：`POST /v1/developer/proofs/:id/invitations`，带上
   `{ "role": "maintainer" }` 或 `"viewer"`。邀请保留 7 天。
2. 把邀请的 `id` 发给对方。对方用 `GET /v1/developer/invitations/:id` 读取它，用
   `POST /v1/developer/invitations/:id/accept` 接受它。
3. 管理：`GET /v1/developer/proofs/:id/members`、带新 `role` 的
   `PUT /v1/developer/members/:id`，以及
   `DELETE /v1/developer/members/:id`。成员也可以移除自己。

要取消邀请，请调用
`POST /v1/developer/invitations/:id/revoke`。证明结束时，它的成员也会失去访问权限。

## 报告

报告是一次保存下来的检查。用报告查看你的 App 随时间如何变化。

| 任务                 | 请求                                                                                |
| -------------------- | ----------------------------------------------------------------------------------- |
| 保存一份新报告       | `POST /v1/developer/reports`，带上 `{ "cardUrl" }`                                  |
| 列出某个 App 的报告  | `GET /v1/developer/reports?cardUrl=...`（最新的在前，每页 50 条，用 `before` 翻页） |
| 读取一份报告         | `GET /v1/developer/reports/:id`                                                     |
| 比较两份报告         | `GET /v1/developer/reports/:id/compare?other=<id>`                                  |
| 删除你保存的一份报告 | `DELETE /v1/developer/reports/:id`                                                  |
| 列出你保存的报告     | `GET /v1/developer/personal-reports`                                                |

比较结果会列出 `introduced`（新出现）、`resolved`（已解决）和
`persisting`（仍存在）的问题。

## 私密连接测试

测试会像用户一样从 OpenBot 连接你的 App。它是私密的。它不保存用户连接，也不把 App 加入 Index。测试在一小时后结束。

1. 用你自己的 UUID 创建一个测试：`POST /v1/developer/tests`，带上
   `{ "id", "cardUrl", "remoteIndex" }`。
2. 如果端点需要设置，就发送它们：`PUT /v1/developer/tests/:id/configuration`，带上一个由键和值组成的对象。键和[连接](/zh-cn/docs/developers/apps#审查并创建连接)中的相同。
3. 运行测试：向 `POST /v1/developer/tests/:id/run` 发送
   `{ "commandKey": "test-run-1" }`。接口返回 `202` 和执行回执。用
   `GET /v1/developer/tests/:id` 读取测试，用
   `GET /v1/executions/:executionId/observe` 订阅已保存的事件。

响应丢失时复用同一个命令键。上次运行结束后，用新键启动下一次运行。测试保留最近一次的
`executionId`。SDK 的 `DeveloperTests.run(id)` 生成命令，其 `send`
方法会复用命令键。关闭事件流不会停止测试。通过执行接口取消，或使用测试清理接口先停止运行，再删除私有数据。清理会等待运行释放连接。启动另一个服务器不会改写活动工作流的状态。节点丢失后会复用已保存的调用结果；未完成的读取可以重新执行。

每次运行都有
`stages`：`configuration`、`negotiation`、`tools`、`resources`、`resourceTemplates`
和 `prompts`。每个阶段都是 `Passed`、`Failed`、`NotAdvertised` 或
`NotChecked`。测试的 `status` 最终为 `Succeeded` 或 `Failed`。

### 在测试中登录

当 App 需要账号时，测试状态会变成 `AwaitingAuthorization`。

1. 开始登录：`POST /v1/developer/tests/:id/authorization`，带上
   `{ "scopes": [], "commandKey": "test-sign-in-1" }`。如果 App 有多个提供方，请加上
   `issuer`。接口返回 `202` 和执行回执。订阅执行事件，结束后读取测试中的
   `authorization.authorizationUrl`。`PreparingAuthorization`
   表示准备尚未结束。登录链接和加密 flow 会在同一次提交中保存。响应丢失时复用命令键。SDK 的
   `DeveloperTests.authorize(id, { scopes: [] })` 会保留此键。
2. 在浏览器中打开 `authorization.authorizationUrl` 并登录。
3. 提供方把你跳转到 `/auth/developer/apps/callback`。OpenBot 再把你跳转到
   `/?developerTest=<testId>`。
4. 完成：调用 `POST /v1/developer/tests/:id/authorization/complete`，带上新的
   `commandKey`。接口返回 `202` 执行回执。回复丢失时复用同一键重试。SDK 的
   `DeveloperTests.completeAuthorization`
   会保留此键。等待执行结束后读取测试，再重新运行。

交换会保留发起登录的调用者作为权限限制。复用已保存结果前，会检查此调用者和提交完成命令的调用者。授权码和令牌只进入加密记录。请求断开不会停止已提交的交换。结果不明时，交换会通过执行接口等待决定，不会自行重发授权码。无法安装的授权会交给平台清理。

完成后，请调用 `POST /v1/developer/tests/:id/cleanup`，并提交
`commandKey`。`cancel` 接口使用相同请求体。两者都返回 `202` 和执行回执。
`DELETE /v1/developer/tests/:id?commandKey=...`
也返回回执。重试请求时保留同一个键。SDK 提供 `DeveloperTests.cleanup`、`cancel`
和 `remove` 方法。

测试的 `cleanupExecutionId`
指向负责到期和清理的服务执行。通过统一执行接口观察它。只要测试工作或令牌回收仍在进行，测试就保持
`Cancelling`。如果授权交换结果不明，必须先通过交换执行提交决定，清理才能结束。随后，OpenBot 会在提供方允许时撤销测试登录，并在同一事务中删除私有数据和标记清理完成。删除命令也在该事务中删除测试。关闭观察不会停止清理。

清理会先把所有已保存的令牌交给加密的任务记录，再移除本地登录。共享授权清理负责远端调用和重试。任务结束前，测试私有数据会保留。只有提供方确认撤销后，`cleanupRemote`
才是 `Complete`。提供方不支持撤销时，该值为 `LocalOnly`。

同一服务持有保存的到期计时器，并每分钟检查一次测试是否仍有 App 访问权。权限被移除后，服务仍可清理。服务器重启不会重置测试或授权流程。

---

OAuth 测试会保留授权被拒绝的原因，例如 `FlowExpired` 或
`CallbackMismatch`。连接不可用时，原因是
`ConnectionUnavailable`。测试记录不存在时，返回
`404 DeveloperNotFound`。网络或存储故障返回 `503 DeveloperUnavailable`。

## 请求收录

你不必等用户来连接你的 App。可以让 OpenBot 检查它：

```sh
curl -X POST https://api.example.com/v1/developer/indexing \
  -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "cardUrl": "https://apps.example.com/mcp/server-card", "commandKey": "index-check-1" }'
```

OpenBot 先检查你当前的权限和 App 限制，再接受命令。被限制的 App 返回 403
`DeveloperRestricted`。公开检查在后台运行，并保存结果。

丢失响应后重试时保留 `commandKey`。同一个键返回同一个请求。每个请求都有
`executionId`，可通过 `/v1/executions/:executionId`
查询或观察。通过执行取消接口取消请求。取消自己的请求不会停止共享的公开检查。

请求的 `status` 表示共享检查状态：`Waiting`、`Verifying`，然后是 `Completed`。
`check` 保存结果。执行记录表示你的请求状态，包括取消和失败。用
`GET /v1/developer/indexing` 列出请求，或用 `GET /v1/developer/indexing/:id`
读取一个请求。后续检查和服务器重启都不会改变已完成请求的结果。

## 通知

OpenBot 大约每小时检查一次你管理的 App。有变化时，它会给你发送通知。

App 和证明的定期检查使用共同执行器。下次检查时间和每次结果保存在 PostgreSQL 中。新实例会从这些记录继续。证明状态和访问通知在同一事务中提交。旧检查不能覆盖较新的证明状态。重放已保存的 App 检查不会重复发送同一问题通知。

| 类型            | 何时                                       |
| --------------- | ------------------------------------------ |
| `IssueAppeared` | 出现了一个新的阻塞问题。                   |
| `IssueResolved` | 一个阻塞问题消失了。                       |
| `AccessChanged` | 某份证明的状态变了，或者你失去了成员权限。 |

用 `GET /v1/developer/notifications` 读取通知。用 `before` 读取更早的页面。用
`POST /v1/developer/notifications/:id/read` 把一条通知标记为已读。

问题通知对每个 App 默认打开。要为某个 App 关闭它们，请发送
`PUT /v1/developer/subscriptions`，带上
`{ "cardUrl": "...", "enabled": false }`。用 `GET /v1/developer/subscriptions`
列出你的设置。

在 [API 参考](/docs/api/operations/tags/developer-tools/)中查看完整的结构。

数据迁移保留现有声明、证明、成员、邀请、App、报告和通知设置。App 与证明检查保留保存的下次检查时间。已放弃的证明不会启动新检查。旧索引请求保留原有 ID，并关联历史执行。已保存结果的请求保持完成；没有保存结果的请求标记为中断，因为原始调用人未被保存。平台仍可完成独立的公开检查。
