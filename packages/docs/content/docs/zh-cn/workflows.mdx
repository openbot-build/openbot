title: Workflows
description: 由 Agents 规划和运行的节点图，包含精确的工具调用、目标、检查和计划。
---

**Workflow**（工作流）是一个由节点组成的图。图是一组节点，以及节点之间的连接。每个节点都说明，在它开始之前，哪些其他节点必须先结束。互不等待的节点会同时运行。
有些节点是精确的：它们用固定的参数调用一个工具，或者比较两个值。其他节点把一个目标、一个问题或一个规划任务交给 Agent。一个 Workflow 可以把这些节点混合在一起。
Workflow 的每次启动都是一个 **Run**（运行）。Run 在后台进行。服务器重启后它会继续运行，它也可以等待很长时间，例如等待一个人批准某次工具调用。

规划也是这样工作的。Agent 做计划时，不会把计划写成文本。它写的是一个 Workflow 图。OpenBot 把这个计划保存为该 Agent 的一个 Workflow，并运行它。所以计划是可见的，它可以运行，而且一个成功过的计划之后可以在没有模型的情况下再次运行。目标、计划和探索都是图中的节点。

## 创建 Workflow

`POST /v1/workflows` 创建一个 Workflow：

```json
{
	"name": "Paint the door",
	"graph": {
		"nodes": [
			{
				"_tag": "Call",
				"id": "set-mode",
				"tool": "SetValue",
				"arguments": { "key": "mode", "value": "{{input.mode}}" }
			},
			{
				"_tag": "Task",
				"id": "paint",
				"needs": ["set-mode"],
				"goal": "set color to blue"
			},
			{
				"_tag": "Task",
				"id": "size",
				"needs": ["set-mode"],
				"goal": "set size to big",
				"check": "size is big"
			},
			{
				"_tag": "Check",
				"id": "painted",
				"needs": ["paint"],
				"condition": "color is blue",
				"output": { "type": "string" }
			},
			{
				"_tag": "Expect",
				"id": "done",
				"needs": ["painted", "size"],
				"value": "{{nodes.painted.output}}",
				"operator": "equals",
				"expected": "blue"
			}
		]
	}
}
```

这里 `paint` 和 `size` 都需要 `set-mode`，所以它们在 `set-mode` 之后同时开始。`done` 会等待这两个分支。

| 字段          | 含义                                                                                                                                                       |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`        | 一个简短的名字。长度为 1 到 100 个字符。                                                                                                                   |
| `description` | 可选。给人看的文本。                                                                                                                                       |
| `agent`       | 可选。执行节点的 [Agent](/zh-cn/docs/agents)。不填时，由 Run 所服务的成员的 Main Agent 执行节点。你需要在 Workflow 的每个 Agent 上拥有 `agents.delegate`。 |
| `judge`       | 可选。用于检查的 [模型](/zh-cn/docs/models)。不填时，使用 Agent 的模型。                                                                                   |
| `graph`       | 节点。每个节点都有一个在 Workflow 中唯一的 `id`。`id` 以小写字母开头，只包含小写字母、数字、`-` 和 `_`。                                                   |
| `schedule`    | 可选。在固定的时间启动 Run。见 [计划时间](#计划时间)。                                                                                                     |
| `shared`      | 可选。`true` 会创建一个组织共享的 Workflow。                                                                                                               |
| `owner`       | 可选。拥有这个 Workflow 的 Agent 的 ID。这个 Agent 总是可以用它的工具运行这个 Workflow。它不能和 `shared` 一起使用。                                       |

保存时，OpenBot 会检查这个图。两个节点不能有相同的 `id`。每个 `needs` 都必须指向图中的一个节点。这些依赖不能形成环。

`GET /v1/workflows` 列出你可以读取的 Workflows。规划出来的 Workflows 不在这个列表中。加上 `planned=true` 可以只列出规划出来的 Workflows。`PATCH /v1/workflows/:workflowId` 修改一个 Workflow。它需要 `expected`，也就是当前的 `revision`。每次修改都会产生一个新的 revision，OpenBot 会保留每一个 revision。要归档一个 Workflow，请发送 `"archived": true`。

## 节点

| `_tag`     | 字段                                    | 会发生什么                                                                                                | 模型   |
| ---------- | --------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------ |
| `Call`     | `tool`、`arguments`                     | OpenBot 用这些参数调用一次工具。工具的结果就是这个节点的输出。                                            | 否     |
| `Expect`   | `value`、`operator`、`expected`         | OpenBot 比较两段文本。`operator` 是 `equals`、`contains`、`matches`（正则表达式）或 `not_empty`。         | 否     |
| `Task`     | `goal`、`agent`、`check`                | Agent 用它的工具达成目标，然后调用 `openbot_node_result`。有 `check` 时，Agent 接着检查这个条件是否为真。 | 会记录 |
| `Check`    | `condition`、`agent`、`output`、`until` | Agent 用它的工具查看，但不做任何修改。它调用 `openbot_check`，并给出 `passed` 和证据。见 [检查](#检查)。  | 是     |
| `Plan`     | `goal`、`agent`                         | Agent 把计划写成一个 Workflow 图。OpenBot 保存它，并把它作为子 Run 运行。见 [计划和目标](#计划和目标)。   | 会记录 |
| `Goal`     | `goal`、`check`、`agent`、`budget`      | 和 `Plan` 一样，但在子 Run 结束后，Agent 会检查结果。检查失败时，Agent 会重新规划，直到检查通过。         | 会记录 |
| `Workflow` | `workflow`、`input`                     | OpenBot 把另一个 Workflow 作为子 Run 运行。Run 所属的成员需要在那个 Workflow 上拥有 `workflows.run`。     | 否     |
| `Wait`     | `seconds`                               | OpenBot 等待。                                                                                            | 否     |

带有 `agent` 的节点会使用那个 Agent，而不是 Workflow 的 Agent。Agents 在 `kind: "workflow"` 的 [Sessions](/zh-cn/docs/sessions) 中工作。一个节点会使用它的 Agent 在这个 Run 中的一个空闲 Session，所以先后运行的节点会共享它们学到的东西。同时运行的节点会得到各自的 Session。

需要批准的工具，例如 App 工具，在节点中的工作方式和在其他地方一样。这个节点会等待，直到 [request](/zh-cn/docs/requests) 得到回答。其他分支会继续运行。

在每个 Agent 节点中，Agent 都可以用 `openbot_report_finding` 报告一个问题：包括 `severity`（`low`、`medium`、`high` 或 `critical`）、`title`、它 `expected`（预期）的结果、它 `observed`（观察到）的结果，以及 `reproduction`（复现）步骤。这些发现是 Run 的一部分。要做探索，可以给一个 `Task` 或 `Plan` 节点一个目标，例如“在注册流程中寻找问题”。

### 节点之间如何依赖

每个节点都有这些可选字段：

| 字段       | 含义                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------- |
| `needs`    | 必须先结束的节点的 id。没有 `needs` 的节点在 Run 开始时启动。                             |
| `when`     | 一个类似 `Expect` 节点的条件：`value`、`operator`、`expected`。条件为假时，跳过这个节点。 |
| `onFail`   | `fail`（默认）、`continue` 或 `replan`。见下文。                                          |
| `attempts` | 节点在失败之前最多可以运行几次。默认是 1。对于 `Goal` 节点，它是规划的轮数。              |

当一个节点失败时，`onFail` 决定接下来发生什么：

- `fail`：不再启动新的节点。已经在运行的节点会运行完。其他所有节点都是 `skipped`，然后 Run 失败。
- `continue`：它后面的节点照样运行。这次失败不会让 Run 失败。
- `replan`：Run 失败，然后创建这个 Workflow 的 `Plan` 或 `Goal` 节点会重新规划。见 [计划和目标](#计划和目标)。

因为 `when` 为假而被跳过的节点，不会阻止它后面的节点。因为前面的节点失败而被跳过的节点也是 `skipped`，它后面的节点也一样。

### 检查

`Check` 节点从不修改任何东西。

- 有 `output`（一个 JSON Schema）时，Agent 还会把它找到的值作为 `value` 给出。这个值必须符合这个 schema。它就是节点的输出，例如 `{{nodes.painted.output}}`。
- 有 `until`（`{ "timeoutSeconds": 600, "intervalSeconds": 10 }`）时，Agent 会一次又一次地检查，每次之间暂停一会儿，直到条件为真或者时间用完。

### 模板

文本字段和 `Call` 的 `arguments` 可以使用 Run 中的值：

| 模板                  | 值                                                                           |
| --------------------- | ---------------------------------------------------------------------------- |
| `{{input.name}}`      | Run 输入中的一个字段。                                                       |
| `{{nodes.id.output}}` | 前面某个节点的输出。你可以继续深入，例如 `{{nodes.set-mode.output.value}}`。 |

只包含一个模板的文本，例如 `"{{input.count}}"`，会保留值的类型。所以数字仍然是数字。没有值的模板会让节点失败。

## 计划和目标

`Plan` 节点把一个目标交给 Agent，并要求它做一个计划。Agent 必须用一个 Workflow 图调用 `openbot_plan`：图中的节点和本页介绍的相同。文本不算计划。然后 OpenBot：

1. 把这个图保存为一个归该 Agent 所有的 Workflow。它的 `origin` 是 `{ "_tag": "Plan", "workflow", "run", "node" }`。
2. 把它作为这个节点的子 Run 运行。子 Run 有 `trigger: "plan"` 和 `parent: { "run", "node" }`。
3. 子 Run 结束时，结束这个节点。子 Run 通过时，这个节点也通过。

计划中也可以有自己的 `Plan` 和 `Goal` 节点，用于需要进一步规划的部分。所以 Agents 可以把大的工作拆成更小的计划，拆到工作需要的深度为止。

当子 Run 中的某个节点以 `onFail: replan` 失败时，Agent 会重新规划。它会读取上一个计划失败的原因。新的计划是同一个 Workflow 的一个新 revision。已经通过且没有变化的节点会保留它们的结果，所以不会再次运行。

`Goal` 节点是一个会检查自己结果的 `Plan` 节点。每个子 Run 结束后，Agent 会检查 `check` 条件。当条件为假，或者子 Run 失败时，Agent 会根据学到的东西重新规划。节点结果中的 `round` 记录规划的轮数。有 `attempts` 时，Goal 在达到这个轮数后停止。

`budget`，例如 `{ "tokens": 20000 }`，是一个 Goal（连同它的子 Runs）可以使用的模型 token 数量。它不是硬性限制。当 Goal 用完预算、又必须重新规划时，它会请求继续。这项能力是 `workflows.budget`，目标是 Workflow ID，它会像每个 [request](/zh-cn/docs/requests) 一样沿着所有者链向上传递。决策者同意时，Goal 会再得到一份预算。决策者拒绝时，Goal 失败。

### 再次运行的计划

通过的计划可以在没有模型的情况下再次运行。当一个规划出来的 Workflow 的 Run 通过时，OpenBot 把它的 revision 保存为 `passedRevision`。在之后的 Run 中，有 `passedRevision` 的 `Plan` 或 `Goal` 节点会立即运行那个 revision。它的 `mode` 是 `replayed`。它的 `Task` 节点也会重放记录下来的工具调用。使用 `cache: "off"` 时，Agent 总是现场规划。

## 记录和重放

现场运行 `Task` 节点会消耗模型调用。所以 OpenBot 会记录通过的 `Task` 节点的工具调用，但只在某个检查确认它们之后才记录。一个检查会确认它前面的节点：它 `needs` 中的节点、那些节点需要的节点，依此类推。`Check`、`Expect`，或者 `Task` 自己的 `check` 都可以做确认。检查说明这些调用产生了正确的效果。

下一个 Run 会一个接一个地重放记录下来的调用，不使用模型。如果某个调用不起作用，例如因为某些东西变了，OpenBot 会把目标交给 Agent。它会告诉 Agent 哪些调用已经运行过了。Agent 从当前状态继续。新的调用会替换旧的记录。

一份记录对应节点的 `id`、填入模板之后的目标，以及 Agent。其中任何一项变化，都会开始一份新的记录。`Check` 节点总是现场运行。

启动请求中的 `cache` 说明一个 Run 如何使用记录和已通过的计划：

| `cache` | 重放 | 记录 |
| ------- | ---- | ---- |
| `use`   | 是   | 是   |
| `read`  | 是   | 否   |
| `off`   | 否   | 否   |

在 CI 中使用 `read`，这样 CI 永远不会修改记录。`GET /v1/workflows/:workflowId/recordings` 列出记录，在同一路径上用 `DELETE` 可以删除它们。子 Run 使用其父 Run 的 `cache`。

## 启动 Run

`POST /v1/workflows/:workflowId/runs` 启动一个 Run，并返回 `202` 和这个 Run。你需要在这个 Workflow 上拥有 `workflows.run`。

```json
{ "input": { "mode": "fast" }, "cache": "use" }
```

`GET /v1/workflow-runs/:runId` 读取一个 Run：

| 字段       | 含义                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `status`   | `queued`、`running`、`passed`、`failed` 或 `cancelled`。                                                                      |
| `trigger`  | `manual`、`schedule`、`webhook`、`agent`、`plan` 或 `workflow`。                                                              |
| `revision` | 这个 Run 使用的 Workflow revision。                                                                                           |
| `nodes`    | 每个节点一个结果，包含 `needs`、`status`、`mode`、`attempts`、`round`、`turns`、`output`、`message`、`tokens` 和 `children`。 |
| `summary`  | 按状态和按模式统计的节点数量。                                                                                                |
| `usage`    | `tokens`：这个 Run（连同它的子 Runs）使用的模型 token。                                                                       |
| `parent`   | 启动这个 Run 的另一个 Run 中的节点，或者 `null`。                                                                             |
| `findings` | Agents 报告的问题。                                                                                                           |
| `sessions` | 这个 Run 的 Agents 工作所在的 Sessions。打开它们可以读取每个 Turn。                                                           |
| `error`    | 当 Run 因为节点失败以外的原因停止时，说明它为什么停止。                                                                       |

节点结果的 `mode` 是 `deterministic`（没有模型）、`live`（由 Agent 完成）、`replayed`（记录的工作再次运行）或 `handed_off`（重放不起作用，所以由 Agent 完成）。`children` 列出 `Plan`、`Goal` 或 `Workflow` 节点的子 Runs。

`GET /v1/workflow-runs` 列出你的 Runs，最新的排在前面。加上 `workflow=<id>` 或 `status=<status>` 可以筛选。`POST /v1/workflow-runs/:runId/cancel` 停止一个 Run、它启动的 Turns，以及它的子 Runs。

`POST /v1/workflow-runs/:runId/revise` 把一个正在进行的 Run 移到它的 Workflow 的另一个 revision。发送 `{ "revision": 3 }`，或者发送 `{}` 使用最新的 revision。没有变化的节点会保留它们的状态，即使它们正在运行。发生变化的运行中节点会停止，然后用新的定义重新开始。新的节点会加入这个 Run。

一个 Run 为一个成员工作。只有这个成员可以读取它。

## 触发方式

### 计划时间

```json
{ "schedule": { "cron": "0 9 * * 1-5", "timeZone": "Europe/Berlin" } }
```

`cron` 有五个字段：分钟、小时、月中的日期、月份和星期几。没有 `timeZone` 时，时区是 UTC。按计划启动的 Run 为 Workflow 的 **actor**（执行者）工作：也就是最后一个修改其计划时间或 webhook 的成员。Run 启动时，actor 必须仍然拥有 `workflows.run`。

### Webhooks

`PUT /v1/workflows/:workflowId/webhook` 生成一个新的 secret，并只返回一次：

```json
{
	"url": "https://openbot.example.com/v1/hooks/workflows/wfl_…",
	"secret": "owh_…"
}
```

另一个系统向这个 `url` 发送 `POST`，并带上 `Authorization: Bearer <secret>`，就可以启动一个 Run。JSON 请求体就是 Run 的输入。回答是 `202` 和 `{ "run": "run_…" }`。错误的 secret 会得到 `401`。新的 secret 会替换旧的。在同一路径上用 `DELETE` 可以删除这个 webhook。webhook 启动的 Run 也为 actor 工作。

### Agents

每个 Agent 都有这些工具：

| 工具                     | 作用                                                                 |
| ------------------------ | -------------------------------------------------------------------- |
| `openbot_list_workflows` | 列出它可以运行的 Workflows。                                         |
| `openbot_run_workflow`   | 启动一个 Run。Run 在后台进行。它的结果会作为一条新消息进入 Session。 |
| `openbot_plan`           | 把工作规划为一个 Workflow 图。见下文。                               |
| `openbot_get_run`        | 读取成员的一个 Run：它的状态和每个节点的结果。                       |

当普通 Session 中的 Agent 需要一个计划时，它用一个 `name` 和图的 `nodes` 调用 `openbot_plan`。OpenBot 把这个计划保存为该 Agent 的一个 Workflow，带有 `origin: { "_tag": "Session", "session" }`，并立即启动一个 Run。结果会作为一条新消息进入 Session。要修改计划，Agent 带上 `workflow` id 再次调用 `openbot_plan`。这会产生一个新的 revision。如果这个 Workflow 有正在进行的 Run，它会移到新的 revision。否则会启动一个新的 Run，已经通过且没有变化的节点会保留它们的结果。

要给 Agent 一个让 OpenBot 持续推进的目标，Agent 会规划一个带有 `Goal` 节点的图。这个 Goal 会规划、运行和检查，直到它的条件为真。

Agent 第一次运行某个 Workflow 时，它上面的决策者必须同意。这项能力是 `workflows.run`，目标是 Workflow ID。见 [Requests](/zh-cn/docs/requests)。Agent 总是可以运行它拥有的 Workflows，以及它自己的计划。使用其他 Agents 的计划需要在这些 Agents 上拥有 `agents.delegate`。为 Agent 不拥有的 Workflow 制定新计划，需要 `workflows.edit` 和 `workflows.run`。

在 workflow Session 中，Agent 还有用来回答节点的工具：`openbot_node_result`、`openbot_check`、`openbot_report_finding`，以及用于 `Plan` 和 `Goal` 节点的 `openbot_plan`。

## 权限

| 权限              | 允许你                                                     |
| ----------------- | ---------------------------------------------------------- |
| `workflows.read`  | 读取 Workflows，以及它们的 Runs、报告和记录。              |
| `workflows.write` | 创建和修改 Workflows，以及它们的计划时间、webhook 和记录。 |
| `workflows.run`   | 从客户端或 Agent 启动、修订和取消 Runs。                   |

Agents 的能力对应到这些权限：`workflows.run` 和 `workflows.budget` 需要 `workflows.run`，`workflows.edit` 需要 `workflows.write`。

你自己的 Workflows 位于 `openbot.org.<org>.user.<user>.workflow` 之下。共享的 Workflows 位于 `openbot.org.<org>.workflow` 之下。成员可以读取和运行共享的 Workflows。管理员还可以修改它们。见 [权限](/zh-cn/docs/permissions)。

## 错误

| 状态码 | 错误                         | 何时出现                                                       |
| ------ | ---------------------------- | -------------------------------------------------------------- |
| `400`  | `WorkflowInvalid`            | 图、计划时间或某个 Agent 无效，或者 Run 已经结束。             |
| `401`  | `WorkflowHookDenied`         | webhook secret 错误，或者这个 Workflow 没有 webhook。          |
| `403`  | `PermissionDenied`           | 你可以读取这个 Workflow，但不能修改或运行它。                  |
| `404`  | `WorkflowNotFound`           | 没有你可以读取的、使用这个 ID 的 Workflow 或 Run。             |
| `409`  | `WorkflowConflict`           | 在你读取之后，这个 Workflow 发生了变化。请重新读取，然后再试。 |
| `503`  | `WorkflowStorageUnavailable` | OpenBot 现在无法连接到它的数据库。                             |
