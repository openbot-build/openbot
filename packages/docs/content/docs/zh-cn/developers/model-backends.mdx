## 内置模型

当你从自己的程序中运行 OpenBot 时，可以用 `builtinModels`
选项在代码中提供模型。参见[从代码运行](/zh-cn/server)。

- 每个组织都可以使用它们。
- API 不能修改它们。
- 它们和保存的提供方一起显示在模型列表中。

`builtinModels` 有三个字段：

| 字段        | 是什么                                                           |
| ----------- | ---------------------------------------------------------------- |
| `providers` | 要显示的提供方，比如 `{ id, name }`。                            |
| `models`    | 要显示的模型，是 `Config.Model` 值。                             |
| `resolve`   | 一个函数，接收一个选择，返回一个带有 `LanguageModel` 的 Effect。 |

`builtinModels.defaultModel`
选项指定其中一个模型。当新 Chat 的 Bot 没有指定模型时，这个 Chat 会得到它。只有模拟的平台会设置它，例如开发环境或测试。在真实的平台上，每个 Bot 都指定自己的模型。

这个示例提供一个 Anthropic 模型，密钥来自你程序的环境：

```ts
import { NodeRuntime, NodeServices } from "@effect/platform-node"
import { Config, Model, Provider } from "@openbot-build/core"
import {
	AnthropicProvider,
	EnvironmentConfiguration,
	Server,
} from "@openbot-build/openbot"
import { Context, Effect, Layer, Redacted } from "effect"
import { LanguageModel } from "effect/ai"
import { FetchHttpClient } from "effect/http"

const selection = Config.Selection.make({
	provider: Provider.Id.make("house"),
	model: Model.Id.make("claude-sonnet-4-5"),
})

NodeRuntime.runMain(
	Effect.scoped(
		Effect.gen(function* () {
			const settings = yield* EnvironmentConfiguration.load
			// 只构建一次模型。它和程序存在的时间一样长。
			const layer = Layer.unwrap(
				AnthropicProvider.make({ max_tokens: 4096 }).model(selection),
			).pipe(
				Layer.provide(
					AnthropicProvider.layerClient({
						apiKey: Redacted.make(process.env.ANTHROPIC_API_KEY ?? ""),
					}),
				),
				Layer.provide(FetchHttpClient.layer),
			)
			const claude = Context.get(
				yield* Layer.build(layer),
				LanguageModel.LanguageModel,
			)
			const builtinModels = {
				providers: [{ id: selection.provider, name: "House models" }],
				models: [
					Config.Model.make({
						provider: selection.provider,
						id: selection.model,
						name: "Claude Sonnet 4.5",
						reasoningEfforts: [],
						serviceTiers: [],
					}),
				],
				resolve: (requested: Config.Selection) =>
					requested.model === selection.model
						? Effect.succeed(claude)
						: Effect.fail(
								new Config.ModelConfigurationError({
									reason: "model-not-found",
									message: "This model is not available",
								}),
							),
			}
			return yield* Layer.launch(
				Server.layerLive({ ...settings, builtinModels }).pipe(
					Layer.provide(Layer.merge(NodeServices.layer, FetchHttpClient.layer)),
				),
			)
		}),
	),
)
```

当 `resolve` 失败时，启动 Turn 会返回 `503`。开发入口用 `builtinModels`
提供它的测试模型。完整示例参见 `packages/openbot/src/app/DevelopmentModel.ts`。

### 提供方模块

提供方模块为某一种 API 把模型名称变成一个
`LanguageModel`。`@openbot-build/openbot`
导出了三个这样的模块。每个模块都有同样的部分：

| 部分                        | 作用                                                           |
| --------------------------- | -------------------------------------------------------------- |
| `make(defaults?)`           | 创建一个提供方。`defaults` 是每次调用都使用的请求选项。        |
| `provider.model(selection)` | 返回一个选择对应的模型 Layer。它不发送任何请求。               |
| `layerClient(options)`      | 创建 HTTP 客户端。传入 `apiKey`；要用其他地址时传入 `apiUrl`。 |
| `layer(tag, defaults?)`     | 把提供方放进一个由你命名的服务中。                             |

| 模块                   | 提供方 ID       | API                                                                              |
| ---------------------- | --------------- | -------------------------------------------------------------------------------- |
| `OpenAiProvider`       | `openai`        | OpenAI Responses API。`ResponsesCompaction` 为你自己的程序增加原生的上下文压缩。 |
| `OpenAiCompatProvider` | `openai-compat` | OpenAI Chat Completions API，以及仿照它的服务。                                  |
| `AnthropicProvider`    | `anthropic`     | Anthropic Messages API。                                                         |

OpenBot 对保存的提供方也使用这些模块。上下文压缩（context
compaction）会把很长的历史变短，让它能放进模型的上下文窗口。OpenBot 会为每个 Chat 做这件事：由这个 Chat 的模型写一段摘要。它默认不使用
`ResponsesCompaction`。见
[压缩](/zh-cn/developers/chats#压缩)。每个提供方的简短示例参见
[Packages](/zh-cn/packages)。

---

使用 Cloudflare Workers AI 时，请选择 `openai-compat` 提供方，并设置账户地址
`https://api.cloudflare.com/client/v4/accounts/<account-id>/ai/v1`。Workers
AI 不接受工具调用助手消息中的 `null`
文本。OpenBot 将这条消息的文本设为空字符串，让下一次模型调用能够读取工具结果。此处理仅用于这个 Cloudflare 地址。其他提供方的消息保持原样。

### 模型回复中断后重试

对于已保存的 `openai-compat` 提供方，可以在传给 `Server.layerLive` 的选项中设置
`modelReadRetryRoutes`。列表默认为空。每一项指定一个已保存的提供方 ID、完整的 Chat
Completions URL，以及**实际发给该地址的模型名称**。例如：

```ts
Server.layerLive({
	...settings,
	modelReadRetryRoutes: [
		{
			providerId: provider.id,
			completionUrl: "https://model.example/v1/chat/completions",
			model: "text-small",
		},
	],
})
```

请填写最终地址：符合重试条件的请求不会跟随重定向。只为不会自行执行操作的提供方启用重试。如果网关返回 HTTP
504 或回复流中断，普通 Chat 可以再尝试同一个模型步骤一次。OpenBot 复用已保存的工具结果。如果请求允许提供方执行工具、含有无法识别的选项，或自定义了 HTTP 客户端转换，就不会重试。每次尝试都要检查权限和预算；两次请求都可能已经消耗模型用量。

只有遇到这次故障的服务器可以补发。如果它停止，接手的服务器不会再次发送这个请求。其他未完成的步骤仍按[原有规则](/zh-cn/developers/chats#服务器停止时)恢复。

读取[执行事件](/zh-cn/developers/chats)的客户端应在原处显示新尝试的回复，替换上一次留下的部分文本。旧文本仍保留在事件历史中，可用尝试编号区分。

## 开发用模型

开发服务器（`devenv shell -- pnpm dev`）不会调用真实的模型。它改用测试模型。它们每次都给出同样的回答，所以你可以零成本地测试客户端。

提供方 ID 是 `development`。模型 ID 有：

| 模型           | 作用                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| `mock-text`    | 默认模型。立刻返回固定的文本。                                              |
| `mock-slow`    | 在十秒内慢慢返回文本。用它测试流式输出和中断。                              |
| `mock-tool`    | 调用一个需要决定的无害测试工具。见 [Requests](/zh-cn/developers/requests)。 |
| `mock-app`     | 调用测试 App 的一个工具，并返回它的真实内容。                               |
| `mock-failure` | 先发送一些文本，然后故意以模型错误失败。                                    |

它们回答中的 token 数不是真实的。要选择其中一个，请把它保存到 Chat 上：

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" -H 'Content-Type: application/json' \
  -d '{"expected":1,"model":{"_tag":"Config.Selection","provider":"development","model":"mock-slow"}}' \
  http://localhost/v1/chats/$CHAT_ID
```

开发入口通过 `builtinModels`
提供这些模型，所以开发平台的每个组织都可以使用它们。它把 `mock-text` 作为
`builtinModels.defaultModel`，所以当新 Chat 的 Bot 没有指定模型时，这个 Chat 会得到它。生产程序永远不会使用它们。
