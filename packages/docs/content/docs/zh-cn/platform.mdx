邀请制升级默认值、邮箱登录、审批、组角色及管理员恢复请参阅[账号准入](/zh-cn/access)。

面向平台运维人员。这些任务会影响整个部署。请按任务要求准备服务器访问权限或平台管理权限。从[管理员手册](/zh-cn/admin)开始。

Platform（平台）就是整个 OpenBot 部署。一个平台有许多组织。平台管理员负责运行平台。本页介绍如何设置平台，以及如何用
`/v1/platform` 管理它。

## 平台管理员

平台管理员管理平台。平台管理员**不是**每个组织的成员。除非他也是某个组织的成员，否则他不能读取这个组织的 Chat、Bot 或成员。他只能通过
`/v1/platform` 管理平台。

平台管理员是一个电子邮件地址。当有人第一次用这个邮箱登录、并且提供方已验证该邮箱时，这个条目会关联到那个账号。

| 路由                                | 作用                                       |
| ----------------------------------- | ------------------------------------------ |
| `GET /v1/platform/admins`           | 列出平台管理员。                           |
| `POST /v1/platform/admins`          | 添加一个平台管理员。请求体是 `{ email }`。 |
| `DELETE /v1/platform/admins/:email` | 移除一个平台管理员。                       |

```sh
curl -b cookies.txt \
  -H "Origin: https://api.example.com" \
  -H "Content-Type: application/json" \
  -d '{"email":"bob@example.com"}' \
  https://api.example.com/v1/platform/admins
```

```json
{
	"email": "bob@example.com",
	"userId": null,
	"addedAt": "2026-10-21T09:00:00.000Z"
}
```

在 Bob 第一次登录之前，`userId` 为
`null`。平台必须至少保留一个管理员。移除最后一个管理员会返回 `409` 和
`LastPlatformAdmin`。

## 设置

新数据库中没有平台设置。在你运行设置程序之前，除 `/health`
之外的每个路由都会返回 `503` 和 `SetupRequired`。

设置程序用 `OPENBOT_DATABASE_URL` 和 `OPENBOT_SECRET_KEYS`
连接数据库。它会写入第一份平台设置和第一批平台管理员。在镜像中，它是
`/app/dist/app/Setup.mjs`。从源代码运行时，使用
`pnpm --filter @openbot-build/openbot setup`。这个包还提供命令 `openbot-setup`。

```sh
docker run --rm --env-file openbot.env openbot:$OPENBOT_RELEASE \
  /app/dist/app/Setup.mjs \
  --public-origin=https://api.example.com \
  --oidc-issuer=https://id.example.com \
  --oidc-client-id=openbot \
  --admin-email=alice@example.com
```

| 参数                   | 必需           | 作用                                                                              |
| ---------------------- | -------------- | --------------------------------------------------------------------------------- |
| `--public-origin`      | 是             | OpenBot 的公开 HTTPS 源，比如 `https://api.example.com`。不带路径，结尾不带斜杠。 |
| `--oidc-issuer`        | 与 ID 一起     | 平台 OpenID Connect 提供方的 HTTPS 地址，结尾不带斜杠。                           |
| `--oidc-client-id`     | 与 issuer 一起 | 在该提供方那里的客户端 ID。                                                       |
| `--oidc-client-secret` | 否             | 客户端密钥。对于使用 PKCE 的公开客户端，不填。                                    |
| `--admin-email`        | 至少一个       | 拥有这个已验证邮箱的人登录后会成为平台管理员。要添加更多人，就重复这个参数。      |
| `--force`              | 否             | 即使设置已存在也写入。只在恢复时使用，也就是没有任何平台管理员能登录的时候。      |

`--oidc-issuer` 和 `--oidc-client-id`
要么一起设置，要么都不设置。当大家只通过各组织的
[SSO 连接](/zh-cn/sso)登录时，两者都不设置。

命令行可能会出现在进程列表中。所以，你可以改用环境变量
`OPENBOT_SETUP_OIDC_CLIENT_SECRET` 提供客户端密钥，而不是
`--oidc-client-secret`。这是更好的做法。

`--admin-provider` 指定验证管理员邮箱的提供方，默认是
`oidc`。恢复时，若相应登录方式已配置，可使用 `email` 或 SSO 连接 ID。

S3、SMTP 和注册规则在初始化后通过 `PATCH /v1/platform/settings`
设置。这些是数据库中的共享配置，不作为初始化或服务器启动参数。

设置程序还会生成一个随机的登录密钥。Better
Auth 用它来签名登录 cookie。OpenBot 加密保存它，你永远看不到它。

### 再次运行设置

- 使用同样的源和提供方时，设置程序什么也不改。它只会添加管理员邮箱。
- 使用其他值时，设置程序会失败。它会告诉你改用 `PATCH /v1/platform/settings`。
- 使用 `--force`
  时，设置程序会写入新的值。它会保留当前的登录密钥，所以不会因此让任何人退出登录。

## 平台设置

`GET /v1/platform/settings` 读取设置。`PATCH /v1/platform/settings` 修改设置。

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  https://api.example.com/v1/platform/settings
```

```json
{
	"version": 3,
	"publicOrigin": "https://api.example.com",
	"identityProvider": {
		"issuer": "https://id.example.com",
		"clientId": "openbot",
		"clientSecret": {
			"set": true,
			"hint": "…k9Qz"
		}
	},
	"organizationCreation": "platform_admins",
	"ceiling": "{\"_tag\":\"Rules\",\"algorithm\":\"denyOverrides\",\"rules\":[]}",
	"appRestrictions": [],
	"codeMode": {
		"enabled": false,
		"timeoutMs": 30000,
		"memoryMb": 64,
		"outputBytes": 65536
	},
	"rateLimit": {
		"requestsPerMinute": null
	},
	"tokenRate": {
		"organization": null,
		"member": null,
		"bot": null,
		"token": null
	},
	"files": {
		"storage": null,
		"uploads": {
			"server": true,
			"direct": true
		},
		"maxBytes": 20971520,
		"quotaBytes": null,
		"mediaTypes": [
			"image/png",
			"image/jpeg",
			"image/gif",
			"image/webp",
			"application/pdf",
			"text/plain"
		],
		"unusedMs": 86400000
	},
	"mail": null,
	"updatedAt": "2026-10-21T09:00:00.000Z"
}
```

| 字段                   | 是什么                                                                                               |
| ---------------------- | ---------------------------------------------------------------------------------------------------- |
| `version`              | 每次修改加一。                                                                                       |
| `publicOrigin`         | OpenBot 的公开 HTTPS 源。                                                                            |
| `identityProvider`     | 平台的 OpenID Connect 提供方；当大家只通过 SSO 连接登录时为 `null`。                                 |
| `organizationCreation` | 谁可以创建组织：`anyone` 或 `platform_admins`。参见[组织创建](#组织创建)。                           |
| `ceiling`              | 一个带拒绝规则、对每个组织生效的策略。参见[策略上限](#策略上限)。                                    |
| `appRestrictions`      | App Index 隐藏的 App。参见 [App Index](/zh-cn/developers/app-index#宿主限制)。                       |
| `codeMode`             | Bot 能否使用 Code Mode，以及它的限制。参见 [Code Mode](/zh-cn/developers/code-mode#打开-code-mode)。 |
| `rateLimit`            | 每个调用方在一分钟内最多可以发送多少个 API 请求。参见[速率限制](/zh-cn/usage#速率限制)。             |
| `tokenRate`            | 每个范围最高的 token 速率。组织只能设置更低的速率。参见 [token 速率](/zh-cn/usage#token-速率)。      |
| `files`                | [文件](/zh-cn/developers/files#设置存储)的对象存储和限制。                                           |
| `mail`                 | [发送邮件](#发送邮件)的 SMTP 设置。`null` 表示不发送邮件。                                           |
| `updatedAt`            | 设置最后一次修改的时间。                                                                             |

### 机密永远不会返回

机密可以写入，但永远不会读出。响应中显示的是 `{ set, hint }`：

- 当保存了机密时，`set` 为 `true`。
- `hint` 是 `…`
  加上最后 4 个字符，方便你区分不同的机密。对于短于 12 个字符的机密，它为
  `null`。
- SMTP 密码的 `hint` 总是 `null`，不会显示密码的任何字符。

### 修改设置

`PATCH` 的请求体需要 `expectedVersion`，也就是你读到的
`version`。只加入你想修改的字段。

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expectedVersion":3,"organizationCreation":"platform_admins"}' \
  https://api.example.com/v1/platform/settings
```

如果有人在你读取之后修改了设置，OpenBot 会返回 `409` 和
`SettingsConflict`，以及当前的 `version`。请重新读取设置，然后再试一次。

`PATCH` 中的 `identityProvider` 是这样工作的：

| 值                                         | 结果                               |
| ------------------------------------------ | ---------------------------------- |
| `null`                                     | 移除平台提供方。                   |
| `{ issuer, clientId }`                     | 设置提供方，并保留当前的密钥。     |
| `{ issuer, clientId, clientSecret: "…" }`  | 设置提供方和一个新的密钥。         |
| `{ issuer, clientId, clientSecret: null }` | 把提供方设置为公开的 PKCE 客户端。 |

每个实例都会立刻使用修改后的值。参见[配置](/zh-cn/configuration#修改如何到达每个实例)。

<Callout type="warn">
	新的 `publicOrigin` 会让所有人退出登录。它还会把登录重定向 URI 改为
	`<publicOrigin>/auth/callback/oidc`。请先在你的提供方那里添加新的重定向 URI，然后再修改源。
</Callout>

## 策略上限

`ceiling`
是一个在每个组织中都生效的策略。它只能有拒绝规则。来自上限的拒绝总是胜出，所以任何角色、任何令牌都不能做它拒绝的事。条件中可以使用调用者的
`organizationId`。参见[权限](/zh-cn/permissions#策略)。上限对平台 API 不生效，所以它永远不会把平台管理员锁在外面。

下面这个上限禁止每个组织添加自己的模型提供方：

```json
{
	"expectedVersion": 4,
	"ceiling": "{\"_tag\":\"Rules\",\"algorithm\":\"denyOverrides\",\"rules\":[{\"_tag\":\"Deny\",\"actions\":[\"write\"],\"resources\":[\"ModelProvider\"],\"reason\":\"The platform gives the model providers.\"}]}"
}
```

带有允许规则的上限会返回 `400`。请求中的上限最多可以有 100 条规则。

## 发送邮件

平台管理员可以设置 SMTP，也就是把邮件交给邮件服务器的协议。设置后，OpenBot 会发送[组织邀请](/zh-cn/organization#邀请)和
[Bot 邮箱邀请](/zh-cn/developers/sharing#邀请别人)。新平台和旧版本保存的设置都默认关闭邮件发送。Bot 邀请链接不会发送邮件。

把下面的请求体发给 `PATCH /v1/platform/settings`。`expectedVersion`
必须是你刚读到的版本。SMTP 密码会加密保存在数据库中，每个实例都会立即使用新设置。

```json
{
	"expectedVersion": 3,
	"mail": {
		"host": "smtp.example.com",
		"port": 587,
		"security": "starttls",
		"from": "openbot@example.com",
		"fromName": "OpenBot",
		"username": "openbot",
		"password": "replace-with-your-smtp-password",
		"invitationUrl": null
	}
}
```

| 字段            | 含义                                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------------------- |
| `host`          | SMTP 主机名或 IP 地址，不含协议、端口或路径。                                                                         |
| `port`          | SMTP 端口，范围是 1 到 65535。                                                                                        |
| `security`      | `tls` 从连接开始就使用 TLS，通常用于端口 465。`starttls` 要求先升级到 TLS，通常用于端口 587。两者都不会退回明文发送。 |
| `from`          | 发件人的邮箱。                                                                                                        |
| `fromName`      | 发件人的显示名称。                                                                                                    |
| `username`      | SMTP 登录名。不需要登录时设为 `null`，这也会清除已保存的密码。                                                        |
| `password`      | 只写入的 SMTP 密码。首次设置登录时必须提供。                                                                          |
| `invitationUrl` | 邮件按钮打开的地址。`null` 使用 `publicOrigin`。可设为客户端自己的邀请页 HTTPS 地址；本机开发地址也可以使用 HTTP。    |

修改 `mail` 时，除 `password` 外，每个字段都要提供。只有 `host`、`port`、
`security` 和 `username` 都未变时，才能省略 `password`
并保留原密码。这些值改变后，如果仍需要登录，就必须提供新密码。读取设置时，密码只返回
`{ "set": true, "hint": null }` 或 `{ "set": false, "hint": null }`。在 `PATCH`
中省略整个 `mail` 会保留现有设置；`"mail": null` 会关闭发送。

配置后，用测试邮件检查连接：

```sh
curl -X POST -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"to":"alice@example.com"}' \
  https://api.example.com/v1/platform/mail/test
```

此接口只供平台管理员使用，支持 API key 和同源 session cookie。响应是
`{ "status": "sent" }`、`{ "status": "disabled" }` 或
`{ "status": "failed" }`。`sent`
只表示 SMTP 服务器接受了邮件，不保证邮件已进入收件箱。 `disabled`
表示未启用发送。`failed`
表示无法确认发送成功，OpenBot 不会自动重试。如果服务器已接收邮件，但它的回复丢失，手动重发可能产生重复邮件。

邮件模板用 React
Email 构建，同时包含 HTML 和纯文本。它沿用 OpenBot 的灰阶配色、大圆角、胶囊按钮，以及 DM
Sans 和 DM
Mono 字体，并为不支持这些字体的邮件客户端提供回退字体。模板没有边框或阴影。按钮显示“Open
OpenBot”，只打开设置中的地址，不会直接接受邀请。使用自己的邀请页时，由客户端在登录后读取邀请并让用户接受或拒绝。

## 组织创建

`organizationCreation` 决定谁可以调用
`POST /v1/organizations`。账号登录时，OpenBot 不会为它创建组织。

| 值                | 结果                                                                  |
| ----------------- | --------------------------------------------------------------------- |
| `anyone`          | 任何登录的人都可以创建组织。                                          |
| `platform_admins` | 只有平台管理员可以创建组织。其他人通过邀请、已验证的域名或 SSO 加入。 |

账号加入组织的所有方式，参见[组织](/zh-cn/organization#谁可以加入)。

## 组织

`GET /v1/platform/organizations` 分页列出平台的所有组织。使用
`limit`（1 到 100），以及值为上一页 `next` 的 `after`。

`PATCH /v1/platform/organizations/:organizationId` 修改组织的 `status`：`active`
或 `suspended`。

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"status":"suspended"}' \
  https://api.example.com/v1/platform/organizations/org_8f3a
```

任何人都不能使用被暂停的组织。它的令牌会立刻失效。把 `status` 设为 `active`
即可撤销暂停。

`GET /v1/platform/organizations/:organizationId/credits`
读取一个组织的额度。对同一路由使用 `PATCH`
可以打开或关闭额度，`POST .../credits/grants`
给出额度。参见[额度](/zh-cn/usage#额度)。

## 共享的模型提供方

平台可以为模型提供方付费，并把它们共享给各个组织。它也可以共享模型。组织也可以使用自己的密钥。参见
[Model](/zh-cn/models)。

| 路由                                                  | 作用                                                        |
| ----------------------------------------------------- | ----------------------------------------------------------- |
| `GET /v1/platform/models`                             | 列出共享的模型。                                            |
| `POST /v1/platform/models`                            | 添加一个共享的模型。                                        |
| `GET /v1/platform/models/:modelId`                    | 读取一个共享的模型。                                        |
| `PATCH /v1/platform/models/:modelId`                  | 修改一个共享的模型。                                        |
| `DELETE /v1/platform/models/:modelId`                 | 移除一个共享的模型。                                        |
| `GET /v1/platform/model_providers`                    | 列出共享的提供方。                                          |
| `POST /v1/platform/model_providers`                   | 添加一个共享的提供方。                                      |
| `GET /v1/platform/model_providers/:providerId`        | 读取一个共享的提供方。                                      |
| `PATCH /v1/platform/model_providers/:providerId`      | 修改一个共享的提供方。                                      |
| `DELETE /v1/platform/model_providers/:providerId`     | 移除一个共享的提供方。                                      |
| `GET /v1/platform/model_providers/:providerId/prices` | 列出一个共享的提供方的价格。参见[价格](/zh-cn/usage#价格)。 |
| `PUT /v1/platform/model_providers/:providerId/prices` | 为一个共享的提供方中的一个模型设置新价格。                  |

请求体和组织的模型与提供方相同，只是多了
`availability`。先添加模型，再添加一个关联它的提供方：

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "id": "gpt-4.1", "name": "GPT-4.1", "reasoningEfforts": [], "serviceTiers": [], "availability": { "_tag": "All" } }' \
  https://api.example.com/v1/platform/models

curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{
    "kind": "openai",
    "name": "OpenAI",
    "apiKey": "sk-...",
    "models": [{ "model": "gpt-4.1", "modelOwner": "platform" }],
    "availability": { "_tag": "All" }
  }' \
  https://api.example.com/v1/platform/model_providers
```

| `availability`                                       | 谁可以使用这个模型或提供方 |
| ---------------------------------------------------- | -------------------------- |
| `{ "_tag": "All" }`                                  | 每个组织。                 |
| `{ "_tag": "None" }`                                 | 没有任何组织。             |
| `{ "_tag": "Selected", "organizations": ["org_…"] }` | 只有列出的组织。           |

只有当两者的 `availability`
都允许时，组织才能看到共享提供方的共享模型。组织也可以把一个它能使用的共享模型关联到自己的提供方。这时它用自己的密钥使用这个模型。

共享提供方只能关联共享模型。当某个共享提供方关联着一个共享模型时，你不能移除这个模型：OpenBot 会返回
`409` 和
`ModelInUse`。当你移除一个共享模型时，OpenBot 也会移除各组织的提供方与它之间的关联。

## 调用平台 API

`/v1/platform` 接受两种调用者：

- 平台管理员的 **session cookie**。
- 平台管理员的**用户令牌**。令牌自身的策略必须允许 `Platform` 上的 `read`（用于
  `GET`）或 `write`（用于其他所有方法）。

组织中的任何角色都不会授予 `Platform` 上的操作。没有指定 `policy`
创建的令牌永远得不到它们。所以，用于平台的令牌必须在创建时写明它们：

```sh
curl -b cookies.txt \
  -H "Origin: https://api.example.com" \
  -H "Content-Type: application/json" \
  -d '{"name":"Platform admin","expiresInDays":30,"policy":"{\"_tag\":\"Rules\",\"algorithm\":\"denyOverrides\",\"rules\":[{\"_tag\":\"Allow\",\"actions\":[\"read\",\"write\"],\"resources\":[\"Platform\"]}]}"}' \
  https://api.example.com/v1/user/tokens
```

只有在它的账号仍是平台管理员时，令牌才有效。其他调用者会得到 `403` 和
`Forbidden`。

OpenBot 把每次平台修改写入审计日志，组织 ID 为
`platform`。API 目前还不能读取这些条目。

在 [Platform 参考](/api/operations/tags/platform/)中查看完整的结构。

## 错误

| 状态  | 错误                    | 何时                                   |
| ----- | ----------------------- | -------------------------------------- |
| `400` | `SettingsInvalid`       | 修改中的某个值无效。                   |
| `403` | `Forbidden`             | 调用者不是平台管理员，或者令牌不允许。 |
| `404` | `OrganizationNotFound`  | 没有这个 ID 的组织。                   |
| `404` | `PlatformAdminNotFound` | 没有使用这个邮箱的平台管理员。         |
| `409` | `SettingsConflict`      | 有人在你读取之后修改了设置。           |
