本页将[执行设计](/zh-cn/docs/architecture)对应到源代码测试和发布检查。源码核对日期为 2026-10-28。这里列出的测试是**源码证据，不是测试通过记录**。每次发布检查应记录版本、命令、结果和日志。命令和测试服务的限制见
[端到端检查](/zh-cn/docs/developers/testing)。

## 如何阅读本表

本次改动记录的起点是 581 项测试。测试数量增加，不能证明旧行为全部保留。现在测试分布在各源码包和
`packages/e2e`
中。测试移动或删除时，应保留原断言、它的新位置，或已获准的行为变更说明。

`packages/e2e/scenarios.json`
详细记录用户任务的断言。它包含 22 个任务组，区分正常、边界和极端场景。空列表不表示已覆盖。本页补充统一执行和数据迁移检查。

表中使用以下路径前缀：

- `E/` 表示 `packages/e2e/test/`。
- `S/` 表示 `packages/openbot/test/`。
- 其他路径从项目根目录开始。

测试可能使用真实数据库和固定模型回复，也可能使用真实 HTTP 服务和测试工作流，或完整服务器。这些测试的范围不同。服务 Layer 重启不等于进程崩溃。同一进程中的两个服务对象也不等于两个服务器进程。

## 基线追踪

`packages/e2e/baseline.json` 为版本 `2a123ffae6f5aea2cfa02f36975efbacc83f1305`
的每个基线测试声明保留一行。它将 142 个文件中的 566 个声明与当前源码比较。记录中的 581 项是运行用例数；循环和参数化测试可以把一个声明展开成多个用例。两种数量不能混用。

源码快照中，371 个测试回调未变，另有 46 个测试保留全部直接断言的语法。59 个同名测试改变了断言，90 个测试需要对应到改名或替代用例。追踪表保留删除的断言文本、当前测试名称和核对说明。语法相同不证明共享测试环境未变，也不证明测试已经通过。后续修改代码后应重新核对此快照。

部分变化遵循已批准的设计：Turn 持有资源，命令返回执行回执，内部原因加密保存，权限列表过滤资源，审计写入失败时决策一起回滚。Computer 恢复是显式保存的动作。记忆不能在没有来源证据时扩大可见范围。等待决策锁时过期的请求不能授予权限。这些是已记录的变化，不代表旧行为完全相同。

`S/MemoryModels.test.ts`
检查预算耗尽时的回复、零模型发送、许可释放、加密原因，以及移除预算后成功调用。`S/TokenThrottle.test.ts`
检查 40 个不同片段拼接后的完整文本。`S/ToolCommands.test.ts`
保留委派的两个时间边界：提前唤醒后保留原截止时间；接管已超时工作时立即暂停，不再等待。

B463 对应 `S/ExecutionStore.test.ts`
中密文、JSON 和身份损坏的三项用例，检查存储错误、修复，以及真正缺失的记录。B202 对应
`E/chat/ExecutionResources.test.ts`：工具构建失败会关闭作用域、保存错误 ID，并允许下一个 Turn 成功。B241 对应
`E/chat/ChatRecovery.test.ts`：损坏的 Chat 不会阻止另一个 Chat 恢复或接收新输入。

App、Channel、Computer、Live、Code
Mode 和 Vault 的映射检查持久回执、清理子执行、安全错误分类及 ID，以及资源归属。
`additionalCurrentChecks` 单列新增的 Pairing 和 Workflow
API 用例，不计入 566 个历史声明。Pairing 等待持久删除结果；cookie 和 token 在请求进入等待状态后比较完整记录。每个映射用例都关联到
`validationRuns` 中已通过的本地运行；各次运行的范围不同。

  完整服务器用例在 Chat 检查点切断 PostgreSQL 连接，检查恢复后只有一份保存的模型结果、Turn 和事件集。

- **A05 — 版本证据：**
  记录源码版本及各次运行范围，明确列出可选或跳过的检查。接受测试数量变化前，比较变更和删除的基线断言。

## 数据迁移检查

[部署指南](/zh-cn/docs/deploy)说明维护顺序和密钥配置。 `S/DataUpgrade.test.ts`
检查空数据库、维护与活动服务器互斥、批次回滚与续跑，以及导入历史不会启动外部工作。这些是基础检查。

`S/MigrationRehearsal.test.ts`
从旧结构和记录开始，与各领域转换测试一起检查以下内容，全部通过后才打开启动门禁：

| 保存的数据                                            | 必需检查                                                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Chat、Turn、排队输入、工具、审批、委派和 Code Mode    | 保留 ID、历史、顺序、归属、限额和决策。待处理工作关联执行。缺失调用人证据不能产生新权限。              |
| App、OAuth、开发测试、索引工作、Channel、触发器和提醒 | 保留连接和证明 ID、加密授权及流程、原调用人证据、计时器、待投递通知和发送结果。旧未知写入保持未知。    |
| 文件、Vault、模型、组织、账户、SSO 和物理资源记录     | 检查对象引用、外键、归属关联、保存密钥的解码和支持的连接状态。不能静默丢弃损坏记录。                   |

演练时保留备份和对象引用清单。外部工作恢复前可以还原。之后应测试向前修复，避免旧备份引发重复外部写入。

## 发布证据

在同一个固定版本上运行[项目检查](/zh-cn/docs/developers/testing)。先完成构建，再开始测试，因为测试和子进程会加载构建文件。

| 检查           | 入口                                                                 | 所需证据                                                                              |
| -------------- | -------------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| 构建与类型     | `devenv shell -- pnpm build`; `devenv shell -- pnpm typecheck`       | 全部包、包测试脚本中的测试类型检查及依赖规则。                                        |
| 包和用户任务   | `devenv shell -- pnpm -r test`                                       | 完整测试输出、跳过项目和最终 E2E 断言表。                                             |
| 故障与迁移     | 上面的 F01–F11 和 A01–A04                                            | 进程边界、故障点、终态、外部动作次数及保存的事件/调用证据。                           |
| 镜像与 Compose | `.github/workflows/ci.yml`, `deploy/docker/check.sh`                 | Docker 构建检查、Compose 启动/迁移/API 检查、镜像层检查和对应镜像 ID 的漏洞扫描输出。 |
| 文档           | 文档包构建、`E/read-docs/Docs.test.ts`、`.github/workflows/docs.yml` | 英语、中文、德语、生成的 API 参考、全部主页语言和链接检查。                           |
| 合并与推送     | 合并后精确版本的 CI                                                  | 必需任务通过。本地局部测试或较早快照不是最终 CI 证据。                                |

基线追踪将每个用例关联到已记录的本地运行。证据包括完整构建、类型检查及 956 个文件的规则检查，以及标准 OpenBot 包运行中的 131 个文件、883 项测试。包测试包含 Activity 进程用例、完整服务器集群检查及迁移演练。

E2E 证据由完整测试组运行和受影响用例的检查共同组成：31 项受影响用例在一次运行中通过，DevelopmentApps 用例在另一次标准包运行中通过。这 32 项与完整测试组的输出有重叠，数量不能相加。一项可选的真实 Cloudflare 用例被跳过。追踪表记录各次命令、范围和日志，不将它们描述为一次最终合并运行。

发布检查应以精确发布提交的 CI 为准，包括镜像、Compose、扫描及文档。本地测试证据不能替代这些任务。
