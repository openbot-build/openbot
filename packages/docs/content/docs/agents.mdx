An **Agent** is a worker with a role, such as a programmer, a writer or a designer. Each Agent has its own instructions, its own Sessions and its own long-term memory. Agents give work to each other, so each one keeps its attention on its own task.
This page shows the kinds of Agents and the routes under `/v1/agents`. Every route accepts a user token or the session cookie. See [Authentication](/docs/authentication).

---

## Three kinds of Agents

| Kind         | Owner                                        | Lives                               | What it is for                                                       |
| ------------ | -------------------------------------------- | ----------------------------------- | -------------------------------------------------------------------- |
| `main`       | One member                                   | As long as the member               | Acts for the person. Does simple work itself and gives work away.    |
| `persistent` | A member, the organization, or another Agent | Until you archive it                | A lasting worker with a role. It learns from its work over time.     |
| `session`    | One Session                                  | As long as the Session that owns it | A helper for one line of work. It keeps its context in that Session. |

Every member has exactly one **Main Agent**. OpenBot makes it the first time it is needed. A Session that you create without an Agent belongs to your Main Agent.

A new Main Agent has no model. Set its `model` before you create a Session without a model of its own. See [Models](/docs/models#choose-a-model).

A **Session Agent** is "almost lasting". An Agent starts it with a tool while it works. The Session Agent keeps its context while its Session lasts, so the Agent can give it work many times. When you delete the Session, its Session Agents are archived too. You can [promote](#promote-a-session-agent) a useful Session Agent to a lasting Agent.

An Agent can own lasting Agents too. See [Agents that own Agents](#agents-that-own-agents).

Every Session belongs to one Agent. See [Sessions](/docs/sessions). How Agents give work to each other is on [Delegation](/docs/delegation).

### No limits that an Agent knows

Agents have no list of things they may do. An Agent just tries. When it tries something new for the first time, such as making an Agent or calling an App tool, the decider above it decides. See [Requests](/docs/requests). The decisions are kept, so the limits of each Agent grow from real work.

## Make an Agent

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Programmer","role":"Writes and reviews TypeScript code","instructions":"Write small, tested changes. Explain each change in one short paragraph."}' \
  https://api.example.com/v1/agents
```

| Field          | Meaning                                                                                                      |
| -------------- | ------------------------------------------------------------------------------------------------------------ |
| `name`         | Required. A short name. OpenBot removes spaces at the start and end. The rest must have 1 to 100 characters. |
| `role`         | Required. What the Agent does, in one line. Other Agents read it to choose workers.                          |
| `instructions` | Required. The lasting instructions of the Agent, like a job description.                                     |
| `model`        | Optional. The model of the Sessions of this Agent, when a Session does not choose its own.                   |
| `planApproval` | Optional. How the plans of this Agent are approved. See [Plan mode](/docs/sessions#plan-mode).               |
| `shared`       | Optional. `true` makes an organization Agent that every member can use.                                      |
| `agent`        | Optional. The ID of the Agent that owns the new Agent. You cannot use it with `shared`.                      |

OpenBot returns `201` with the Agent:

```json
{
	"id": "agt_5c0e…",
	"kind": "persistent",
	"owner": { "_tag": "Member", "userId": "u-1" },
	"name": "Programmer",
	"role": "Writes and reviews TypeScript code",
	"instructions": "Write small, tested changes. …",
	"archived": false,
	"revision": 0,
	"createdAt": 1792486800000,
	"updatedAt": 1792486800000
}
```

`owner` is `Member`, `Organization`, `Session` or `Agent`. A shared Agent works with the permissions and the App connections of the member who uses it, never with those of the person who made it.

## List, read and change Agents

`GET /v1/agents` lists your Main Agent, your own Agents and the shared Agents that you may use. Add `?archived=false` to hide archived Agents. Add `?session=<id>` to list the Session Agents of one Session. Add `?agent=<id>` to list the Agents that one Agent owns.

`GET /v1/agents/:agentId` returns one Agent.

```sh
curl -X PATCH -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expected":0,"instructions":"Write small changes with tests first."}' \
  https://api.example.com/v1/agents/$AGENT
```

`expected` is the current `revision`. You can change `name` (with the same rules as above), `role`, `instructions`, `model` (send `null` to remove it) and `archived`. The Main Agent cannot be archived. When you archive an Agent, OpenBot also archives every Agent that it owns, and the Agents below them. When you unarchive it, only that one Agent comes back.

## Promote a Session Agent

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expected":3}' \
  https://api.example.com/v1/agents/$AGENT/promote
```

The Session Agent becomes a lasting Agent of the member. Send `agent` with the ID of an Agent to make that Agent its owner. OpenBot also adds the lasting entries of its Session memory to its [Agent memory](/docs/memory#agent-memory).

An Agent can promote a Session Agent of its own Session with the `openbot_promote_agent` tool. Then the Agent owns it.

## Agents that own Agents

An Agent can own lasting Agents. So an Agent can build its own team, and each member of the team keeps its own memory.

- An Agent makes an Agent that it owns with the `openbot_create_agent` tool. A person makes one with `POST /v1/agents` and the `agent` field.
- An Agent that another Agent makes with a tool, a lasting Agent or a Session Agent, gets the `model` of the Agent that makes it. The tool call can name another `model`.
- The owner is `{ "_tag": "Agent", "agent": "<owner ID>", "userId": "<member>" }`. `userId` is the member at the top of the owner tree. It is `null` when the organization owns the Agent at the top.
- An Agent can give work to the Agents it owns without a request.
- The **owner chain** of an Agent goes up through its owners to a Main Agent, and then to the person. For example: **person → Main → Worker → Scout**. Requests of an Agent go up this chain, also when a person works with the Agent directly. See [Requests](/docs/requests#the-chain-of-deciders).
- In the chain, the owner of a member's Agent or of a shared Agent is the Main Agent of the person who works with it.

## What an Agent knows in each Turn

OpenBot adds these to the instructions of every Turn:

- the name, role and instructions of the Agent,
- the person it works with now, with their name and member ID. In a [Channel](/docs/channels), it is the person who wrote the message of the Turn,
- rules about privacy: what the Agent learned from one person may be private, so it tells another person only what is clearly shared,
- for a Session with work from another Agent, how to send the result back,
- the active entries of its [Agent memory](/docs/memory#agent-memory).

## Permissions

| Permission        | Lets you                                                    |
| ----------------- | ----------------------------------------------------------- |
| `agents.read`     | Read Agents, their memory, Rules and Grants.                |
| `agents.write`    | Make and change Agents, their memory, Rules and Grants.     |
| `agents.delegate` | Give work to an Agent, from a client or from another Agent. |

Your own Agents are below your member key. Shared Agents are below `openbot.org.<org>.agent`. Members may read and use shared Agents. Administrators may also change them. See [Permissions](/docs/permissions).

## Errors

| Status | Error                     | When                                                       |
| ------ | ------------------------- | ---------------------------------------------------------- |
| `400`  | `AgentInvalid`            | The change is not allowed, such as archiving a Main Agent. |
| `403`  | `PermissionDenied`        | You may read the Agent, but not change or use it.          |
| `404`  | `AgentNotFound`           | There is no Agent with this ID that you may read.          |
| `409`  | `AgentConflict`           | `expected` is old. Read the Agent again and retry.         |
| `503`  | `AgentStorageUnavailable` | OpenBot cannot reach its database.                         |
