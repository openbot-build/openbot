This manual is for people who write software that uses or extends OpenBot. API
access does not give extra rights. Each request still acts for its caller.

## Connect a client

Start with an existing OpenBot address and an account in an organization. Use
the [local API quick start](/docs/developers/quickstart) when you need a test
server.

1. Implement
   [sign-in, organization selection, and tokens](/docs/developers/authentication).
2. Use the [TypeScript client](/docs/client) or the
   [HTTP reference](/docs/api/).
3. Send [Bot messages](/docs/developers/bots), read
   [Chat results and streams](/docs/developers/chats), and handle
   [requests](/docs/developers/requests).
4. Add [files](/docs/developers/files), [Apps](/docs/developers/apps), or
   [live sessions](/docs/developers/live) for your client.

The API task guides in the sidebar describe request fields, response states, and
errors. Your client owns its screens and return paths.

## Publish an App

You need control of the App service and its public HTTPS address.

1. Publish its documents with the [App Protocol](/docs/protocol).
2. Check it with the [protocol test service](/docs/protocol-test).
3. Use [publisher tools](/docs/developer-tools) to prove control, test
   connections, and ask for indexing.
4. Read the [App Index contract](/docs/developers/app-index) for search and
   withdrawal.

## Work on OpenBot

1. Read [contributing](/docs/contributing) for setup, checks, and project rules.
2. Read the [package boundaries](/docs/packages) and
   [execution design](/docs/architecture).
3. Use [Run from code](/docs/server) for server composition. Add
   [model backends](/docs/developers/model-backends),
   [Live backends](/docs/developers/live-backend), or
   [logging](/docs/developers/logging) there.
4. Follow [publishing and checks](/docs/developers/publishing) when you maintain
   project releases.

Production installation and secrets belong to the
[administrator manual](/docs/admin).
