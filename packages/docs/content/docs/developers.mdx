This manual is for people who write software that uses or extends OpenBot. API
access does not give extra rights. Each request still acts for its caller.

## Connect a client

Start with an existing OpenBot address and an account in an organization. Use
the [local API quick start](/developers/quickstart) when you need a test server.

1. Implement
   [sign-in, organization selection, and tokens](/developers/authentication).
2. Use the [TypeScript client](/client) or the [HTTP reference](/api/).
3. Send [Bot messages](/developers/bots), read
   [Chat results and streams](/developers/chats), and handle
   [requests](/developers/requests).
4. Add [files](/developers/files), [Apps](/developers/apps), or
   [live sessions](/developers/live) for your client.

The API task guides in the sidebar describe request fields, response states, and
errors. Your client owns its screens and return paths.

## Publish an App

You need control of the App service and its public HTTPS address.

1. Publish its documents with the [App Protocol](/protocol).
2. Check it with the [protocol test service](/protocol-test).
3. Use [publisher tools](/developer-tools) to prove control, test connections,
   and ask for indexing.
4. Read the [App Index contract](/developers/app-index) for search and
   withdrawal.

## Work on OpenBot

1. Read [contributing](/contributing) for setup, checks, and project rules.
2. Read the [package boundaries](/packages) and
   [execution design](/architecture).
3. Use [Run from code](/server) for server composition. Add
   [model backends](/developers/model-backends),
   [Live backends](/developers/live-backend), or [logging](/developers/logging)
   there.
4. Follow [publishing and checks](/developers/publishing) when you maintain
   project releases.

Production installation and secrets belong to the
[administrator manual](/admin).
