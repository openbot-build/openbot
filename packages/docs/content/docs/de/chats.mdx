Ein **Chat** ist ein Gespräch mit einem [Bot](/de/docs/bots). Du erstellst keine
Chats, du wählst sie nicht aus und du schließt sie nicht. Du schickst einem Bot
eine Nachricht, und OpenBot führt einen Chat für dich und diesen Bot. Der Bot
antwortet immer sofort. Lange Arbeit geht an andere Chats, die parallel laufen.
Die Ergebnisse kommen später in deinen Chat zurück. Diese Seite zeigt, wie du
mit einem Bot sprichst und wie du einen Chat liest. Jede Route nimmt ein
User-Token oder das Session-Cookie an. Siehe
[Authentifizierung](/de/docs/authentication).

| Begriff    | Bedeutung                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Turn       | Ein Durchgang des Bots: Er liest neue Eingaben, macht Model-Schritte und Werkzeugaufrufe und gibt eine Antwort.                                         |
| Item       | Ein Eintrag im Verlauf eines Chats, zum Beispiel eine Nachricht, eine Antwort des Models, ein Werkzeugaufruf oder ein Werkzeugergebnis.                 |
| Inbox      | Die Eingaben, die auf einen Turn warten. Siehe [Die Inbox](#die-inbox).                                                                                 |
| Mitteilung | Eine Eingabe von OpenBot, nicht von einer Person, zum Beispiel das Ergebnis von Arbeit, die der Bot abgegeben hat. Siehe [Mitteilungen](#mitteilungen). |
| Revision   | `chat.revision`. Eine Zahl, die bei jeder Änderung am Chat steigt.                                                                                      |

---

## Arten von Chats

OpenBot erstellt jeden Chat selbst. `kind` sagt, warum es einen Chat gibt:

| Art       | Wann OpenBot ihn erstellt                                                                                                             | Wem er gehört                               |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `direct`  | Wenn eine Person einem Bot zum ersten Mal eine Nachricht schickt.                                                                     | Dieser Person.                              |
| `channel` | Bei der ersten Nachricht in einem Chat eines [Channel](/de/docs/channels).                                                            | Dem Actor des Channel.                      |
| `task`    | Jedes Mal, wenn ein Bot einem Bot Arbeit gibt oder ein [Trigger](/de/docs/triggers) auslöst. Siehe [Delegation](/de/docs/delegation). | Dem Besitzer des Chats, der die Arbeit gab. |
| `review`  | Wenn ein Bot über einen [Request](/de/docs/requests) entscheiden muss.                                                                | Der Person, für die der Request ist.        |

Jede Person hat mit jedem Bot einen direkten Chat. Ein Chat hat kein Ende. Er
geht weiter, solange Menschen mit dem Bot sprechen, außer du
[löschst seinen Verlauf](#den-verlauf-löschen). Ein Prüf-Chat (`review`)
schließt nach seiner Entscheidung.

## Mit einem Bot sprechen

Schicke einem Bot eine Nachricht mit `POST /v1/bots/:botId/messages`:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"input":"Plan three days in Rome."}' \
  https://api.example.com/v1/bots/$BOT/messages
```

Die Nachricht geht in deinen direkten Chat mit diesem Bot. Die erste Nachricht
erstellt den Chat. Du brauchst `bots.delegate` für den Bot. Um zu wissen, mit
welchem Bot du zuerst sprichst, lies `defaultBot` aus `GET /v1/me/settings`.
Siehe [Dein Standard-Bot](/de/docs/bots#dein-standard-bot).

| Feld         | Bedeutung                                                                                                                            |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| `input`      | Pflicht. Text oder eine Liste von Nachrichten der Person (siehe unten).                                                              |
| `stream`     | Optional. `true` sendet Live-Ereignisse, wenn die Nachricht einen Turn startet. Siehe [Die Antwort streamen](#die-antwort-streamen). |
| `background` | Optional. Nur `true` ist erlaubt. Jeder Turn läuft im Hintergrund.                                                                   |

Es gibt keine Revision `expected`. Eine Nachricht wird immer angenommen.

`input` nimmt Text an. Diese drei Formen bedeuten dasselbe:

```json
"Plan three days in Rome."
```

```json
[{ "role": "user", "content": "Plan three days in Rome." }]
```

```json
[
	{
		"type": "message",
		"role": "user",
		"content": [{ "type": "input_text", "text": "Plan three days in Rome." }]
	}
]
```

Unbekannte Felder ergeben `400`.

Eine Nachricht kann auch Dateien haben, die du hochgeladen hast, mit Teilen vom
Typ `input_image` und `input_file`. Siehe
[Eine Datei an einen Bot geben](/de/docs/files#eine-datei-an-einen-bot-geben).

`POST /v1/chats/:chatId/messages` nimmt denselben Body. Nutze es für einen
direkten Chat, oder für einen Task-Chat, wenn du der Arbeit eines Bots etwas
hinzufügen willst. In einem Task-Chat liest der Bot deine Nachricht als
Nachricht von dir. Andere Arten von Chats ergeben `409` mit `ChatConflict`.

### Die Antwort

OpenBot antwortet sofort mit `202`:

```json
{
	"delivery": "started",
	"chat": "chat_7d21…",
	"item": "i-01",
	"turn": "t-19aa",
	"response": {
		"id": "t-19aa",
		"object": "response",
		"created_at": 1792486800,
		"chat": "chat_7d21…",
		"background": true,
		"status": "in_progress",
		"output": [],
		"error": null,
		"incomplete_details": null
	}
}
```

`delivery` sagt, was mit der Nachricht passiert ist. Siehe
[Die Inbox](#die-inbox).

| `delivery` | Bedeutung                                                                                                            |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| `started`  | Die Nachricht hat einen neuen Turn gestartet. `turn` und `response` sind dieser Turn.                                |
| `steered`  | Ein Turn von dir läuft, und der Bot liest die Nachricht bei seinem nächsten Schritt. `turn` ist dieser Turn.         |
| `queued`   | Ein Turn einer anderen Person läuft. Die Nachricht wartet auf ihren eigenen Turn. `turn` und `response` sind `null`. |

`response` hat die Form einer Antwort der OpenAI Responses API. Das Gespräch ist
der Chat, und eine Antwort ist ein Turn. Die Arbeit geht weiter, nachdem die
Anfrage endet. Lies das Ergebnis später mit `GET /v1/chats/:chatId` (das Feld
`response`), mit der [Warte-Route](#einen-chat-lesen) oder mit
`GET /v1/chats/:chatId/turns/:turnId`. Der letzte `status` ist `completed`,
`incomplete`, `failed` oder `cancelled`. Jedes Item in `output` ist eine
Nachricht des Assistenten mit Teilen vom Typ `output_text`. `usage` zeigt die
Tokens.

### Die Antwort streamen

Mit `"stream": true` bekommt eine Nachricht, die einen Turn startet, `200` mit
Server-Sent Events (SSE). SSE ist ein einfaches Format für einen Strom von
Ereignissen über HTTP. Eine Nachricht, die keinen Turn startet, bekommt die
normale Antwort `202`.

```sh
curl -N -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"input":"Plan three days in Rome.","stream":true}' \
  https://api.example.com/v1/bots/$BOT/messages
```

```sh
event: response.output_text.delta
data: {"type":"response.output_text.delta","chat":"chat_7d21…","turn":"t-19aa","step":1,"sequence_number":4,"item_id":"i-02","output_index":0,"content_index":0,"delta":"Day 1: ","logprobs":[]}
```

Die Ereignisse kommen in dieser Reihenfolge: `response.created`,
`response.in_progress`, `response.output_item.added`,
`response.content_part.added`, viele `response.output_text.delta`,
`response.output_text.done`, `response.content_part.done`,
`response.output_item.done`. Das letzte Ereignis ist eins von
`response.completed`, `response.incomplete`, `response.failed` oder
`response.cancelled`. Der Stream beobachtet den Turn nur. Wenn du ihn schließt,
läuft der Turn weiter.

### Häufige Fehler

| Status | Fehler                     | Wann                                                                                                       |
| ------ | -------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `400`  | `ChatModelInvalid`         | Der Chat hat kein Model. Der Bot braucht ein `model`. Siehe [Models](/de/docs/models#ein-model-auswählen). |
| `400`  | `FileInvalid`              | Ein Dateiteil nennt keine deiner fertigen Dateien, oder die Datei ist kein Bild.                           |
| `403`  | `PermissionDenied`         | Du darfst diesem Bot keine Arbeit geben.                                                                   |
| `404`  | `BotNotFound`              | Es gibt keinen Bot mit dieser ID, den du nutzen darfst.                                                    |
| `404`  | `ChatNotFound`             | Du hast keinen Chat mit dieser ID.                                                                         |
| `409`  | `ChatConflict`             | Diese Art von Chat nimmt keine Nachrichten von Personen an.                                                |
| `503`  | `ChatExecutionUnavailable` | OpenBot hat kein Model, um den Turn auszuführen.                                                           |
| `503`  | `ChatStorageUnavailable`   | OpenBot erreicht seine Datenbank nicht.                                                                    |

## Die Inbox

Jeder Chat hat eine **Inbox** (einen Eingang). Jede Eingabe kommt zuerst dort
hinein: eine Nachricht einer Person oder eine Mitteilung von OpenBot. Die Inbox
gibt jede Eingabe nach diesen Regeln an einen Turn:

1. **Der Chat ist frei.** Die Eingabe startet sofort einen neuen Turn. Alle
   Eingaben desselben Authors, die in der Inbox warten, gehen in diesen Turn.
2. **Ein Turn desselben Authors läuft.** Die Eingabe lenkt den Turn (Steer): Der
   Bot liest sie bei seinem nächsten Model-Schritt.
3. **Ein Turn eines anderen Authors läuft.** Die Eingabe wartet. Sie startet
   ihren eigenen Turn, nachdem der laufende Turn endet. Das passiert in einem
   Gruppenchat eines Channel, in dem viele Menschen sprechen.
4. **Ein Turn endet.** Die nächste Eingabe in der Inbox startet den nächsten
   Turn. Das passiert nach jedem Ende: `Completed`, `Failed` und `Interrupted`.

Der **Author** ist die Person, für die die Eingabe ist. Bei einer Nachricht ist
es die Person, die sie schickt, zusammen mit der Art, wie sie sich angemeldet
hat. Eine Nachricht mit einem anderen User-Token derselben Person zählt also als
anderer Author. Eine Mitteilung hat den Author der Arbeit, um die es geht.

Ein Turn, der endet, bevor er eine Steer-Nachricht liest, gibt sie an die Inbox
zurück. So geht keine Eingabe verloren. Die Ansicht eines Chats zeigt in
`inbox`, wie viele Eingaben warten.

## Mitteilungen

Ein Turn wartet nie. Alles, was Zeit von außen braucht, kommt später als
**Mitteilung** (Notice) zurück: eine neue Eingabe von OpenBot, nicht von einer
Person.

- Ein Bot gibt einem Bot Arbeit. Der Werkzeugaufruf kehrt sofort zurück. Wenn
  die Arbeit endet, kommt ihr Ergebnis als Mitteilung zurück. Siehe
  [Delegation](/de/docs/delegation).
- Ein Werkzeugaufruf braucht eine Entscheidung. Der Werkzeugaufruf bekommt
  sofort ein Ergebnis, das sagt, dass er wartet. Die Antwort kommt als
  Mitteilung zurück. Wenn der Aufruf erlaubt wird, läuft er dann. Siehe
  [Requests](/de/docs/requests).
- Ein Bot bittet um eine [Erinnerung](#erinnerungen). Die Notiz kommt zu dieser
  Zeit als Mitteilung zurück.

Eine Mitteilung ist ein Eingabe-Item mit `origin.notice`. Ihr `kind` sagt, worum
es geht, und `ref` nennt die Sache, zum Beispiel die ID einer Delegation:

| `kind`       | Was sie bringt                                                                 |
| ------------ | ------------------------------------------------------------------------------ |
| `delegation` | Das Ergebnis von Arbeit, die dieser Chat abgegeben hat.                        |
| `task`       | Die Aufgabe eines Task-Chats.                                                  |
| `request`    | Die Antwort auf einen Request. Ein erlaubter Aufruf läuft mit ihr.             |
| `review`     | Den Request, über den ein Prüf-Chat entscheidet.                               |
| `plan`       | Die Antwort auf einen Plan. Siehe [Plan-Modus](#plan-modus).                   |
| `reminder`   | Die Notiz einer Erinnerung.                                                    |
| `code`       | Das Ende eines Programms im [Code Mode](/de/docs/code-mode), das gewartet hat. |
| `app`        | Eine Nachricht aus einer [App-Ansicht](/de/docs/apps#app-ansichten).           |
| `todos`      | Eine Erinnerung an die offenen Einträge der [Todo-Liste](#todo-liste).         |

Der Text einer Mitteilung beginnt mit `[OpenBot]`. Der Bot weiß, dass solcher
Text von OpenBot kommt, nicht von einer Person. Er liest ihn als Daten, nicht
als Anweisungen. Der [Memory-Bot](/de/docs/memory#der-memory-bot) nimmt eine
Mitteilung nie als die Worte einer Person.

Eine Mitteilung geht wie eine Nachricht durch die Inbox. Wenn du also mit dem
Bot sprichst, kann zur selben Zeit ein Ergebnis kommen. Es lenkt deinen Turn
oder wartet auf den nächsten.

## Offene Arbeit

**Offene Arbeit** ist die Arbeit eines Chats, die noch nicht beendet ist: die
Arbeit, die er an Bots gegeben hat, seine Requests, die auf eine Entscheidung
warten, und seine Erinnerungen. Jede davon kommt später als Mitteilung zurück.

`open` in der Ansicht eines Chats zählt sie:

```json
{ "delegations": 2, "requests": 0, "reminders": 1 }
```

Der Bot sieht am Anfang jedes Turns eine Liste seiner offenen Arbeit: die ID,
den Bot und die erste Zeile jeder Delegation, jeden Request und jede Erinnerung
mit ihrer Zeit. So weiß er, was zurückkommen wird.

Offene Arbeit entscheidet auch, wann die Arbeit eines Task-Chats endet. Siehe
[Delegation](/de/docs/delegation#wann-die-arbeit-endet).

## Einen Chat lesen

`GET /v1/chats` listet deine direkten Chats und Channel-Chats auf, den ältesten
zuerst. Füge `bot=<id>` hinzu, um die Chats eines Bots aufzulisten. Füge
`kind=<kind>` hinzu, um eine Art aufzulisten, zum Beispiel `task` oder `review`.
Jede Zusammenfassung hat `chat`, `status`, `turn`, eine kurze `response` und
`activity`.

`GET /v1/chats/:chatId` gibt die Ansicht eines Chats zurück. Lesen startet nie
Arbeit. Hier ist eine kurze Form davon:

```json
{
	"chat": {
		"id": "chat_7d21…",
		"revision": 4,
		"kind": "direct",
		"bot": "bot_3f9a…",
		"parent": null,
		"settings": { "mode": "build" },
		"createdAt": 1792486800000
	},
	"status": "Running",
	"turn": { "id": "t-19aa", "status": { "_tag": "Running" } },
	"response": { "id": "t-19aa", "status": "in_progress" },
	"activity": "active",
	"inbox": 0,
	"open": { "delegations": 1, "requests": 0, "reminders": 0 }
}
```

| Feld       | Bedeutung                                                                                                                                                                                                                      |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `chat`     | Der Chat: sein `kind`, sein `bot` und seine `settings`. `parent` nennt den Chat und die Delegation, die einem Task-Chat seine Arbeit gegeben haben. Ein Channel-Chat hat einen `title`: den Namen des Chats auf der Plattform. |
| `status`   | `Idle` vor dem ersten Turn. Danach der Status des letzten Turns: `Running`, `Completed`, `Failed` oder `Interrupted`.                                                                                                          |
| `turn`     | Der aktuelle Turn oder der letzte.                                                                                                                                                                                             |
| `response` | Die Antwort dieses Turns.                                                                                                                                                                                                      |
| `activity` | `active`, solange ein Turn auf diesem Server läuft, `inactive`, wenn nichts läuft, und `historical`, wenn der Chat sagt, dass ein Turn läuft, aber kein Prozess auf diesem Server ihn ausführt.                                |
| `inbox`    | Die Zahl der Eingaben, die auf einen Turn warten.                                                                                                                                                                              |
| `open`     | Die [offene Arbeit](#offene-arbeit).                                                                                                                                                                                           |

Die Ansicht enthält keinen Verlauf. Lies den Verlauf mit diesen Routen:

| Route                                       | Was sie zurückgibt                                                                                                                                                             |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `GET /v1/chats/:chatId/items`               | Die Items des Chats, das neueste zuerst. Nutze `limit` (1 bis 100, Standard 50). Sende `next` als `before`, um ältere Items zu lesen. So liest du einen langen Chat am besten. |
| `GET /v1/chats/:chatId/turns`               | Die Turn-Einträge, den ältesten zuerst. Nutze `limit` und `after` (eine Turn-ID). Die Antwort ist `{ "items": [...], "next": "<turnId>" \| null }`.                            |
| `GET /v1/chats/:chatId/turns/:turnId`       | `{ "turn": {...}, "response": {...} }`.                                                                                                                                        |
| `GET /v1/chats/:chatId/turns/:turnId/items` | Die Items eines Turns, mit `after` (eine Item-ID) und `limit`.                                                                                                                 |

Ein Turn-Eintrag hat `status`, `settings`, `steps`, `usage`, `input` (die IDs
seiner Eingabe-Items), `items`, `startedAt` und `completedAt`. `author` ist die
Person, für die der Turn arbeitet. In einem [Channel](/de/docs/channels) ist es
die Person, die die Nachricht geschrieben hat. Jedes Item hat `id`, `seq` (seine
Stelle im Verlauf), `content` und `origin` (`chat`, `turn`, `step` und bei einer
Mitteilung `notice`).

Um auf eine Änderung zu warten, nutze Long Polling (eine Anfrage, die auf eine
Änderung wartet). OpenBot antwortet, wenn die Revision nicht mehr `after` ist
oder wenn die Wartezeit endet. Das längste Warten dauert 30 Sekunden. Ein Turn,
den eine Mitteilung startet, zeigt sich hier auch.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  "https://api.example.com/v1/chats/$CHAT/wait?after=4&timeoutMs=30000"
```

Weitere Routen lesen die Arbeit eines Chats:

| Route                                  | Was sie auflistet                                                                                                     |
| -------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/chats/:chatId/delegations`    | Die Arbeit, die dieser Chat an Bots gegeben hat. Siehe [Delegation](/de/docs/delegation#die-arbeit-beobachten).       |
| `GET /v1/chats/:chatId/confessions`    | Was der Bot mit `confide` gesagt hat. Siehe [Beichten zeigen](/de/docs/client#beichten-zeigen).                       |
| `GET /v1/chats/:chatId/enrichments`    | Was der Memory-Bot zur Eingabe jedes Turns hinzugefügt hat. Siehe [Memory](/de/docs/memory#beichten-und-ergänzungen). |
| `GET /v1/chats/:chatId/code-runs`      | Die Programme des Chats im [Code Mode](/de/docs/code-mode).                                                           |
| `GET /v1/chats/:chatId/app-operations` | Die Aufrufe von [Apps](/de/docs/apps) im Chat.                                                                        |

## Unterbrechen

`POST /v1/chats/:chatId/interrupt` stoppt den laufenden Turn:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' \
  https://api.example.com/v1/chats/$CHAT/interrupt
```

Der Status des Turns wird `Interrupted`, und der Status der Antwort wird
`cancelled`. Wenn kein Turn läuft, ändert sich nichts. Die Antwort ist die
Ansicht des Chats.

Ein Unterbrechen stoppt nur den Turn. Die Arbeit, die der Chat an Bots gegeben
hat, geht weiter, und ihre Ergebnisse kommen trotzdem zurück. Auch seine
Requests und Erinnerungen bleiben offen. Um alles zu stoppen, sende
`{ "delegations": true }`. Dann bricht OpenBot auch die Arbeit ab, die der Chat
abgegeben hat, mit der Arbeit, die diese Arbeit abgegeben hat, und die Requests
und Erinnerungen des Chats.

Nach dem Unterbrechen startet die nächste Eingabe in der Inbox den nächsten
Turn.

## Todo-Liste

Ein Chat hat eine Todo-Liste (eine Liste offener Aufgaben). Der Bot führt sie
mit dem Werkzeug `openbot_todos`, wenn seine Arbeit mehr als einen Schritt hat.
Jeder Eintrag hat eine `id`, einen `content` und einen `status`: `pending`,
`in_progress` oder `done`. Nur ein Eintrag kann zur selben Zeit `in_progress`
sein.

Solange ein Eintrag nicht `done` ist, arbeitet der Bot weiter. Wenn der Bot den
Turn mit offenen Einträgen beenden will, gibt OpenBot ihm eine Mitteilung mit
den offenen Einträgen. Dann macht der Bot noch einen Schritt. OpenBot tut das
nur einmal für jeden Stand der Liste. Es tut das nicht, solange der Chat
[offene Arbeit](#offene-arbeit) hat, denn diese Arbeit kommt als Mitteilung
zurück. Wenn am Ende eines Turns jeder Eintrag `done` ist, wird die Liste leer.
So bleibt keine alte Liste in einem Chat, der nie endet.

Lies die Liste mit `GET /v1/chats/:chatId/todos`:

```json
{
	"items": [
		{ "id": "read", "content": "Read the open issues", "status": "done" },
		{ "id": "fix", "content": "Fix the login bug", "status": "in_progress" }
	]
}
```

Ersetze die ganze Liste mit `PUT /v1/chats/:chatId/todos`. Sende die Revision
des Chats, die du gelesen hast:

```json
{
	"revision": 7,
	"items": [
		{ "id": "fix", "content": "Fix the login bug", "status": "pending" }
	]
}
```

Die Antwort ist die Ansicht des Chats. Eine alte Revision ergibt `409` mit
`ChatConflict`. Das gilt auch für eine Liste, in der zwei Einträge dieselbe `id`
haben oder mehr als ein Eintrag `in_progress` ist.

## Erinnerungen

Ein Bot kann mit dem Werkzeug `openbot_remind` später auf etwas zurückkommen. Er
gibt `seconds` an, oder `until` mit Datum und Uhrzeit, zum Beispiel
`2026-10-23T09:00:00Z`, und eine `note` (Notiz). Das Werkzeug gibt sofort
`{ "reminder": "rem_…", "at": "<time>" }` zurück, und der Turn geht weiter. Zu
dieser Zeit kommt die Notiz als Mitteilung in den Chat zurück.

OpenBot speichert jede Erinnerung. Nach einem Neustart kommt die Erinnerung
trotzdem zu ihrer Zeit. Eine Erinnerung, deren Zeit vorbei ist, während kein
Server lief, kommt gleich nach dem Start. OpenBot sucht außerdem jede Minute
nach fälligen Erinnerungen.

Eine Erinnerung ist [offene Arbeit](#offene-arbeit). Ein Unterbrechen mit
`{ "delegations": true }` bricht sie ab. Das tut auch ein Abbruch der Arbeit
ihres Task-Chats und das Löschen ihres Chats.

## Plan-Modus

Im Modus `plan` sieht der Bot nach, aber er ändert noch nichts. Er bekommt nur
die Werkzeuge, die nur lesen: die Bot-Werkzeuge, die Bots auflisten und lesen,
App-Ressourcen und Prompts, und die App-Werkzeuge, die die Organisation in
`appReadRules` nennt. Er bekommt auch das Todo-Werkzeug, das Werkzeug für
Erinnerungen und `openbot_submit_plan`.

Wenn der Plan fertig ist, ruft der Bot `openbot_submit_plan` mit den Schritten
als Todo-Liste und einer kurzen Zusammenfassung auf. OpenBot speichert die Liste
und prüft die Fähigkeit `plans.run`, wie bei jedem [Request](/de/docs/requests).

- Wenn der Plan sofort erlaubt wird, wechselt der Chat in den Modus `build`.
  Nach diesem Turn startet ein neuer Turn mit allen Werkzeugen, und der Bot
  führt den Plan aus.
- Wenn der Plan eine Entscheidung braucht, gibt das Werkzeug sofort ein
  wartendes Ergebnis zurück, und der Turn endet. Wenn der Plan später erlaubt
  wird, wechselt der Chat in den Modus `build`, und eine Mitteilung startet
  einen neuen Turn, der den Plan ausführt.
- Wenn der Plan abgelehnt wird, gibt eine Mitteilung dem Bot den Grund. Der Chat
  bleibt im Modus `plan`.

Die Einstellung für die Erlaubnis sagt, wer antwortet und was passiert, wenn
niemand rechtzeitig antwortet:

```json
{ "approver": "person", "timeoutMs": 600000, "onTimeout": "run" }
```

| Feld        | Werte                | Was es tut                                                                                                                 |
| ----------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `approver`  | `chain`, `person`    | `chain` fragt den Entscheider über dem Bot. So kann ein Grant oder eine Rule antworten. `person` fragt immer den Menschen. |
| `timeoutMs` | 1 Sekunde bis 7 Tage | Wie lange der Request wartet.                                                                                              |
| `onTimeout` | `run`, `stay`        | `run` führt den Plan aus, wenn niemand rechtzeitig antwortet. `stay` lässt den Chat im Modus `plan`.                       |

Du kannst sie an vier Stellen festlegen. Die genaueste Stelle, die etwas
festlegt, gewinnt, auch wenn sie lockerer ist:

1. Der Chat: `planApproval` mit `PATCH /v1/chats/:chatId`. Sende `null`, um es
   zu entfernen.
2. Der Bot: `planApproval` am [Bot](/de/docs/bots).
3. Du: `PATCH /v1/me/settings` mit
   `{ "expectedVersion": 0, "planApproval": { ... } }`. Lies deine Einstellungen
   mit `GET /v1/me/settings`. Dieselben Einstellungen enthalten deinen
   [Standard-Bot](/de/docs/bots#dein-standard-bot).
4. Die Organisation: `planApproval` in ihren
   [Einstellungen](/de/docs/organization#einstellungen). Das ist nur der
   Standard. Es kann eine lockerere Einstellung nicht verbieten.

## Models und Ausführungsmodus

Ein neuer Chat nutzt das `model` seines Bots. `GET /v1/chats/:chatId/models`
zeigt die Models, die du wählen kannst:

```json
{
	"selected": {
		"_tag": "Config.Selection",
		"provider": "development",
		"model": "mock-text"
	},
	"providers": [
		{ "id": "development", "name": "Development scenarios (simulated)" }
	],
	"models": [
		{
			"_tag": "Config.Model",
			"provider": "development",
			"id": "mock-text",
			"name": "mock-text (simulated)",
			"reasoningEfforts": [],
			"serviceTiers": []
		}
	]
}
```

Ändere die Einstellungen eines Chats mit `PATCH /v1/chats/:chatId`:

```json
{
	"expected": 4,
	"mode": "plan",
	"model": {
		"_tag": "Config.Selection",
		"provider": "development",
		"model": "mock-slow"
	}
}
```

| Feld           | Bedeutung                                                                                                                  |
| -------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `expected`     | Pflicht. Die aktuelle `chat.revision`. Eine alte Revision ergibt `409` mit `ChatConflict`.                                 |
| `mode`         | Optional. `build` oder `plan`.                                                                                             |
| `model`        | Optional. Das Model dieses Chats. Es braucht auch `models.use`. `null` lässt den Chat wieder das Model seines Bots nutzen. |
| `planApproval` | Optional. Siehe [Plan-Modus](#plan-modus). `null` entfernt es.                                                             |

Ein falsches Model ergibt `400` mit `ChatModelInvalid`. Der `reason` ist
`provider-not-found`, `model-not-found` oder `unsupported-option`. Wie OpenBot
seine Models bekommt, steht unter [Models](/de/docs/models).

Der Ausführungsmodus ist `build` oder `plan`. `build` ist der normale Modus: Der
Bot macht die Arbeit. Im Modus `plan` schreibt der Bot zuerst einen Plan.
OpenBot speichert den Modus im Chat und kopiert ihn in die `settings` jedes
neuen Turns.

## Kompaktierung

Ein Chat hat kein Ende. Darum kann sein Verlauf größer werden als das
Kontextfenster seines Models. Das Kontextfenster ist der meiste Text, den ein
Model auf einmal lesen kann. Die **Kompaktierung** (Compaction) macht den alten
Teil kürzer, damit er hineinpasst.

Vor jedem Model-Schritt schätzt OpenBot die Input-Tokens des Chats. Etwa vier
Zeichen JSON sind ein Token. Wenn die Schätzung 90 % des Kontextfensters des
Models erreicht, schreibt das Model des Chats eine Zusammenfassung des älteren
Kontexts. Die neuesten Nachrichten bleiben, wie sie sind.

- Das Kontextfenster kommt vom Model im Katalog. Siehe `contextWindow` unter
  [Models](/de/docs/models#ein-model-hinzufügen).
- Ein Model im Code, zum Beispiel ein
  [eingebautes Model](/de/docs/models#eingebaute-models), kann mit
  `autoCompactTokenLimit` eine niedrigere Grenze setzen.
- Ein Model ohne bekanntes Kontextfenster wird nicht kompaktiert.

Der Verlauf behält immer jedes Item, und `GET /v1/chats/:chatId/items` zeigt
alle. Nur das, was das Model liest, wird kleiner. Die Aufrufe für die
Zusammenfassung haben die Nutzungsquelle `compaction`. Siehe
[Nutzung](/de/docs/usage).

OpenBot nutzt standardmäßig nicht die eingebaute Kompaktierung eines Anbieters,
zum Beispiel `/responses/compact` von OpenAI. Ein Programm, das die
[Core-Bibliothek](/de/docs/packages#core) nutzt, kann seinen eigenen Dienst
`ContextCompaction` geben, zum Beispiel `ResponsesCompaction.layer()`.

## Den Verlauf löschen

`DELETE /v1/chats/:chatId` löscht den Verlauf eines direkten Chats oder eines
Channel-Chats und antwortet mit `204`. Zuerst stoppt es den laufenden Turn und
bricht die [offene Arbeit](#offene-arbeit) des Chats ab. Task-Chats und
Prüf-Chats ergeben `409` mit `ChatConflict`.

Danach hält der Chat die [Dateien](/de/docs/files#wie-dateien-verschwinden)
nicht mehr, die er genannt hat.

Nachdem du einen direkten Chat gelöscht hast, startet deine nächste Nachricht an
den Bot einen neuen, leeren Chat mit einer neuen ID. Genauso startet nach dem
Löschen eines Channel-Chats die nächste Nachricht in diesem Chat einen neuen
Chat. Was der Bot aus dem Chat gelernt hat, bleibt in seinem
[Bot Memory](/de/docs/memory). Um auch das zu entfernen, lösche alles mit dem
Tag `chat:<id>`. Siehe [Lesen und ändern](/de/docs/memory#lesen-und-ändern).

## Wenn ein Server stoppt

Ein Turn läuft in einem Server-Prozess. Solange er läuft, markiert der Server
seinen Chat alle 30 Sekunden. Jede Minute sieht OpenBot alle Chats an:

- Ein Turn, der sagt, dass er läuft, dessen Chat aber seit 2 Minuten keine
  Markierung hat, gehört zu einem Server, der gestoppt ist. OpenBot beendet ihn
  als `Interrupted`. Ein Werkzeugaufruf ohne Ergebnis bekommt ein Ergebnis, das
  sagt, dass das Ergebnis nicht verfügbar ist. Eingaben, die der Turn nicht
  gelesen hat, gehen zurück in die Inbox.
- Ein Chat mit Eingaben in seiner Inbox und ohne laufenden Turn bekommt einen
  neuen Turn.

So geht keine Eingabe verloren, wenn ein Server stoppt, und kein Chat bleibt
hängen.

Alle Felder findest du in der
[Chats-Referenz](/docs/api/operations/tags/chats/).
