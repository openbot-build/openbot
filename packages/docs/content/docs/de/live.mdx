  In Echtzeit mit einem Bot sprechen. Ton geht über einen WebSocket hin und
  zurück.
---

Im **Live-Modus** spricht eine Person in Echtzeit mit einem Bot. Der Client
schickt den Ton der Person, und der Bot antwortet mit Ton und Text. Die Person
kann sprechen, während der Bot spricht, und der Bot hört auf.

Der Live-Modus nutzt einen **WebSocket**: eine Verbindung, die offen bleibt und
Nachrichten in beide Richtungen trägt. OpenBot ist in der Mitte. Es verbindet
sich mit einem **Live-Model**, etwa einem Model der OpenAI Realtime API, und
hält den Schlüssel des Anbieters auf dem Server.

Der Live-Modus läuft in einem [Chat](/de/docs/chats) mit
`execution.mode: "live"`. Ein direkter Chat kann zwischen Chat- und
Live-Ausführung wechseln. Bot, Chat-ID, Verlauf, Werkzeuge, Rules und Memory
bleiben gleich. Jede gesprochene Eingabe wird zu einem normalen Turn. Der Chat
speichert Transkripte und Bilder aus der Session, aber keine Tonaufnahmen.

---

## Ein Live-Model hinzufügen

Ein Live-Model ist ein Model mit dem Typ `live`. Füge es hinzu und verknüpfe es
mit einem Anbieter, der ein Live-Backend hat. Heute haben nur `openai`-Anbieter
eines: die OpenAI Realtime API. Siehe [Models](/de/docs/models).

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{ "id": "gpt-realtime", "type": "live", "name": "GPT Realtime", "reasoningEfforts": [], "serviceTiers": [] }' \
  https://api.example.com/v1/organization/models
```

Verknüpfe dann `gpt-realtime` mit einem `openai`-Anbieter. Die Live-Ausführung
nutzt ein Live-Model, die Chat-Ausführung ein Sprach-Model. Der Wechsel wählt
die passende Art von Model, ohne einen anderen Chat anzulegen.

## Einen Live-Chat anlegen

`POST /v1/bots/:botId/live` legt einen neuen Live-Chat von dir mit einem Bot an.
Du brauchst `bots.delegate` auf dem Bot und `models.use` auf dem Live-Model.
Jeder Aufruf legt einen neuen Chat an, so kann jedes Gespräch seinen eigenen
Verlauf haben.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{}' \
  https://api.example.com/v1/bots/$BOT_ID/live
```

| Feld    | Regeln                                                                                         |
| ------- | ---------------------------------------------------------------------------------------------- |
| `model` | Optional. Ein Live-Model, als `{ "provider": "…", "model": "…" }`. Der Standard ist das erste. |

Die Antwort ist der neue Chat, mit `201`. Sein `settings.model` ist das
Live-Model und sein `execution.mode` ist `live`. `PATCH /v1/chats/:chatId`
ändert das Model innerhalb der gewählten Ausführung. Nutze die folgende Route,
um zur Chat-Ausführung zu wechseln. Ohne Live-Model gibt OpenBot `409` mit
`LiveUnavailable` zurück.

Ein Live-Chat ist in der Liste von `GET /v1/chats`, und
`DELETE /v1/chats/:chatId` löscht ihn.

## Einen bestehenden Chat umschalten

Mit `PUT /v1/chats/:chatId/execution` wechselst du einen ruhenden Chat der Art
`direct` oder `live`. Lies zuerst den Chat und sende seine aktuelle Revision:

```json
{
	"expected": 4,
	"mode": "live",
	"model": {
		"_tag": "Config.Selection",
		"provider": "openai",
		"model": "gpt-realtime"
	}
}
```

Du brauchst `write` und `run` auf dem Chat, das Recht zur Delegation an seinen
Bot und `models.use` auf dem Ziel-Model. `model` ist optional: OpenBot merkt
sich das letzte Model jeder Ausführungsart. Ohne gespeicherte Auswahl nutzt Chat
das Model des Bots und Live das erste verfügbare Live-Model.

Die Antwort ist die aktualisierte Chat-Ansicht. `chat.execution` enthält `mode`,
`generation`, `phase` und die gespeicherten Auswahlen `chatModel` und
`liveModel`. `kind` und Chat-ID bleiben gleich. Die Auswahl von Live öffnet
keinen Socket und startet keinen Turn. Verbinde dich erst nach dem Wechsel. Für
die Rückkehr zu Chat wartest du auf das Ende der laufenden Arbeit und sendest
`mode: "chat"` mit einer neuen Revision.

Ein laufender Turn, eine offene Freigabe, ein ungeklärter Werkzeugvorgang, eine
beschäftigte Live-Verbindung oder ein anderer Wechsel blockiert die Änderung.
OpenBot prüft auch, ob das Ziel-Model den gespeicherten Kontext lesen kann. Eine
blockierte Änderung ergibt `409` mit `ChatExecutionBlocked`, `reason`, `message`
und zugehörigen `ids`. Die alte Ausführung bleibt gewählt. Lies vor einem neuen
Versuch den aktuellen Chat. Sende keine Nachricht oder Werkzeugoperation erneut,
um einen Wechsel wiederherzustellen. Eine ruhende Live-Verbindung kann
umgeschaltet werden; ihre Generation wird ungültig und sie kann keine neue
Arbeit starten.

Wartender Klartext kann an die gewählte Ausführung gehen, auch nach einer
Live-Trennung. Die Reihenfolge bleibt gleich; nichts wird erneut gesendet. Live
wartet auf eine bereite Verbindung, Chat startet die Eingaben nach dem Wechsel.
Dateien, die schon warten, werden für das Ziel-Model mitgeprüft. Eingaben zur
Fortsetzung von Werkzeugen müssen vorher enden. Auch Text, der während der
Prüfung ankommt, bleibt für die gewählte Ausführung. Neue Bilder oder andere
Kontextänderungen während der Prüfung können den Wechsel blockieren. Die Eingabe
bleibt bei der ursprünglichen Ausführung und geht nicht verloren.

Bei vorhandenem gemeinsamem Verlauf muss das Ziel ein konfiguriertes
`contextWindow` haben. Ein unbekanntes Fenster blockiert den Wechsel. OpenBot
schätzt die Tokens des aufgelösten Kontexts mit dem Kernverfahren und weist
Schätzungen über dem Eingabebudget zurück. Der Wechsel kompaktiert den Verlauf
nicht. Die Schätzung und die Bestätigungen der Verlaufseinträge sind keine
genaue Tokengarantie; der Anbieter kann eine Antwort weiterhin ablehnen.

## Verbinden

Öffne einen WebSocket auf `GET /v1/chats/:chatId/live`. Du brauchst `run` auf
dem Chat. Der Chat muss `execution.mode: "live"` gewählt haben. Das Model ist
das ausgewählte Live-Model des Chats.

| Query           | Regeln                                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------------------ |
| `voice`         | Optional. Eine Stimme aus `capabilities.voices`.                                                             |
| `inputFormat`   | Optional. Der Ton, den der Client schickt, etwa `pcm16@24000`. Der Standard ist das erste Format des Models. |
| `outputFormat`  | Optional. Der Ton, den der Client zurück haben will. Der Standard ist das erste Format des Models.           |
| `turnDetection` | Optional. `server`: Das Model hört, wann die Person aufhört. `client`: Push-to-talk.                         |
| `organization`  | Optional. Die Organisation einer Browser-Session, wenn das Konto mehr als eine hat.                          |

Ein Programm schickt `Authorization: Bearer <token>`. Ein Browser schickt das
Session-Cookie. Dann muss die Seite auf dem öffentlichen Origin von OpenBot
sein. Sonst gibt OpenBot `403` mit `ForbiddenOrigin` zurück, so kann eine Seite
auf einer anderen Website dein Cookie nicht nutzen. Ein Browser kann bei einem
WebSocket den Header `OpenBot-Organization` nicht schicken. Wenn das Konto
Mitglied in mehr als einer Organisation ist, schickt er die ID darum in
`organization`. Ohne sie gibt OpenBot `400` mit `OrganizationRequired` zurück.

OpenBot prüft die Anfrage, bevor es den Socket öffnet. Es gibt `409` mit
`LiveUnavailable` zurück, wenn der Chat keine Live-Ausführung gewählt hat, oder
wenn das Model das Format, die Stimme oder die Turn-Erkennung nicht hat, nach
der du fragst.

```ts
const socket = new WebSocket(
	"wss://api.example.com/v1/chats/" + chatId + "/live?voice=marin",
)
socket.binaryType = "arraybuffer"
socket.onmessage = (event) => {
	if (typeof event.data === "string") console.log(JSON.parse(event.data))
	else play(new Uint8Array(event.data))
}
```

## Nachrichten

Ein **Text-Frame** hat eine JSON-Nachricht. Ein **Binär-Frame** hat Ton. Der
Client schickt Ton im Eingabeformat, und OpenBot schickt Ton im Ausgabeformat.
`pcm16` ist 16-Bit-PCM mit Vorzeichen, Little Endian und einem Kanal.

Das Protokoll ist für jedes Live-Model gleich. Die erste Nachricht sagt dem
Client, was das Model kann.

### Von OpenBot

| `type`                    | Bedeutung                                                                                                                                                           |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `session.ready`           | Die Session ist offen. Sie hat `provider`, `model`, `capabilities`, `audio`, `turnDetection` und `voice`.                                                           |
| `input.speech.started`    | Die Person hat angefangen zu sprechen.                                                                                                                              |
| `input.speech.stopped`    | Die Person hat aufgehört zu sprechen.                                                                                                                               |
| `input.transcript`        | Text dessen, was die Person gesagt hat. `final` ist `true` für den ganzen Text.                                                                                     |
| `output.transcript.delta` | Ein Teil des Textes der Antwort.                                                                                                                                    |
| `output.done`             | Das Antwort-Item `itemId` hat keinen Ton und keinen Text mehr.                                                                                                      |
| `output.stop`             | Die Person spricht wieder. Hör jetzt auf, die Antwort abzuspielen.                                                                                                  |
| `turn.started`            | Ein Turn hat angefangen. Er hat `turnId`.                                                                                                                           |
| `turn.completed`          | Der Turn ist zu Ende. `status` ist `Completed`, `Failed` oder `Interrupted`.                                                                                        |
| `error`                   | Etwas ist schiefgegangen. Es hat `code` und `message`. Die Session bleibt offen, außer die Verbindung zum Model endet oder OpenBot kann dem Chat nicht mehr folgen. |

### Vom Client

| `type`               | Bedeutung                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------- |
| `input.text`         | Getippter Text. Er startet einen Turn, wie Sprache.                                            |
| `input.image`        | Ein Bild, etwa ein Frame eines Videos. `data` ist Base64. Nur wenn `inputs.image` wahr ist.    |
| `input.audio.commit` | Die Person hat aufgehört zu sprechen. Nur mit der Turn-Erkennung `client`.                     |
| `input.audio.clear`  | Den Ton vergessen, der noch nicht committet ist.                                               |
| `response.cancel`    | Die Antwort und ihren Turn stoppen.                                                            |
| `output.truncate`    | Die Person hat die Antwort `itemId` nur bis `audioEndMs` gehört. Nur wenn `truncate` wahr ist. |

### Fähigkeiten

`capabilities` in `session.ready` sagt, was das Live-Model kann:

| Feld                 | Bedeutung                                                                |
| -------------------- | ------------------------------------------------------------------------ |
| `audio`              | Die Formate für `input` und `output`.                                    |
| `turnDetection`      | `server`, `client` oder beide.                                           |
| `inputTranscription` | Das Model gibt den Text dessen, was die Person sagt.                     |
| `tools`              | Das Model kann die Werkzeuge des Bots aufrufen.                          |
| `interruption`       | Das Model kann eine laufende Antwort stoppen.                            |
| `truncate`           | Das Model kann den Teil einer Antwort vergessen, der nicht gehört wurde. |
| `inputs`             | `text` und `image` sagen, welche anderen Eingaben das Model nimmt.       |
| `voices`             | Die Stimmen des Models.                                                  |

Wenn der Client eine Nachricht schickt, die das Model nicht kann, schickt
OpenBot einen `error` mit dem Code `unsupported`. Für Bilder nennt
`inputs.imageMediaTypes` die genauen akzeptierten MIME-Typen. Eine fehlende
Liste bedeutet keine Bildunterstützung.

## Turns und Verlauf

Wenn die Person aufhört zu sprechen, schreibt das Model den Text dessen, was sie
gesagt hat. Dann gibt OpenBot diesen Text dem Chat. Wenn der Bot frei ist,
startet er einen Turn. Die Antwort kommt als Ton, und ihr Text geht in den Turn.

Der Turn ist ein normaler Turn der Person: Der Bot nutzt seine Anweisungen,
Werkzeuge, [Freigaben](/de/docs/requests) und [Rules](/de/docs/rules). Du kannst
ihn mit `GET /v1/chats/:chatId/turns` lesen, und andere Clients sehen ihn mit
`GET /v1/chats/:chatId/wait`. Die Nutzung des Live-Models geht in die
[Nutzung](/de/docs/usage), wie bei anderen Aufrufen von Models. Ton-Tokens
zählen in den Summen für Eingabe und Ausgabe.

Vor `session.ready` lädt OpenBot den gespeicherten Kontext in das Live-Model und
wartet auf die Bestätigung des Anbieters. Dazu gehören Text von User und
Assistent, Transkripte, abgeschlossene Werkzeugaufrufe mit Ergebnissen,
Freigabeentscheidungen als reine Verlaufsdaten und unterstützte Bilder. Das
Laden erzeugt keine Antwort, führt kein Werkzeug aus und erteilt keine Freigabe.
Es ist nicht auf die letzten 40 Nachrichten begrenzt. Anbieterspezifische
Reasoning-Daten und undurchsichtige Kompaktierungsdaten werden nicht zwischen
Models übertragen. Bei Bedarf baut OpenBot portablen Kontext aus dem
aufbewahrten Verlauf auf.

Dateien werden über den Dateidienst von OpenBot aufgelöst. Der
OpenAI-Live-Adapter kann User-Bilder laden, aber keine Anhänge wie PDFs
vollständig übernehmen. Nicht unterstützte Teile, unlesbare Dateien,
unvollständige Werkzeugdaten, Ablehnung durch den Anbieter oder fehlende
Ladebestätigungen lassen die Verbindung scheitern. OpenBot startet nicht mit
leerem Kontext und ersetzt Dateien nicht still durch Zusammenfassungen. Der
OpenAI-Adapter schaltet das automatische Kürzen des Anbieters aus. Der Kontext
muss trotzdem in das Fenster des Ziel-Models passen; der Anbieter kann einen zu
großen Verlauf ablehnen.

Beim Wechsel zurück zu einem Sprach-Model muss dessen `inputMediaTypes` die
genauen MIME-Typen der Bilder und Dateien im Verlauf enthalten. Eine leere Liste
bedeutet nur Text. Eine fehlende Liste beweist keine Medienunterstützung.
OpenBot leitet sie nicht aus dem Model-Namen ab. Setze diese Angaben beim
Hinzufügen des Models.

Ein Chat kann zur selben Zeit eine Live-Session haben. Nur die gewählte
Ausführung kann seine Turns starten. Eine Generationsprüfung weist alte
Verbindungen nach einem Wechsel zurück. Im Live-Modus warten andere Eingaben im
Chat, bis eine Session offen ist. Das gilt für eine Nachricht von
`POST /v1/chats/:chatId/messages`, das Ergebnis einer
[Delegation](/de/docs/delegation) und die Antwort auf eine Anfrage. Wenn die
Session öffnet, führt OpenBot die wartenden Eingaben aus. Der Client bekommt
`turn.started` und `turn.completed` für jeden Turn des Chats, auch für Turns,
die er nicht gestartet hat.

Wenn die Person während einer Antwort spricht, schickt OpenBot `output.stop`,
stoppt die Antwort und stoppt den Turn.

Die Antwort beginnt, wenn der Text der Sprache fertig ist. Das dauert kurz, aber
dann hat der Verlauf des Chats dieselben Worte, die die Person gesagt hat.

## Ein Live-Backend hinzufügen

Ein **Live-Backend** verbindet OpenBot mit einer Art von Live-Dienst. Alles
andere im Live-Modus arbeitet mit jedem Backend. So fügst du eines hinzu:

1. Schreib ein Modul, das ein `LiveBackend` aus
   `packages/openbot/src/models/LiveBackends.ts` gibt. Sein `make` gibt ein
   `LiveModel` aus `@openbot-build/core/Live`.
2. Sag in `capabilities`, was der Dienst kann. OpenBot schickt nie eine Eingabe,
   die das Backend nicht kann. Gib bei `inputs.image: true` die akzeptierten
   Bild-MIME-Typen in `inputs.imageMediaTypes` an.
3. Bilde die Werte von `Live.Input` auf die Nachrichten des Dienstes ab, und die
   Nachrichten des Dienstes auf Werte von `Live.Event`.
4. Implementiere `Connection.loadContext(prompt)`. Prüfe alle Prompt-Teile und
   warte, bis der Anbieter jeden Verlaufseintrag angenommen hat. Die Methode
   darf keine Antwort starten, kein Werkzeug ausführen und nichts still
   weglassen. Ohne sie kann ein Backend keine Session mit gemeinsamem Kontext
   öffnen. Nutze `Live.contextOf` und `Live.validateContext`, wenn das Backend
   deren portable Darstellung von Text, Bildern und Werkzeugen unterstützt.
5. Füge das Backend zu `layerLiveBackends` in
   `packages/openbot/src/app/OpenBot.ts` hinzu.

`packages/openbot/src/providers/openai/OpenAiRealtime.ts` ist das Backend für
die OpenAI Realtime API. Nimm es als Beispiel.

Ein Dienst, der den Text der Sprache nicht gibt, kann den Verlauf des Chats
nicht halten. OpenBot öffnet mit so einem Model noch keine Session.
