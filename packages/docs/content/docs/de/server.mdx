Für Entwickler. Wähle im [Entwicklerhandbuch](/de/developers) zwischen
API-Anbindung, App-Veröffentlichung und Projektarbeit.

Das Programm `openbot` deckt die meisten Bedürfnisse ab. Wenn du mehr brauchst,
kannst du OpenBot aus deinem eigenen Programm starten. Dann kannst du eigene
Models, Werkzeuge, Routen und Quellen für den App Index hinzufügen.

OpenBot ist mit [Effect](https://effect.website) gebaut. Du baust es aus Layers
zusammen. Ein Layer ist ein Rezept in Effect, das Dienste baut. Wenn du einen
Layer erstellst, öffnet das weder das Netzwerk noch die Datenbank. Das passiert
erst, wenn du ihn startest.

---

## Das kleinste Programm

Dieses Programm macht dasselbe wie `openbot`:

```ts
import { Host, Launch } from "@openbot-build/openbot"

Launch.main(Host.layer)
```

`Launch.main` liest zuerst die Kommandozeile. Mit `--help` zeigt es die Hilfe
und endet. Dafür braucht es keine Einstellungen. Dann liest es die Variablen aus
[Konfiguration](/de/configuration), aus der Umgebung oder aus geheimen Dateien.
Es sperrt ausgehende Verbindungen zu privaten Adressen und schreibt einen
fehlgeschlagenen Start ins Log. Dann führt es den Layer aus, den du ihm gibst,
bis der Prozess endet. Es gibt diesem Layer die Node.js-Dienste und den
Fetch-HTTP-Client. `Launch.server` ist dasselbe Programm als Effect, wenn du es
selbst ausführst. Gib ihm `NodeServices.layer` und `NodeCrypto.layer`.

`Launch.settings` liest dieselben Einstellungen: `host`, `port`, `databaseUrl`,
`secretKeys`, `clusterSecret`, `clusterHost`, `outboundAllow` und `pluginsFile`.
Du kannst diese Werte auch im Code schreiben.

Das Programm braucht trotzdem eine Plattform. Führe das Einrichtungsprogramm
einmal aus, bevor Menschen es nutzen. Siehe [Platform](/de/platform#setup).

## Was das Paket exportiert

Das Paket exportiert vier Namensräume und die Programme (`openbot-server`,
`openbot-migrate`, `openbot-setup` und `openbot-inspect`). Sonst exportiert es
nichts.

| Export                                                       | Was es ist                                                                                                                                                    |
| ------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Host.layer(options)`                                        | OpenBot mit eigenem Node.js-HTTP-Server. `openbot-server` führt ihn aus.                                                                                      |
| `Host.layerApp(options)`                                     | Die Routen und Dienste von OpenBot, für einen HTTP-Server, den du schon hast.                                                                                 |
| `Host.Options`, `Host.AppOptions`                            | Die Optionen von `Host.layer` und von `Host.layerApp`. Siehe [Optionen](#optionen).                                                                           |
| `Host.routes(work)`, `Host.startup(work)`                    | Deine eigenen Routen und deine eigene Arbeit beim Start, mit den Diensten von Plugins, die sie brauchen. Siehe [Deine eigenen Routen](#deine-eigenen-routen). |
| `Host.Outside`, `Host.RouteServices`, `Host.StartupServices` | Die Dienste von außen und die Dienste des Hosts, die deine Routen und deine Arbeit beim Start nutzen können.                                                  |
| `Launch.main(make)`, `Launch.server(make)`                   | Führt den Layer von `make` so aus, wie `openbot-server` es tut.                                                                                               |
| `Launch.settings`, `Launch.Settings`                         | Liest die Einstellungen eines Servers aus Umgebungsvariablen und geheimen Dateien, und ihr Typ.                                                               |
| `Launch.StartFailed`                                         | Der Fehler eines Starts, der fehlschlägt. Siehe [Der Plugin-Host](#der-plugin-host).                                                                          |
| `Preset`                                                     | Die Tabelle der Plugins von OpenBot (`plugins`), ihre Einträge für den Loader (`entries`) und die Plugins, die aktiv sein müssen (`required`).                |
| `Wallets`                                                    | Der Dienst für Guthaben-Operationen (`Wallets.Wallets`). Deine Routen können ihn nutzen.                                                                      |

Der Entwicklungsserver (`@openbot-build/server-development`) und die Test-Helfer
(`@openbot-build/server-testing`) bauen nur auf diesen Exporten auf. Siehe
[Den Entwicklungsserver starten](#den-entwicklungsserver-starten) und
[Testserver im Code](/de/developers/testing#testserver-im-code).

## Optionen

`Host.layer` nimmt Instanz-Optionen, Anmelde-Optionen und App-Optionen.
`Host.layerApp` nimmt die Instanz-Optionen und die App-Optionen, aber nicht
`host` und `port`, weil es keinen eigenen HTTP-Server hat. Es nimmt auch keine
Anmelde-Optionen.

### Instanz-Optionen

| Option          | Typ                | Was es ist                                                                                                 |
| --------------- | ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `host`          | `string`           | Pflicht. Die Adresse, auf der der Server hört, zum Beispiel `127.0.0.1`.                                   |
| `port`          | `number`           | Pflicht. Der Port, auf dem der Server hört, zum Beispiel `3000`.                                           |
| `databaseUrl`   | `Redacted<string>` | Pflicht. Die PostgreSQL-URL.                                                                               |
| `secretKeys`    | `Redacted<string>` | Pflicht. Die Liste der geheimen Schlüssel. Siehe [Geheime Schlüssel](/de/configuration#geheime-schlüssel). |
| `clusterSecret` | `Redacted<string>` | Erforderlich. Mindestens 32 Zeichen. Alle Knoten nutzen dasselbe Geheimnis für private RPC.                |
| `clusterHost`   | `string`           | Optional. Die von anderen Knoten erreichbare Adresse. Standard ist die gebundene HTTP-Adresse.             |
| `pluginsFile`   | `string`           | Optional. Der Pfad der Plugin-Datei. Siehe [Plugins](/de/plugins) und [Der Plugin-Host](#der-plugin-host). |

### Anmeldung

Ohne die Option `auth` liest der Server den öffentlichen Origin, den Anbieter
der Plattform und das Anmelde-Geheimnis aus den
[Plattform-Einstellungen](/de/platform#einstellungen-der-platform).

- Vor der Einrichtung antwortet jede Route außer `/health` mit `503` und
  `SetupRequired`.
- OpenBot liest diese Einstellungen jedes Mal, wenn es sie braucht. Wenn sich
  eine davon ändert, nutzt schon die nächste Anfrage den neuen Wert. Der Server
  wird nur einmal gebaut, also gehen laufende Anfragen und Turns weiter.

Die Option `auth` von `Host.layer` gibt eine Anmelde-Konfiguration. Beim Start
schreibt der Server den öffentlichen Origin, das Anmelde-Geheimnis und den
Anbieter von `auth` in die Plattform-Einstellungen. Danach arbeitet er wie ohne
`auth`, also wirkt auch eine spätere Änderung der Plattform-Einstellungen
sofort. Wenn `auth` im Entwicklungsmodus ist, nutzt der Server das lokale
Testkonto, und er hält seinen App Index getrennt vom öffentlichen. Tests und der
Entwicklungsserver nutzen diese Option. Zwei weitere Optionen gehören zu `auth`:
`platformAdmins` gibt die Admins einer neuen Plattform, und `fileStorage` gibt
den Objektspeicher für Dateien.

### App-Optionen

| Option      | Was sie tut                                                                                                                                                                                                                  |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `entries`   | Die Einträge des Plugin-Loaders. Standard ist `Preset.entries`. Ein Test kann hier eigene Plugins hinzufügen.                                                                                                                |
| `plugins`   | Weitere Plugins, die die Einträge über ihren Modulnamen nennen können. Die Plugins des Presets gehen vor.                                                                                                                    |
| `hostTools` | Die Werkzeuge, die dein Programm jedem Chat gibt. Siehe [Ein Werkzeug hinzufügen](#ein-werkzeug-hinzufügen).                                                                                                                 |
| `outside`   | Ein Layer mit Diensten von außen, die an die Stelle der echten treten. Seine Fehler und die Dienste, die er braucht, gehen in den Typ des Server-Layers. Siehe [Dienste, die OpenBot braucht](#dienste-die-openbot-braucht). |
| `work`      | Deine eigenen Routen und deine Arbeit beim Start. Mache jedes Stück mit `Host.routes` oder `Host.startup`. Siehe [Deine eigenen Routen](#deine-eigenen-routen).                                                              |

Werte, die alle Instanzen teilen, sind Einstellungen in der Datenbank, keine
Optionen. Das Timing der Arbeit des App Index ist die Konfiguration des Plugins
`apps` in der Plugin-Datei: `{ intervalMs, retryMs }`. Siehe
[Plugins](/de/plugins).

## Dienste, die OpenBot braucht

`Host.layer` und `Host.layerApp` bauen die Dienste, die OpenBot braucht, aber
nicht die Plattform-Dienste. Mit zwei Optionen kann dein Programm eigene Dienste
an die Stelle der Standard-Dienste setzen. So kann ein Test Fälschungen geben,
und dein Programm kann seine eigenen geben.

| Dienste                             | Was sie sind                                                                                                                                                                                                                                     | Standard                                                                                                                         |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------- |
| Geteilte Dienste                    | Der Datenbank-Pool, die geheimen Schlüssel und die geteilten Einstellungen.                                                                                                                                                                      | Aus `databaseUrl` und `secretKeys` gebaut.                                                                                       |
| Dienste von außen (`Host.Outside`)  | Die Treiber der Computer-Anbieter, die Live-Backends, die Leser von Passwort-Managern, das Netzwerk und die Prüfung von Apps, die DNS-Prüfung von Domains, das öffentliche Netzwerk des App Index, die Suche nach Apps und der Versand von Mail. | Die echten Dienste, im Netzwerk des Prozesses, mit der Adressregel des Outbound-Schutzes. Mail geht über SMTP. Option `outside`. |
| Eingebaute Models (`BuiltinModels`) | Models, die jede Organisation nutzen kann, im Code gegeben. Siehe [Models](/de/models#eingebaute-models). Es ist auch ein Dienst von außen.                                                                                                      | Keine. Gib `Layer.succeed(BuiltinModels, models)` im Layer `outside`.                                                            |
| Werkzeuge des Hosts (`HostTools`)   | Die Werkzeuge, die dein Programm jedem Chat gibt.                                                                                                                                                                                                | `HostTools.none`. Option `hostTools`.                                                                                            |
| Plattform-Dienste                   | Dateien, Pfade, Zufallszahlen, Digests und der HTTP-Client.                                                                                                                                                                                      | Keine. Gib `NodeServices.layer`, `NodeCrypto.layer` und `FetchHttpClient.layer`.                                                 |

Der Layer `outside` kann nur einen Teil der Dienste von außen geben. Für jeden
Dienst, den er nicht gibt, behält der Host den echten Dienst. Der Layer
`outside` kann die geteilten Dienste nutzen, zum Beispiel die Einstellungen und
den Datenbank-Pool.

`Launch.main` gibt die Plattform-Dienste. Dieses Programm macht dasselbe wie
`Launch.main(Host.layer)`, mit den Werkzeugen des Hosts im Blick:

```ts
import { Host, Launch } from "@openbot-build/openbot"
import * as HostTools from "@openbot-build/tools-contract/HostTools"

Launch.main((settings) =>
	Host.layer({ ...settings, hostTools: HostTools.none }),
)
```

## Chats

Models kommen von den Model Providers in der Datenbank und aus dem Dienst
`BuiltinModels`. Siehe [Models](/de/models). [Bot Memory](/de/developers/memory)
folgt `botMemory` in den
[Organisations-Einstellungen](/de/organization#einstellungen).

Der Server hält Dienste der Anwendung und aktive Ausführungen. Jeder Turn baut
Model und Werkzeuge in seinem eigenen Scope. Die gespeicherte Identität hält
Mitglied, ursprüngliches Token, Bot und die Grenzen der Delegation. Anfragen
halten keine Laufzeit eines Mitglieds offen. Pro Chat darf ein Turn zugleich
vorankommen. Befehle, gespeicherte Schritte, Ereignisse und Ergebnisse bleiben
über Knoten und Neustarts hinweg in PostgreSQL. Das Schließen eines HTTP-Streams
beendet die Beobachtung. Ein Abbruch braucht einen eigenen Befehl.

### Ein Werkzeug hinzufügen

Ein Werkzeug (Tool) ist eine Funktion, die das Model aufrufen kann. Erstelle es
mit Effect AI. Gib dann das Toolkit und seine Handler mit `HostTools.layer` an
OpenBot. Jeder Turn jedes Chats kann das Werkzeug aufrufen. `handlers` bekommt
die ID des Chats und gibt die Handler für seine Turns. Jeder Turn baut sie, wenn
er startet, und schließt sie, wenn er endet.

```ts
import { Host, Launch } from "@openbot-build/openbot"
import * as HostTools from "@openbot-build/tools-contract/HostTools"
import { DateTime, Effect, Schema } from "effect"
import { Tool, Toolkit } from "effect/ai"

const CurrentTime = Tool.make("CurrentTime", {
	description: "Returns the current time on the server.",
	parameters: Schema.Struct({}),
	success: Schema.String,
})
const toolkit = Toolkit.make(CurrentTime)
const handlers = toolkit.toLayer({
	CurrentTime: () => Effect.map(DateTime.now, DateTime.formatIso),
})

Launch.main((settings) =>
	Host.layer({
		...settings,
		hostTools: HostTools.layer({ toolkit, handlers: () => handlers }),
	}),
)
```

Füge `needsApproval: true` zu `Tool.make` hinzu, wenn jeder Aufruf eine
Entscheidung braucht. OpenBot prüft dann dafür die Fähigkeit `tools.call`. Wenn
der Aufruf einen Entscheider braucht, bekommt der Bot ein wartendes Ergebnis,
und der Aufruf läuft später, wenn er erlaubt wird. Siehe
[Requests](/de/developers/requests).

## Deine eigenen Routen

`Host.routes` fügt demselben Server HTTP-Routen hinzu. Es nimmt einen Namen, die
Schlüssel der Dienste von Plugins, die die Routen brauchen (`inject`), und einen
Layer mit den Routen. Der Layer kann die Dienste von `inject` und die Dienste
des Hosts in `Host.RouteServices` nutzen: den Router, den Datenbank-Pool, die
Einstellungen und die Ratenlimits. Injiziere zum Beispiel `Auth`, um das
Anmelde-Cookie zu prüfen, und `Wallets.Wallets` für Guthaben-Operationen.

```ts
import { Host, Launch, Wallets } from "@openbot-build/openbot"
import { Effect, Layer } from "effect"
import { HttpRouter, HttpServerResponse } from "effect/http"

const origin = Host.routes({
	name: "origin",
	inject: [Wallets.Wallets],
	layer: Layer.unwrap(
		Effect.map(Wallets.Wallets, (wallets) =>
			HttpRouter.add(
				"GET",
				"/origin",
				Effect.map(wallets.publicOrigin, (text) =>
					HttpServerResponse.text(text),
				).pipe(Effect.orDie),
			),
		),
	),
})

Launch.main((settings) => Host.layer({ ...settings, work: [origin] }))
```

Die Routen sind ein Fork des Hosts. Ein Fork ist ein Teil des Plugin-Hosts, der
für sich startet und stoppt. Er hängt die Routen ein, wenn jeder Schlüssel von
`inject` da ist. Wenn ein Plugin, das einen dieser Schlüssel gibt, neu startet,
nimmt der Fork die Routen weg und hängt sie mit den neuen Diensten wieder ein.
So nutzen die Routen immer die Dienste, die gerade laufen. Wenn ein Schlüssel
nie da ist, zum Beispiel weil die Plugin-Datei sein Plugin ausschaltet, startet
der Server nicht.

`Host.startup` fügt Arbeit hinzu, die beim Start des Servers läuft, zum Beispiel
das Indexieren einer App. Es nimmt dieselben drei Werte. Sein Layer kann die
Dienste von `inject` und die Dienste in `Host.StartupServices` nutzen. Es lebt
so lange wie die Routen, und es läuft wieder, wenn ein Plugin, das einen seiner
Schlüssel gibt, neu startet.

Nutze keine Pfade unter `/auth/` oder `/v1/`. Sie gehören OpenBot.

OpenBot bedient diese Routen mit einem eigenen Router. Router-Middleware in
diesem Layer, auch globale Middleware, wirkt nur auf diese Routen. Wenn eine
Route von OpenBot und eine deiner Routen auf dieselbe Anfrage passen, gewinnt
die Route von OpenBot. Das gilt auch für eine Wildcard-Route, wie `/*`. Sie
bekommt nur die Anfragen, die keine Route von OpenBot nimmt, auch bei `HEAD`.

## Deinen eigenen HTTP-Server nutzen

`Host.layerApp(options)` gibt die OpenBot-Routen und -Dienste, für einen
HTTP-Server, den du schon hast. Bediene es mit
`HttpRouter.serve(Host.layerApp(options))`. Es braucht die Plattform-Dienste und
deinen HTTP-Server.

`Host.layer` startet seinen eigenen Node.js-Server und legt eine Prüfung der
Plattform-Einstellungen um den Router. Solange die Plattform keine Einstellungen
hat, antwortet die Prüfung auf jede Route außer `/health` mit `503` und
`SetupRequired`. `Host.layerApp` hat diese Prüfung nicht. Füge dieselbe Prüfung
deinem Server als Router-Middleware hinzu. Lies
`packages/openbot/src/Serving.ts`, um zu sehen, wie `Host.layer` das macht.
Bewahre das Anmelde-Geheimnis in den Plattform-Einstellungen auf, nicht in
deiner eigenen Umgebungsvariable. Jede Instanz muss dasselbe nutzen.

## Der Plugin-Host

`Host.layer` und `Host.layerApp` führen OpenBot auf dem Plugin-Host aus. Jede
Funktion ist ein Plugin. Zum Plugin-Host siehe
[Ausführungsdesign](/de/architecture).

Der Layer ist bereit, wenn jedes Plugin und jeder Fork von `work` aktiv ist. Ein
fehlgeschlagener Start lässt den Layer mit `Launch.StartFailed` fehlschlagen.
Sein `reason` ist `RequiredPluginMissing`, `PluginsInactive`,
`PluginsFileInvalid` oder `PluginsFileUnreadable`. Seine `message` nennt die
Plugins oder die Probleme, und seine `cause` hält den vollen Fehler. Die volle
Ursache eines Plugin-Fehlers steht in den Fehlereinträgen. `Launch.main`
schreibt den Fehlschlag ins Log und stoppt den Prozess.

Die Layer geben die Dienste des Hosts, zum Beispiel den Datenbank-Pool und die
Einstellungen, und keinen Dienst eines Plugins. Arbeit, die einen Dienst eines
Plugins braucht, ist ein Fork von `work` und nennt die Schlüssel, die sie
braucht. Darum kann die Plugin-Datei jedes Plugin ausschalten, das nicht Pflicht
ist, auch in `Host.layer`. Schalte die Plugins mit aus, die es brauchen: Ohne
`bots` schalte zum Beispiel auch `chats` und jedes andere Plugin aus, das einen
Dienst von `bots` injiziert. Ein Plugin, das auf einen Dienst wartet, den kein
Plugin gibt, stoppt den Start. Siehe [Plugins](/de/plugins).

## Die Datenbank migrieren

Das Programm `openbot-migrate` führt alle Migrationen von `server-database` aus
und prüft dann das Schema. Es braucht nur `OPENBOT_DATABASE_URL`. Stoppe vorher
alle Instanzen. `Host.layer` und `Host.layerApp` prüfen das Schema, bevor sie
Dienste starten. Diese Version braucht eine neue Datenbank: Eine Migration
stoppt mit einem Fehler, wenn die Datenbank Daten einer älteren Version enthält.
Siehe [Deploy](/de/deploy#die-datenbank-vorbereiten).

```sh
pnpm --filter @openbot-build/openbot migrate
```

## Den Entwicklungsserver starten

`pnpm dev` startet den Entwicklungsserver. Er hat ein lokales Testkonto,
simulierte Models und eine simulierte App. Ein Projekt, das auf OpenBot aufbaut,
kann denselben Server aus seinem eigenen Programm starten:

```ts
import { NodeRuntime } from "@effect/platform-node"
import * as Development from "@openbot-build/server-development/Development"

NodeRuntime.runMain(Development.launch)
```

`Development.launch` liest dieselben Einstellungen wie `Launch.main` und
`OPENBOT_DEV_PUBLIC_ORIGIN`. Wenn die Variablen `OPENBOT_DEV_S3_*` gesetzt sind,
nutzt es diesen lokalen Objektspeicher für Dateien und legt seinen Bucket an.
`Development.layer` ist der Server ohne diese Schritte. Er ist `Host.layer` mit
simulierten Diensten von außen, simulierten Models und den Routen und der Arbeit
beim Start der simulierten App. Er braucht die Plattform-Dienste, zum Beispiel
`NodeServices.layer`, `NodeCrypto.layer` und `FetchHttpClient.layer`, und
`Development.launch` gibt sie ihm. Er schreibt die Plattform-Einstellungen
selbst. Darum braucht er kein Einrichtungsprogramm.
`Development.developmentSecret` macht das Anmelde-Geheimnis aus dem ersten
geheimen Schlüssel. So bleibt es nach einem Neustart gleich. `pnpm dev` startet
ihn aus dem Paket `server-development`. Nutze den Entwicklungsserver nie in der
Produktion. Jeder, der ihn erreicht, kann sich anmelden.

## Fehler-Logs an deinen eigenen Dienst senden

OpenBot schreibt Fehlschläge als Fehler-Logs. Füge deinen eigenen Effect-Logger
hinzu, um sie an einen anderen Dienst zu senden. Was jedes Log enthält, und ein
vollständiges Beispiel, findest du unter [Fehler-Logs](/de/error-logs).
