Für Entwickler. Wähle im [Entwicklerhandbuch](/de/developers) zwischen
API-Anbindung, App-Veröffentlichung und Projektarbeit.

Das Programm `openbot` deckt die meisten Bedürfnisse ab. Wenn du mehr brauchst,
kannst du OpenBot aus deinem eigenen Programm starten. Dann kannst du eigene
Models, Werkzeuge, Routen und Quellen für den App Index hinzufügen.

OpenBot ist mit [Effect](https://effect.website) gebaut. Du baust es aus Layers
zusammen. Ein Layer ist ein Rezept in Effect, das Dienste baut. Wenn du einen
Layer erstellst, öffnet das weder das Netzwerk noch die Datenbank. Das passiert
erst, wenn du ihn startest.

---

## Das kleinste Programm

Dieses Programm macht dasselbe wie `openbot`:

```ts
import { Host, Launch } from "@openbot-build/openbot"

Launch.main(Host.layer)
```

`Launch.main` liest zuerst die Kommandozeile. Mit `--help` zeigt es die Hilfe
und endet. Dafür braucht es keine Einstellungen. Dann liest es die Variablen aus
[Konfiguration](/de/configuration), aus der Umgebung oder aus geheimen Dateien.
Es sperrt ausgehende Verbindungen zu privaten Adressen und schreibt einen
fehlgeschlagenen Start ins Log. Dann führt es den Layer aus, den du ihm gibst,
bis der Prozess endet. Es gibt diesem Layer die Node.js-Dienste und den
Fetch-HTTP-Client. `Launch.server` ist dasselbe Programm als Effect, wenn du es
selbst ausführst. Gib ihm `NodeServices.layer` und `NodeCrypto.layer`.

`EnvironmentConfiguration.load` gibt dieselben Einstellungen zurück: `host`,
`port`, `databaseUrl`, `secretKeys`, `clusterSecret`, `clusterHost` und
`outboundAllow`. Du kannst diese Werte auch im Code schreiben.

Das Programm braucht trotzdem eine Plattform. Führe das Einrichtungsprogramm
einmal aus, bevor Menschen es nutzen. Siehe [Platform](/de/platform#setup).

## Optionen

`Host.layer` nimmt Instanz-Optionen, Anmelde-Optionen und App-Optionen.
`Host.layerApp` nimmt die Instanz-Optionen und die App-Optionen, aber nicht
`host` und `port`, weil es keinen eigenen HTTP-Server hat. Es nimmt auch keine
Anmelde-Optionen.

### Instanz-Optionen

| Option          | Typ                | Was es ist                                                                                                 |
| --------------- | ------------------ | ---------------------------------------------------------------------------------------------------------- |
| `host`          | `string`           | Pflicht. Die Adresse, auf der der Server hört, zum Beispiel `127.0.0.1`.                                   |
| `port`          | `number`           | Pflicht. Der Port, auf dem der Server hört, zum Beispiel `3000`.                                           |
| `databaseUrl`   | `Redacted<string>` | Pflicht. Die PostgreSQL-URL.                                                                               |
| `secretKeys`    | `Redacted<string>` | Pflicht. Die Liste der geheimen Schlüssel. Siehe [Geheime Schlüssel](/de/configuration#geheime-schlüssel). |
| `clusterSecret` | `Redacted<string>` | Erforderlich. Mindestens 32 Zeichen. Alle Knoten nutzen dasselbe Geheimnis für private RPC.                |
| `clusterHost`   | `string`           | Optional. Die von anderen Knoten erreichbare Adresse. Standard ist die gebundene HTTP-Adresse.             |

### Anmeldung

Ohne die Option `auth` liest der Server den öffentlichen Origin, den Anbieter
der Plattform und das Anmelde-Geheimnis aus den
[Plattform-Einstellungen](/de/platform#einstellungen-der-platform).

- Vor der Einrichtung antwortet jede Route außer `/health` mit `503` und
  `SetupRequired`.
- OpenBot liest diese Einstellungen jedes Mal, wenn es sie braucht. Wenn sich
  eine davon ändert, nutzt schon die nächste Anfrage den neuen Wert. Der Server
  wird nur einmal gebaut, also gehen laufende Anfragen und Turns weiter.

Die Option `auth` von `Host.layer` gibt eine Anmelde-Konfiguration. Beim Start
schreibt der Server den öffentlichen Origin, das Anmelde-Geheimnis und den
Anbieter von `auth` in die Plattform-Einstellungen. Danach arbeitet er wie ohne
`auth`, also wirkt auch eine spätere Änderung der Plattform-Einstellungen
sofort. Wenn `auth` im Entwicklungsmodus ist, nutzt der Server das lokale
Testkonto. Tests und der Entwicklungsserver nutzen diese Option. Zwei weitere
Optionen gehören zu `auth`: `platformAdmins` gibt die Admins einer neuen
Plattform, und `fileStorage` gibt den Objektspeicher für Dateien. Jeder Server
gibt die App-Dienste auch an dein Programm weiter, damit Tests sie nutzen
können.

### App-Optionen

| Option                       | Was sie tut                                                                                                                                                                                     |
| ---------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `builtinModels`              | Models, die jede Organisation nutzen kann, im Code angegeben. Siehe [Models](/de/models#eingebaute-models).                                                                                     |
| `builtinModels.defaultModel` | Das Model eines neuen Chats, wenn sein Bot keines nennt. Es ist eines aus `builtinModels`. Nur eine simulierte Plattform setzt es.                                                              |
| `routes`                     | Ein Layer mit deinen eigenen HTTP-Routen.                                                                                                                                                       |
| `indexSources`               | Weitere Quellen für die Suche im App Index, neben dem OpenBot Index.                                                                                                                            |
| `indexWork`                  | Zeitplan des App-Index-Workers: `{ intervalMs, retryMs }`.                                                                                                                                      |
| `startup`                    | Ein Layer mit Arbeit, die beim Start des Servers läuft.                                                                                                                                         |
| `mailTransport`              | Ein Layer mit deinem eigenen Mail-Dienst. Standard ist der Versand mit SMTP.                                                                                                                    |
| `hostTools`                  | Die Werkzeuge, die dein Programm jedem Chat gibt. Siehe [Ein Werkzeug hinzufügen](#ein-werkzeug-hinzufügen).                                                                                    |
| `outside`                    | Ein Layer mit den Diensten von außen. Seine Fehler und die Dienste, die er braucht, gehen in den Typ des Server-Layers ein. Siehe [Dienste, die OpenBot braucht](#dienste-die-openbot-braucht). |

Einige Werte waren früher Optionen. Jetzt sind sie Einstellungen in der
Datenbank. So teilen alle Instanzen sie:

| Alte Option           | Einstellung                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------- |
| `appRestrictions`     | `appRestrictions` in den [Plattform-Einstellungen](/de/platform#einstellungen-der-platform). |
| `appReadRules`        | `appReadRules` in den [Organisations-Einstellungen](/de/organization#einstellungen).         |
| `bots.helperModel`    | `rulesModel` und `botMemoryModel` in den Organisations-Einstellungen.                        |
| `bots.requestTimeout` | `requestTimeoutMs` in den Organisations-Einstellungen.                                       |
| `bots.memory`         | `botMemory` in den Organisations-Einstellungen.                                              |
| `appEncryptionKey`    | Die Instanz-Option `secretKeys`.                                                             |

## Dienste, die OpenBot braucht

`Host.layer` und `Host.layerApp` bauen die Dienste, die OpenBot braucht, aber
nicht die Plattform-Dienste. Mit zwei Optionen kann dein Programm eigene Dienste
an die Stelle der Standard-Dienste setzen. So kann ein Test Fälschungen geben,
und dein Programm kann eigene geben.

| Dienste                            | Was sie sind                                                                                                                                                                                                              | Standard                                                                                                                       |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| Gemeinsame Dienste                 | Der Datenbank-Pool, die geheimen Schlüssel und die gemeinsamen Einstellungen.                                                                                                                                             | Aus `databaseUrl` und `secretKeys` gebaut.                                                                                     |
| Dienste von außen (`Host.Outside`) | Die Treiber der Computer-Anbieter, die Live-Backends, die Leser der Passwort-Manager, das Netzwerk und die Prüfung der Apps, die DNS-Prüfung von Domains, das öffentliche Netzwerk des App Index und das Finden von Apps. | Die echten Dienste, im Netzwerk des Prozesses, mit der Adressregel des Schutzes für ausgehende Verbindungen. Option `outside`. |
| Werkzeuge des Hosts (`HostTools`)  | Die Werkzeuge, die dein Programm jedem Chat gibt.                                                                                                                                                                         | `HostTools.none`. Option `hostTools`.                                                                                          |
| Plattform-Dienste                  | Dateien, Pfade, Zufallszahlen, Hashwerte und der HTTP-Client.                                                                                                                                                             | Keiner. Gib `NodeServices.layer`, `NodeCrypto.layer` und `FetchHttpClient.layer`.                                              |

`Launch.main` gibt die Plattform-Dienste. Dieses Programm macht dasselbe wie
`Launch.main(Host.layer)`, und die Werkzeuge des Hosts sind zu sehen:

```ts
import { Host, HostTools, Launch } from "@openbot-build/openbot"

Launch.main((settings) =>
	Host.layer({ ...settings, hostTools: HostTools.none }),
)
```

Die Optionen `chats`, `discovery`, `computerDrivers`, `liveBackends`,
`vaultReaders`, `appProbe`, `appNetwork`, `domainControl` und
`indexPublicNetwork` gibt es nicht mehr. Gib an ihrer Stelle die Dienste im
Layer `outside`.

## Chats

Models kommen von den Model Providers in der Datenbank und aus `builtinModels`.
Siehe [Models](/de/models). [Bot Memory](/de/developers/memory) folgt
`botMemory` in den
[Organisations-Einstellungen](/de/organization#einstellungen).

Der Server hält Dienste der Anwendung und aktive Ausführungen. Jeder Turn baut
Model und Werkzeuge in seinem eigenen Scope. Die gespeicherte Identität hält
Mitglied, ursprüngliches Token, Bot und die Grenzen der Delegation. Anfragen
halten keine Laufzeit eines Mitglieds offen. Pro Chat darf ein Turn zugleich
vorankommen. Befehle, gespeicherte Schritte, Ereignisse und Ergebnisse bleiben
über Knoten und Neustarts hinweg in PostgreSQL. Das Schließen eines HTTP-Streams
beendet die Beobachtung. Ein Abbruch braucht einen eigenen Befehl.

### Ein Werkzeug hinzufügen

Ein Werkzeug (Tool) ist eine Funktion, die das Model aufrufen kann. Erstelle es
mit Effect AI. Gib dann das Toolkit und seine Handler mit `HostTools.layer` an
OpenBot. Jeder Turn jedes Chats kann das Werkzeug aufrufen. `handlers` bekommt
die ID des Chats und gibt die Handler für seine Turns. Jeder Turn baut sie, wenn
er startet, und schließt sie, wenn er endet.

```ts
import { Host, HostTools, Launch } from "@openbot-build/openbot"
import { DateTime, Effect, Schema } from "effect"
import { Tool, Toolkit } from "effect/ai"

const CurrentTime = Tool.make("CurrentTime", {
	description: "Returns the current time on the server.",
	parameters: Schema.Struct({}),
	success: Schema.String,
})
const toolkit = Toolkit.make(CurrentTime)
const handlers = toolkit.toLayer({
	CurrentTime: () => Effect.map(DateTime.now, DateTime.formatIso),
})

Launch.main((settings) =>
	Host.layer({
		...settings,
		hostTools: HostTools.layer({ toolkit, handlers: () => handlers }),
	}),
)
```

Füge `needsApproval: true` zu `Tool.make` hinzu, wenn jeder Aufruf eine
Entscheidung braucht. OpenBot prüft dann dafür die Fähigkeit `tools.call`. Wenn
der Aufruf einen Entscheider braucht, bekommt der Bot ein wartendes Ergebnis,
und der Aufruf läuft später, wenn er erlaubt wird. Siehe
[Requests](/de/developers/requests).

## Deine eigenen Routen

`routes` fügt demselben Server HTTP-Routen hinzu. Es ist ein Layer. Der Layer
kann den Dienst `Auth` nutzen, um das Anmelde-Cookie zu prüfen, und den Dienst
`Wallets` für Operationen mit Guthaben. `Host.RouteServices` nennt jeden Dienst,
den er nutzen kann.

```ts
import { HttpRouter, HttpServerResponse } from "effect/http"

const routes = HttpRouter.add(
	"GET",
	"/status",
	HttpServerResponse.text("ready"),
)

Host.layer({ ...settings, routes })
```

Nutze keine Pfade unter `/auth/` oder `/v1/`. Sie gehören OpenBot.

OpenBot bedient diese Routen mit einem eigenen Router. Router-Middleware in
diesem Layer, auch globale Middleware, wirkt nur auf diese Routen. Wenn eine
Route von OpenBot und eine deiner Routen auf dieselbe Anfrage passen, gewinnt
die Route von OpenBot. Das gilt auch für eine Wildcard-Route, wie `/*`. Sie
bekommt nur die Anfragen, die keine Route von OpenBot nimmt, auch bei `HEAD`.

## Deinen eigenen HTTP-Server nutzen

`Host.layerApp(options)` gibt die OpenBot-Routen und -Dienste, für einen
HTTP-Server, den du schon hast. Bediene es mit
`HttpRouter.serve(Host.layerApp(options))`. Es braucht die Plattform-Dienste und
deinen HTTP-Server.

`Host.layer` startet seinen eigenen Node.js-Server und legt eine Prüfung der
Plattform-Einstellungen um den Router. Solange die Plattform keine Einstellungen
hat, antwortet die Prüfung auf jede Route außer `/health` mit `503` und
`SetupRequired`. `Host.layerApp` hat diese Prüfung nicht. Füge dieselbe Prüfung
deinem Server als Router-Middleware hinzu. Lies
`packages/openbot/src/app/Serving.ts`, um zu sehen, wie `Host.layer` das macht.
Bewahre das Anmelde-Geheimnis in den Plattform-Einstellungen auf, nicht in
deiner eigenen Umgebungsvariable. Jede Instanz muss dasselbe nutzen.

## Der Plugin-Host

`Host.layer` und `Host.layerApp` führen OpenBot auf dem Plugin-Host aus. Jede
Funktion ist ein Plugin. Zum Plugin-Host siehe
[Ausführungsdesign](/de/architecture).

Der Layer ist bereit, wenn jedes Plugin aktiv ist. Ein fehlgeschlagener Start
stoppt den Prozess wie bisher: Der Layer endet mit dem Fehler, zum Beispiel
`RequiredPluginMissing` oder `PluginsInactive`. Der Fehler nennt die Plugins,
die nicht aktiv sind. Die volle Ursache eines Plugin-Fehlers steht in den
Fehlereinträgen.

Die Dienste, die diese Layer deinem Programm geben, sind die Dienste der Plugins
zur Zeit des Starts. Wenn ein Plugin später neu startet, ändert sich deine Kopie
nicht.

## Die Datenbank migrieren

`DatabasePostgres.migrate` bereitet das Schema und die erste Datenprüfung vor.
Nur eine leere Datenbank kann dadurch bereit sein. Nutze für ein vollständiges
Upgrade den Wartungsbefehl. Er braucht `OPENBOT_DATABASE_URL` und
`OPENBOT_SECRET_KEYS`. Stoppe vorher alle Instanzen. `Host.layer` und
`Host.layerApp` prüfen Schema und abgeschlossene Datenversion, bevor sie Dienste
starten. Ihre gemeinsame Sperre bleibt für die ganze Serverlaufzeit offen. Die
Schritte für Sicherung und Wiederherstellung stehen unter
[Deploy](/de/deploy#die-datenbank-vorbereiten).

```sh
pnpm --filter @openbot-build/openbot migrate
```

## Den Entwicklungsserver starten

`pnpm dev` startet den Entwicklungsserver. Er hat ein lokales Testkonto,
simulierte Models und eine simulierte App. Ein Projekt, das auf OpenBot aufbaut,
kann denselben Server aus seinem eigenen Programm starten:

```ts
import { NodeRuntime } from "@effect/platform-node"
import * as Development from "@openbot-build/openbot/Development"

NodeRuntime.runMain(Development.launch)
```

`Development.launch` liest dieselben Einstellungen wie `Launch.main` und
`OPENBOT_DEV_PUBLIC_ORIGIN`. Wenn die Variablen `OPENBOT_DEV_S3_*` gesetzt sind,
nutzt es diesen lokalen Objektspeicher für Dateien und legt seinen Bucket an.
`Development.layer` ist der Server ohne diese Schritte. Er braucht die
Plattform-Dienste, zum Beispiel `NodeServices.layer`, `NodeCrypto.layer` und
`FetchHttpClient.layer`, und `Development.launch` gibt sie ihm. Er schreibt die
Plattform-Einstellungen selbst. Darum braucht er kein Einrichtungsprogramm.
`Development.developmentSecret` macht das Anmelde-Geheimnis aus dem ersten
geheimen Schlüssel. So bleibt es nach einem Neustart gleich. Nutze den
Entwicklungsserver nie in der Produktion. Jeder, der ihn erreicht, kann sich
anmelden.

## Fehler-Logs an deinen eigenen Dienst senden

OpenBot schreibt Fehlschläge als Fehler-Logs. Füge deinen eigenen Effect-Logger
hinzu, um sie an einen anderen Dienst zu senden. Was jedes Log enthält, und ein
vollständiges Beispiel, findest du unter [Fehler-Logs](/de/error-logs).
