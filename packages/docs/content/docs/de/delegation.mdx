---
title: Delegation
description: Wie Bots anderen Bots Arbeit geben und die Ergebnisse zurückbekommen.
---

**Delegation** heißt: Ein Bot gibt eine Aufgabe an einen anderen Bot. Der andere Bot arbeitet in seiner eigenen Session, mit seinem eigenen Kontext. Nur ein kurzer Auftrag geht nach unten, und nur ein kurzes Ergebnis kommt zurück. So bleibt jeder Bot bei seiner eigenen Arbeit.
Diese Seite zeigt die Bot-Werkzeuge, den Auftrag und das Ergebnis, und wie du abgegebene Arbeit beobachtest.

---

## Die Bot-Werkzeuge

OpenBot gibt jedem Bot diese Werkzeuge:

| Werkzeug                    | Was es tut                                                                                                                   |
| --------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `openbot_list_bots`         | Listet die Bots auf, denen er Arbeit geben kann, mit ihren Rollen. Seine Session Bots sind dabei.                            |
| `openbot_bot_details`       | Liest die Rolle und die Anweisungen eines Bots.                                                                              |
| `openbot_delegate`          | Gibt einem anderen Bot eine Aufgabe und wartet auf das Ergebnis.                                                             |
| `openbot_start_session_bot` | Startet einen neuen [Session Bot](/de/docs/bots#drei-arten-von-bots) für seine Session.                                      |
| `openbot_create_bot`        | Erstellt einen neuen dauerhaften Bot, der ihm gehört. Siehe [Bots, die Bots besitzen](/de/docs/bots#bots-die-bots-besitzen). |
| `openbot_promote_bot`       | Macht einen Session Bot seiner Session zu einem dauerhaften Bot, der ihm gehört.                                             |
| `openbot_report`            | Nur bei abgegebener Arbeit. Schickt das Ergebnis zurück.                                                                     |

Wenn ein Bot zum ersten Mal einem anderen dauerhaften Bot Arbeit gibt, einen Session Bot startet, einen Bot erstellt oder einen dauerhaft macht, muss die Stelle über ihm zustimmen. Siehe [Requests](/de/docs/requests). Den Session Bots seiner Session und den Bots, die ihm gehören, kann ein Bot immer Arbeit geben.

---

## Der Auftrag

`openbot_delegate` nimmt einen Auftrag (Brief) an:

| Feld             | Bedeutung                                                                            |
| ---------------- | ------------------------------------------------------------------------------------ |
| `bot`            | Die ID des anderen Bots.                                                             |
| `reason`         | Warum der Bot das will. Eine entscheidende Stelle liest es, wenn sie zustimmen muss. |
| `task`           | Was zu tun ist.                                                                      |
| `userRequest`    | Die Worte der Person, unverändert. Ein Auftrag ersetzt sie nie.                      |
| `context`        | Kurze Fakten, die der andere Bot braucht.                                            |
| `references`     | Session- und Item-IDs, die der andere Bot lesen kann.                                |
| `constraints`    | Regeln für die Arbeit.                                                               |
| `expectedOutput` | Wie ein gutes Ergebnis aussieht.                                                     |
| `session`        | Optional. Frühere Arbeit dieses Bots in dieser Session fortsetzen.                   |

Der andere Bot bekommt den Auftrag als erste Nachricht eines Turns. Er sieht nie den Verlauf des Bots, der die Arbeit abgegeben hat.

### Welche Session die Arbeit nutzt

- Mit `session` geht die Arbeit in dieser Session weiter, wenn sie dem anderen Bot gehört und aus derselben Session gestartet wurde.
- Bei einem Session Bot geht die Arbeit in seiner neuesten Session aus derselben Eltern-Session weiter. So behält ein Session Bot seinen Kontext.
- Sonst beginnt die Arbeit in einer neuen Session.

Wenn die andere Session beschäftigt ist, wartet der Auftrag in ihrer Queue (Warteschlange) und läuft als Nächstes.

## Das Ergebnis

Der andere Bot ruft `openbot_report` einmal auf, wenn er fertig ist. Wenn er ohne Bericht endet, nutzt OpenBot seine letzte Antwort.

```json
{
	"status": "completed",
	"summary": "Added the endpoint and two tests.",
	"artifacts": [{ "kind": "branch", "ref": "bots-contract" }],
	"openQuestions": [],
	"child": { "session": "c81d…", "turn": "t-77" }
}
```

`status` ist `completed`, `failed` oder `cancelled`. Das Ergebnis enthält nie den ganzen Verlauf. Um die Details zu lesen, öffne die Session in `child`.

---

## Wie die Eltern-Session wartet

Während der andere Bot arbeitet, hat der Turn, der die Arbeit abgegeben hat, den Status `Waiting`. Er hält keinen laufenden Prozess. Darum kann das Warten lange dauern und übersteht einen Neustart des Servers. Wenn die Arbeit endet, gibt OpenBot das Ergebnis an den wartenden Werkzeugaufruf, und der Turn geht weiter. Wenn ein Turn mehreren Bots gleichzeitig Arbeit gibt, geht er nach dem letzten Ergebnis weiter.

Abgegebene Sessions haben `kind: "delegated"` und ein `parent` mit der Session, dem Turn und dem Werkzeugaufruf, die sie gestartet haben. Sie haben dieselben Routen wie jede Session. Du kannst sie lesen, lenken und unterbrechen.

## Abgegebene Arbeit beobachten

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  https://api.example.com/v1/sessions/$SESSION/delegations
```

```json
[
	{
		"id": "dlg_9f1e…",
		"parent": { "session": "a41c…", "turn": "t-12", "toolCallId": "call-3" },
		"bot": "bot_5c0e…",
		"child": { "session": "c81d…", "turn": "t-77" },
		"status": "running",
		"brief": { "task": "…", "userRequest": "…" },
		"result": null
	}
]
```

| Status        | Bedeutung                                                                         |
| ------------- | --------------------------------------------------------------------------------- |
| `authorizing` | Die Arbeit wartet darauf, dass ein [Request](/de/docs/requests) beantwortet wird. |
| `queued`      | Die Arbeit darf beginnen. OpenBot startet sie jetzt.                              |
| `running`     | Der andere Bot arbeitet daran.                                                    |
| `completed`   | Die Arbeit ist fertig. `result` enthält das Ergebnis.                             |
| `failed`      | Die Arbeit ist fehlgeschlagen oder war nicht erlaubt.                             |
| `cancelled`   | Die Arbeit wurde gestoppt.                                                        |

## Abgegebene Arbeit stoppen

Wenn du einen Turn [unterbrichst](/de/docs/sessions#steer-queue-und-unterbrechen), stoppt OpenBot auch die Arbeit, die er abgegeben hat, und schließt seine offenen Requests. Jeder Eintrag wird `cancelled`.

## Forks

Ein Fork (Abzweigung) einer Session ist neue direkte Arbeit. Er behält den Bot seiner Quelle, hat aber kein `parent`. Arbeit, die ein Fork abgibt, beginnt in neuen Sessions. So teilen sich zwei Zweige nie die Arbeit eines Session Bots.
