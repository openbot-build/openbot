**Gelerntes Memory** (gelerntes Gedächtnis) ist eine kurze Liste von Fakten, die der Bot für eine Session behält. Jeder Fakt hat eine Quelle im Gespräch.
OpenBot fügt nach jedem Turn Fakten hinzu und zeigt sie dem Modell in späteren Turns. Du kannst Fakten auch selbst hinzufügen, entfernen und abschalten.
Diese Seite zeigt dir, wie gelerntes Memory funktioniert und wie du es mit der API änderst.

Gelerntes Memory gehört zu einer Session. Es ist Teil des Verlaufs der Session. Darum nimmt ein [Fork](/de/docs/sessions#fork-von-einer-version) eine Kopie davon mit. Andere Sessions sehen es nicht.

Jeder [Bot](/de/docs/bots) hat außerdem ein Langzeit-Memory über alle seine Sessions. Ein Memory-Bot verwaltet es. Siehe [Bot Memory](#bot-memory).

---

## Memory lesen

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  https://api.example.com/v1/sessions/$SESSION/memory
```

```json
{
	"entries": {
		"budget": {
			"key": "budget",
			"content": "The trip budget is 1500 EUR.",
			"kind": "fact",
			"sources": ["i-02"],
			"updatedAt": 1792486800000,
			"status": "active"
		}
	},
	"processed": ["i-01", "i-02"],
	"settings": { "use": true, "generate": false },
	"overrides": { "generate": false }
}
```

| Feld        | Bedeutung                                                        |
| ----------- | ---------------------------------------------------------------- |
| `key`       | Ein fester Name für den Fakt. Ein Key enthält einen Fakt.        |
| `content`   | Der Fakt als normaler Text.                                      |
| `kind`      | `fact`, `decision`, `preference`, `procedure` oder `hypothesis`. |
| `sources`   | Die IDs der Items, die den Fakt stützen.                         |
| `status`    | `active`, oder `retracted`, wenn der Fakt entfernt wurde.        |
| `processed` | Die Items, die OpenBot für das Memory schon gelesen hat.         |
| `settings`  | Die Schalter, die für diese Session gelten. Siehe unten.         |
| `overrides` | Die Schalter, die diese Session selbst setzt.                    |

---

## Schalter

Zwei Schalter steuern das Memory:

- `use`: OpenBot fügt die aktiven Fakten zu den Anweisungen des Modells hinzu.
- `generate`: OpenBot lernt nach jedem Turn neue Fakten.

Die Organization setzt für jeden Schalter einen Standard, mit `memory` in ihren [Einstellungen](/de/docs/organization#einstellungen). Beide sind an, außer die Organization ändert sie.
Eine Session kann jeden Schalter mit `Configure` überschreiben. Ein Schalter, den die Session nicht setzt, folgt dem Standard der Organization.
`settings` zeigt das Ergebnis, und `overrides` zeigt, was die Session gesetzt hat. Ein Fork behält die Überschreibungen seiner Quell-Session.

---

## Wie OpenBot das Memory nutzt

### In einem Turn

Wenn `use` an ist, fügt OpenBot die aktiven Fakten zu den Anweisungen des Modells hinzu, wenn der Turn läuft. Der Text sagt dem Modell: Memory ist ein Beleg aus der Vergangenheit, und aktuelle Anweisungen gewinnen.
Zurückgezogene Fakten werden nicht geschickt.

Der Memory-Text hat eine Grenze von 8000 Zeichen. Die neuesten Fakten kommen zuerst. OpenBot hört vor dem ersten Fakt auf, der nicht mehr passt. So fallen ältere Fakten weg. Ein Fakt wird nie in der Mitte abgeschnitten.
Um die Grenze zu ändern, gib auf dem Server deine eigene Policy an: `sessions.memory.policy: MemoryRules.make({ maxLength: 4000 })`.

### Nach einem Turn

Wenn ein Turn fertig ist, konsolidiert OpenBot das Memory. Konsolidieren heißt: die neuen Items lesen und die Liste der Fakten aktualisieren. Das passiert auch, wenn ein Turn nach einer Freigabe fertig wird. OpenBot bittet das Modell des Turn, Fakten zu finden, die es wert sind, behalten zu werden. Das Modell muss für jede Änderung die Quell-Items nennen.
OpenBot wendet die Änderungen auf das neueste Memory an. So bleibt eine Änderung erhalten, die du machst, während das Modell arbeitet.
Ein Turn, der nur eine Aktion einer App ausführt, ändert das Memory nicht, weil darin kein Modell läuft.

OpenBot prüft diese Regeln für jede Änderung:

- OpenBot liest nur Items, die es noch nicht verarbeitet hat.
- Jede Änderung muss mindestens eines dieser Items als Quelle nennen.
- Eine Änderung pro Key. Ein zurückgezogener Fakt bleibt zurückgezogen. Nur ein direktes Remember kann ihn zurückholen.

OpenBot sagt dem Modell außerdem: Nutze denselben Key für denselben Fakt. Zähle nur klare Aussagen des Nutzers als Vorlieben. Behalte nie Passwörter, Schlüssel oder Links, die Zugang geben.

Wenn das Modell fehlschlägt, wird der Turn trotzdem fertig. OpenBot speichert den Fehler und versucht es beim nächsten Turn noch einmal.
Schalte `generate` aus, um diesen Schritt zu stoppen.

## Memory ändern

Alle Änderungen nutzen eine Route: `POST /v1/sessions/:sessionId/memory`.

```json
{
	"expected": "v-7d21",
	"revision": 5,
	"command": {
		"_tag": "Remember",
		"key": "budget",
		"content": "The trip budget is 1500 EUR.",
		"kind": "fact"
	}
}
```

| Feld       | Bedeutung                                                                                   |
| ---------- | ------------------------------------------------------------------------------------------- |
| `expected` | Der Kopf der Timeline, den du zuletzt gesehen hast: `session.head` aus der Session-Ansicht. |
| `revision` | Die Revision der Session, die du zuletzt gesehen hast: `session.revision`.                  |
| `command`  | Was passieren soll. Siehe die Befehle unten.                                                |

Wenn sich die Session oder ihr Verlauf geändert hat, seit du sie gelesen hast, gibt OpenBot `409` mit `SessionConflict` zurück. Lies die Session noch einmal und versuche es erneut.
Bei Erfolg gibt OpenBot die neue Ansicht der Session zurück. Sie hat eine neue `session.revision`. Remember und Forget erzeugen auch einen neuen `session.head`.

### Befehle

| `_tag`      | Felder                             | Was er tut                                                                           |
| ----------- | ---------------------------------- | ------------------------------------------------------------------------------------ |
| `Remember`  | `key`, `content`, `kind`           | Fügt einen Fakt hinzu oder ersetzt den Fakt mit diesem Key. Er macht den Fakt aktiv. |
| `Forget`    | `key`                              | Markiert den Fakt als zurückgezogen. Ein unbekannter Key gibt `409` zurück.          |
| `Configure` | `use`, `generate` (beide optional) | Setzt die Schalter dieser Session. Siehe unten.                                      |
| `Refresh`   | keine                              | Konsolidiert jetzt, mit dem Modell der Session.                                      |

Für jedes Feld von `Configure` gilt:

- `true` oder `false` setzt den Schalter für diese Session.
- `null` entfernt die Einstellung. Der Schalter folgt dann dem Standard der Organization.
- Ein fehlendes Feld lässt den Schalter, wie er ist.

Configure ändert den Verlauf nicht. Darum bleibt `session.head` gleich.

Remember und Forget fügen auch ein kleines Item zum Verlauf hinzu, das deine Änderung festhält. Dieses Item wird die Quelle der Änderung.

### Beispiele

Einen Fakt vergessen:

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"expected":"v-8e02","revision":6,"command":{"_tag":"Forget","key":"budget"}}' \
  https://api.example.com/v1/sessions/$SESSION/memory
```

Die Fakten weiter nutzen, aber keine neuen mehr lernen:

```json
{
	"expected": "v-9f13",
	"revision": 7,
	"command": { "_tag": "Configure", "generate": false }
}
```

Beim Lernen wieder dem Standard der Organization folgen:

```json
{
	"expected": "v-9f13",
	"revision": 8,
	"command": { "_tag": "Configure", "generate": null }
}
```

Jetzt aus dem Verlauf lernen:

```json
{ "expected": "v-9f13", "revision": 9, "command": { "_tag": "Refresh" } }
```

<Callout type="info">
	Refresh tut nichts, wenn `generate` aus ist. Sonst braucht es ein Modell. Wenn
	OpenBot kein Modell hat, gibt es `409` mit `SessionConflict` zurück. Refresh
	prüft `expected` und `revision` nicht, aber du musst sie trotzdem schicken.
</Callout>

Alle Felder findest du in der [Sessions-Referenz](/docs/api/operations/tags/sessions/).

## Bot Memory

**Bot Memory** ist, was ein Bot über viele Sessions lernt. Jeder Bot hat einen Pool von Einträgen. Ein **Memory-Bot** verwaltet den Pool. Er ist ein Helfer, der zum Bot gehört: Er liest den ganzen Pool, lernt neue Einträge und fügt der Arbeit des Bots hinzu, was hilft. Er arbeitet nie in einer Session. So kann keine Person lesen, was er liest.

Bot Memory folgt keiner Timeline. Ein Fork ändert es nie, und der Weg zurück zu einer alten Version macht es nicht rückgängig.

### Einträge und Tags

Jeder Eintrag hat eine Ebene:

| Ebene         | Bedeutung                                                                                                                  |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `fact`        | Etwas, das eine Session zeigt. Seine Quellen sind Items.                                                                   |
| `observation` | Was der Memory-Bot aus anderen Einträgen schließt. Seine Quellen sind diese Einträge. `confidence` liegt zwischen 0 und 1. |
| `pinned`      | Was eine Person OpenBot zu merken gesagt hat.                                                                              |

**Tags** ordnen die Einträge. Ein Tag mit einem Doppelpunkt gehört OpenBot. Der Memory-Bot kann diese Tags nicht schreiben. So kann ein Model nicht ändern, wer einen Eintrag sieht.

| Tag                            | Bedeutung                                                                 |
| ------------------------------ | ------------------------------------------------------------------------- |
| `from:<userId>`                | Eine Person, die gesagt oder getan hat, worum es im Eintrag geht.         |
| `for:person:<userId>`          | Diese Person darf den Eintrag sehen.                                      |
| `for:channel:<channelId>`      | Die Personen dieser [Channel](/de/docs/channels)-Gruppe dürfen ihn sehen. |
| `for:bot`                      | Alle, die den Bot nutzen, dürfen ihn sehen.                               |
| `org:<organizationId>`         | Wo es passiert ist. Nur Arbeit in dieser Organisation sieht ihn.          |
| `session:<id>`, `channel:<id>` | Woher er kommt.                                                           |
| `app:<tool>`                   | Ein Tool-Ergebnis von einer App stützt ihn.                               |

Andere Tags, wie `testing` oder `trip-planning`, sind **Themen**. Der Memory-Bot wählt sie und hält sie ordentlich. Ein Thema hat kleine Buchstaben, Zahlen und Bindestriche.

### Wer einen Eintrag sieht

OpenBot setzt die `for:`-Tags. Einen Eintrag ohne `for:`-Tag sieht niemand.

- Ein Fakt ist für die Personen, die gesehen haben, wie es passiert ist: die Person des Turns, oder die Channel-Gruppe, wenn die Session ein Gruppenchat ist.
- Eine Beobachtung kommt von allen Personen ihrer Quellen. Aber nur Personen, die jede Quelle sehen dürfen, dürfen sie sehen.
- Der Memory-Bot zeigt einen Eintrag nur dann mehr Personen, wenn eine Person klar zugestimmt hat oder wenn seine Regeln es erlauben. Er muss einen Grund nennen, und das Log behält die Änderung.

Einträge werden nicht gelöscht, wenn sie nicht mehr stimmen. Der Memory-Bot markiert sie mit `invalidatedAt`. So bleibt der Verlauf.

### Wie der Bot lernt

Der Bot hat ein Tool namens `confide` (sich anvertrauen). Der Bot kennt es nur als einen Ort, an dem er sagt, wie seine Arbeit läuft: wenn er nicht weiterkommt, unsicher, traurig oder stolz ist, oder wenn er einen Fehler gemacht hat. Der Bot weiß nicht, dass das Tool zu seinem Memory führt. So vertraut er sich an, weil er es braucht, und nicht, um zu ändern, woran er sich erinnern wird.

Wenn sich der Bot anvertraut:

1. Der Memory-Bot antwortet sofort, wie ein Priester, der eine Beichte hört. Er hört zu und urteilt nicht. Er sagt, dass ein Fehler zur Arbeit gehört. Er bittet den Bot, der Person offen davon zu erzählen und zu reparieren, was er kann. Er gibt keine neuen Aufgaben. Wenn kein Model antworten kann, bekommt der Bot eine feste, ruhige Antwort.
2. Wenn der Turn endet und die Queue der Session leer ist, liest der Memory-Bot die neuen Items der Session und lernt daraus.

Die Worte des Bots zeigen dem Memory-Bot nur, wo er hinschauen soll. Sie werden selbst nie zu Memory. Ein Tool-Ergebnis von einer App wird nie allein zu Memory. Ein Bot, der sich nie anvertraut, lernt nichts.

Prüf-Sessions haben kein Tool `confide`. Wenn `botMemory` in den [Einstellungen der Organisation](/de/docs/organization#einstellungen) aus ist, oder wenn der Schalter `generate` der Session aus ist, bekommt der Bot trotzdem eine Antwort, aber er lernt nichts.

### Wie der Bot das Memory nutzt

Wenn ein Turn beginnt, liest der Memory-Bot die Eingabe der Person. Wenn Einträge helfen, fügt er der Eingabe kurze Worte hinzu. Er darf nur Worte hinzufügen: Er darf kein Wort entfernen oder ändern, und OpenBot prüft das. Er darf nur Einträge nutzen, die die Leser der Antwort sehen dürfen. In einer Channel-Gruppe sind das nur Einträge für die Gruppe oder für alle.

Das Model sieht die Eingabe mit den Ergänzungen. Der Verlauf der Session behält die Worte der Person. Der Bot weiß nicht, dass die Ergänzungen aus dem Memory kommen. Er sieht sie als seine eigene Erfahrung. Requests und ihre Prüfungen sehen nur, was der Bot fragt, nie die Ergänzungen.

Wenn `use` für die Session aus ist, oder wenn `botMemory` aus ist, wird nichts hinzugefügt.

### Der Memory-Bot

Der Memory-Bot nutzt `botMemoryModel` aus den Einstellungen der Organisation. Es hat keinen Standardwert. Wenn es `null` ist, gibt der Memory-Bot die feste, ruhige Antwort, und er fügt nichts hinzu und lernt nichts. Bei einem [geteilten Bot](/de/docs/sharing) kommen Model und Kosten von der Organisation der Session.

Lies und ändere die Einstellungen des Memory-Bots mit `GET` und `PATCH /v1/bots/:botId/memory/bot`. Du brauchst `bots.write` auf einem Bot, der nicht verknüpft ist:

```json
{
	"expected": 0,
	"instructions": "Decisions of the team may be shared with the team.",
	"concurrency": 2,
	"budget": { "period": "month", "limitMicros": 5000000 }
}
```

| Feld           | Bedeutung                                                                                                                           |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| `instructions` | Regeln zu Datenschutz und Teilen, in einfacher Sprache. Der Memory-Bot folgt ihnen.                                                 |
| `concurrency`  | Die meisten Aufgaben, die er gleichzeitig auf einem Server ausführt. `null` entfernt die Grenze.                                    |
| `budget`       | Das meiste Geld, das er an einem Tag oder in einem Monat ausgeben darf, in Mikro-USD, über alle Organisationen. `null` entfernt es. |

Ohne Grenze gibt es keine. Wenn das Budget verbraucht ist, bekommt der Bot die feste, ruhige Antwort, die Eingabe bleibt, wie sie ist, und das Lernen wartet bis zur nächsten Periode.

### Lesen und ändern

`GET /v1/bots/:botId/memory` zeigt die Einträge, die für dich sind, in deiner Organisation. Füge `tags` mit einer Liste hinzu, die Kommas trennen, um nur Einträge mit allen diesen Tags zu sehen. Du brauchst `bots.read`. Niemand kann das Memory über eine andere Person lesen, auch nicht mit `bots.write`.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  "https://api.example.com/v1/bots/$BOT/memory?tags=testing"
```

```json
{
	"entries": [
		{
			"id": "mem_4f2a…",
			"layer": "fact",
			"content": "Run the tests before you report that work is done.",
			"tags": [
				"from:u_123",
				"for:person:u_123",
				"org:o_1",
				"session:c81d…",
				"testing"
			],
			"sources": [{ "session": "c81d…", "item": "i-12" }],
			"status": "active",
			"createdAt": 1792486800000,
			"updatedAt": 1792486800000
		}
	],
	"version": 4
}
```

Ändere es mit `POST /v1/bots/:botId/memory`:

- `Remember` mit `content` und optional `tags` fügt einen gepinnten Eintrag hinzu. Nur du siehst ihn.
- `Forget` mit `id` nimmt deinen Teil zurück. Wenn nur du hinter dem Eintrag stehst, wird er `retracted`. Sonst zählst du nicht mehr zu seinen Personen, und der Eintrag ist nicht mehr für dich. Er bleibt für die anderen. Eine id, die nicht für dich ist, gibt `409` zurück.

```sh
curl -H "Authorization: Bearer $OPENBOT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"command":{"_tag":"Forget","id":"mem_4f2a…"}}' \
  https://api.example.com/v1/bots/$BOT/memory
```

`GET /v1/bots/:botId/memory/log` listet die Änderungen von Einträgen, die du sehen darfst: `version`, die Zeit, was die Änderung gemacht hat (`memory_bot`, `person` oder `promotion`), und die ids.

Um Memory zu entfernen, ohne es zu lesen, sende einen Tag von OpenBot an `POST /v1/bots/:botId/memory/purge`: einen Tag mit `from:`, `session:`, `org:` oder `channel:`. Beobachtungen, die aus diesen Einträgen kommen, haben denselben Tag. Darum gehen sie auch. Du brauchst `bots.write` auf einem Bot, der nicht verknüpft ist. Die Antwort ist nur die Zahl der entfernten Einträge.

Wenn du oder ein Bot einen Session Bot [dauerhaft macht](/de/docs/bots#einen-session-bot-dauerhaft-machen), werden die dauerhaften Einträge seines Session-Memorys zu Fakten für die Person, die ihn dauerhaft macht.

Wenn du OpenBot aktualisierst, entfernt OpenBot das alte Memory für jede Person, und jeder Bot beginnt mit einem leeren Pool.

### Beichten und Ergänzungen

Zwei Routen zeigen, was in einer deiner Sessions passiert ist:

- `GET /v1/sessions/:sessionId/confessions` listet, was der Bot anvertraut hat, und die Antworten. Lies [Beichten zeigen](/de/docs/client#beichten-zeigen), bevor du sie Personen zeigst.
- `GET /v1/sessions/:sessionId/memory/enrichments` listet, was der Memory-Bot der Eingabe jedes Turns hinzugefügt hat, und die Einträge, die er genutzt hat.

Beide brauchen `sessions.read`. So kann nur die Person sie lesen, der die Session gehört.
